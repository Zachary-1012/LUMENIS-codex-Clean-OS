# 《凉子访谈录》— Benchmark Case V1

## Role in the system

First benchmark case for the Podcast Research Library. It is a research target, not an assertion that every observed characteristic is causal or representative.

## Case decomposition

### A. IP layer
- Show identity and positioning
- Host identity and interviewing style
- Guest selection logic
- Recurring narrative promise
- Series/column architecture

### B. Episode layer
- Publish time
- Runtime
- Opening structure
- First meaningful hook
- Question sequence
- Story turns
- Conflict/reversal
- Emotional peaks
- Insight peaks
- Ending / CTA

### C. Information layer
For every material claim, retain source URL/locator, publisher, published time, observation time, content hash where available, evidence status and confidence.

### D. Platform layer
Collect only observable/public metrics or user-supplied exports. Keep platform observations separate and never infer a metric from another platform without marking it `derived`.

### E. Content-yield layer
Map each episode to derived assets: full episode, chapter, clip candidate, quote, social copy, research note, person dossier update and knowledge-graph nodes.

### F. Learning layer
For each episode record hypotheses, evidence, confounders, what is reusable, what is format-specific, and what should not be copied.

## Initial system hypothesis

The benchmark should be analyzed as a multidimensional content system rather than a single account. The research output must be able to answer:

- Why does a topic deserve an episode now?
- Why is this guest the right person?
- Which question unlocks the highest story yield?
- Where does the episode create emotional or cognitive peaks?
- How does runtime affect consumption when retention data exists?
- Which moments can become derivative assets?
- Which platform packaging changes performance?
- Which observations are facts versus model hypotheses?
- Which learnings transfer to a new show and which are specific to this IP?

## Anti-copy rule

Do not clone surface style. Extract mechanisms, test them against evidence, then adapt them to the ZBC/Zachary Podcast design system and editorial voice.

# Design Philosophy: 芥子·须弥 × 太极 × 一二三 V1

## Scope
Shared philosophy reference for Zachary-OS-AI and ZBC. It guides architecture and experience design; it is not a business rule or runtime dependency.

## Model
芥子 = concrete/local signals and production reality. 须弥 = whole/abstract reusable capability and knowledge. 一 = shared order (Contract, Truth, Security, Compliance, Evidence). 二 = complementary learning/production and abstraction/concretion. 三 = feedback/evaluation/validation/contract-mediated relationship. 万物 = the data, cases, behavior, knowledge, capability and outcomes generated by the loop.

The Buddhist 芥子纳须弥 metaphor and Daoist 道生一、一生二、二生三、三生万物 are distinct traditions. Their combination here is explicitly a modern systems analogy, not an attribution of one tradition to the other.

## Zachary role
Zachary is the reusable-capability/knowledge side: research, learning, AI runtime, evaluation and abstraction. It must receive production feedback without taking ownership of ZBC business Truth.

## UI / UX / visualization / motion
The interface is the concrete surface through which abstract capability becomes an actionable experience. Visuals should reveal relationships among signal, context, evidence, state, decision and action. Prefer progressive disclosure, direct manipulation, context-preserving drill-down, cross-filtering/cross-highlighting where useful, consistent interaction language, semantic continuity, accessible controls and performance-aware rendering.

Motion must express state, cause or continuity. Preserve the semantic mapping of a visual element while it transitions. Avoid decorative motion. Never imply unsupported facts through animation or visual state.

## Shared dynamic state model
INPUT → DETECTED → VERIFIED → CLASSIFIED → CORRELATED → IMPACT/RISK → DECISION → ACTION → FEEDBACK.

This is a reference model only; map it onto existing runtime/data contracts instead of creating a parallel framework.

## Personalization
"形可变，道不可移": user behavior may adapt presentation, interaction style and workflow preference; it must not alter Security, Permission, Truth, Compliance, Contract or core business physics.

## Cross-repository boundary
Zachary ↔ Contract ↔ ZBC is bidirectional capability/feedback flow, not implementation sharing without control. Reuse existing contracts, UI tokens, components, telemetry and evaluation mechanisms. Do not create duplicate frameworks.

## Research basis
Current Microsoft Learn guidance emphasizes direct interaction, filtering/drill-down, meaningful motion, preserving data mappings, avoiding chart junk, accessibility and responsive dashboard hierarchy.

## Definition of Done
Map the philosophy to existing modules; document UX/visualization/motion implications; preserve contracts and Truth; define interaction/accessibility/performance regression checks; capture runtime Evidence before PASS.

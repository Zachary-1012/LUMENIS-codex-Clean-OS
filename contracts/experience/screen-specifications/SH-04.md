## 1. Product invariant and scope

SH-04 is an output queue and artifact inspector. It does not create a fake export, download a path that was never persisted, or treat a report listing as proof that an artifact can be reopened. Exact scope, Evidence/source count and persistence are part of the artifact contract.

The current reporting route is read-only and does not wire the export effect. The App therefore shows only typed, already persisted artifacts and offers no create/download control. Legacy global report lists do not satisfy the contract.

## 2. Binding and response contract

| UI region | Required runtime value | App behavior |
| --- | --- | --- |
| Exact range | Top-level `scope` plus artifact scope matching it exactly | Reject mismatched Subject/BrandFocus or domain |
| Export authorization | Read/export permission result from the response path | Do not present an artifact without permission evidence |
| Artifact queue | `data.exports[]`/`data.artifacts[]` with id, title, format, state, `scope_verified` and an explicit Evidence-backed marker | Allowlist formats and states; hide internal id |
| Reopenable preview | `state=READY` and `artifact.reopenable=true` with a safe preview | Mark ready only when persistence and reopening are explicit |
| Failure state | Failed/generating/draft or missing persistence | Show the true state; never substitute a success or download |
| Existing route | `GET /api/experience/screen/SH-04` | Current report listing lacks the exact effect contract; remain blocked |

Supported display formats are markdown, CSV, PDF, Excel and PPT. Persistence is not inferred from a filename, path or HTTP success. Evidence count remains nullable; missing is not zero. Every artifact needs canonical row scope, row read permission, Evidence-backed marker, and verified lineage/integrity. A global response rejects an artifact explicitly scoped to a focus; a focus response accepts only an exact matching active artifact scope.

## 3. Responsive information architecture

### Desktop (available width ≥1120 logical px)

- Header and exact-range banner establish the artifact context.
- Output queue occupies the primary column with state/format badges.
- Reopenable preview and persistence facts occupy a secondary inspector.

### Intermediate width (760–1119 logical px)

- Queue comes first; preview/metadata follows in a full-width region.
- Failed, generating and unavailable artifacts retain visible state labels.

### Mobile (available width <760 logical px)

- Recompose into exact range → queue → preview → persistence explanation.
- Only local selection and reread are available; no fake external effect is exposed.

## 4. State and recovery

| State | Meaning | Behavior |
| --- | --- | --- |
| Loading | Output listing is pending | Live status, no stale artifact |
| Ready | Exact scope, permission, persisted/reopenable artifact verified | Show preview and metadata |
| Generating / draft | No completed artifact yet | Show in-progress state; no download |
| Failed | Export attempt has a verified failure state | Show safe failure text; no success affordance |
| Unavailable | Ready-looking record is not reopenable or scope is incomplete | Do not call it completed |
| Scope unavailable/denied | Exact range or export permission is absent | “成果中心暂不显示”; no artifact identifiers |
| Authentication/offline/invalid | Core recovery or response problem | Safe retry; no stale artifact |

## 5. Actions and effects

| Action | Effect | Availability |
| --- | --- | --- |
| Select output | Local inspector selection | Enabled in Ready |
| Reread queue | Read-only refresh | Enabled when the screen is mounted |
| Create/export | Consequential effect requiring exact scope, Evidence, approval, persistence and audit | No active control until the server effect contract is verified |
| Download/reopen | External artifact access | No active control; display only an already verified preview |

When the selected artifact is `READY`, exact-scope, permitted, persisted and
reopenable, its nonempty preview text may expose a transient local Read Aloud
action. Bind it to the current scope and artifact identity; use only an exact
installed zh-CN, en-US or ko-KR device voice at 0.75×/1.0×/1.25×. Do not
request a new artifact, translate, save speech audio or use a remote voice.
Scope, artifact, text or screen change stops playback. Blocked/unavailable or
non-reopenable records never expose this action.

## 6. Accessibility and localization

- State, exact range, format and reopenability are announced as text and not by color alone.
- Preview content is rendered as inert text; no HTML or path is interpreted.
- The title uses existing `screen.SH-04` keys in zh-CN, en and ko.
- Error copy hides raw ids, paths, provider information and diagnostics.

## 8. Review decision

The App slice is implemented as a scope-guarded output queue with exact-scope and reopenability checks. The reporting backend currently has no verified export effect/persistence binding for this screen, so no commercial export claim is made and live acceptance remains blocked.

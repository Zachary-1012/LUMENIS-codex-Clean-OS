# XHS 账号安全事件：DCC 冻结门禁

> Incident ID: `XHS-SAFETY-2026-08-31-01`
> 状态：`ACTIVE / HARD FREEZE`
> 适用：Core、DCC、豆包及其他研发窗口

## 1. 事件

目标账号收到平台关于“疑似使用第三方工具或脚本（如AI）自动浏览、查看或发布内容”的警告。

DCC 将该信号视为账号安全事件，而不是普通采集失败。

## 2. 强制动作

所有 XHS 自动化路径立即 `BLOCKED`：

- Web 自动浏览/采集
- App 自动化
- CDP/浏览器自动控制
- 自动登录/Session 自动恢复
- Topic Campaign 自动触发
- XHS Scheduler
- 自动重试/自动恢复

## 3. 不得采用的“解决办法”

不得通过降低频率、随机间隔、模拟真人行为、代理池、频繁换 IP、设备切换、指纹伪装、多账号、验证码绕过或任何其他手段降低被检测概率。

DCC 不生成此类代码、参数或操作指令。

## 4. 研究方向

只研究官方授权 API/SDK、OAuth、公开且允许使用的数据源，以及与账号自动化无关的证据输入方式。

官方能力不足时，不以私有 API 或浏览器自动化替代。

## 5. 恢复门禁

必须：事件复盘 → 规则/授权核验 → 三仓库状态核对 → 测试证据 → DCC 审计 → 人工批准。

没有人工批准前保持冻结。

若某路径只能依赖规避平台检测才能工作，则该路径永久 BLOCKED。

# 产品标准用名 · 线性图标 · 中英韩三语 i18n 规范 V1.0（面向用户，强制）

> 起因：首页出现「ZBC 生产真相 × OSAI 智能推理」内部代号、左导航出现实心红块图标、三语版本再次遗漏。三条均为面向用户的硬规范，UI 阶段首批落地，i18n/术语地基现在就铺，避免返工。

## 一、标准用名（内部缩写/工程代号不得出现在用户界面）
1. 建立唯一《产品术语表》，所有界面文案、报告、通知、邮件、导出都以术语表为准；代码内部可保留代号，**渲染给用户时必须替换为标准用名**。
2. 用名对照（中 / 英；韩文见三语表，需母语校对，不机翻硬凑）：
   - ZBC（内部工程总代号）→ 对外用「**序境 LUMENIS**」，用户界面**不出现 ZBC** 字样。
   - OSAI（内部共享智能层代号）→ 对外**不出现 OSAI**，统一表述「智能引擎 / Intelligence Engine」；OSAI 不成 runtime 依赖也不外露。
   - ZBMP → 品牌智能 / Brand Intelligence；CTH → 太古汇智能 / Taikoo Hui Intelligence；SYS → 系统 / System。
   - TOTP → 动态验证码（双重认证）/ Two-Factor Code；DLQ/Lease/Heartbeat/Checkpoint/Provider 等工程词仅出现在开发者功能并加中文注解，业务界面不可见。
   - KOS/KOL/KOC 首次出现给中文全称（关键意见销售/领袖/消费者），其后可用缩写。
   - 「AI Ready / Provider: detecting…、source: health/summary、Evidence-backed」等技术态/来源串**不得直接显示**，改为规范业务文案或真实指标；无数据走 Empty 态。
3. 首页「ZBC 生产真相 × OSAI 智能推理·统一证据链，每一步可追溯」改为不含内部代号的规范文案（如「序境 · 品牌与舆情智能，统一证据链，每一步可追溯」，最终文案以术语表为准）。
4. 任何新文案先过术语表；代码里集中管理面向用户的字符串，禁止在模板散落内部代号。

## 二、线性图标（Linear / Outline，全站统一）
1. 导航与功能图标统一**线性 outline**：24px 网格、描边粗细统一（建议 1.5px）、圆角端点、统一视觉尺寸、线性留白一致。
2. **禁止实心填充色块**：左导航「小红书」当前的实心红色方块改为线性表达（线性笔记本/线性品牌徽标），品牌色可作描边或小色点，不铺实心块；警告、闪电、菱形、眼睛等全部同一线性风格、同一粗细。
3. 选中/激活态用颜色+字重或 1–2 层克制底纹表达，不靠把图标变成实心块；hover/focus/active/disabled 线性态统一。
4. 图标必带文字标签（极简≠简单）；不混用多套图标库风格，自研/同一图标集，不抄袭。

## 三、中英韩三语 i18n（zh-CN / en / ko，这次不能再漏）
1. 搭建 i18n 框架：所有**可见文案走词条 key**（`t('...')`），建立 `zh-CN / en / ko` 三套词条；新增与改动页面必须走词条，**禁止硬编码裸字符串**；存量页面分批替换并登记进度。
2. 语言切换放入 **设置-外观**，按用户持久化记忆；默认 **zh-CN（简体中文）**；三种语言可随时切换、切换后整页（含导航/卡片/表格表头/状态/日期/报告模板）即时生效，不留中文混排。
3. 三语一律以《产品术语表》标准用名为准：英文专业规范；**韩文必须复用三语研究库并经母语级校对**，没有把握的韩文标 missing、回退中文并列入待补，**不许机翻硬凑/编造**。
4. 数字、日期、相对时间（几分钟前/昨天）、状态枚举随语言本地化；缺失词条显式回退中文并记 missing，不显示 key、不显示空白。
5. 复用本地三语/语料研究成果（intelligence_library、OSAI/ADRH 三语库），先审计已有三语资产再补，不重复翻译。
6. 三语与双域正交：ZBMP/CTH 各自业务术语分别翻译，不串域；技术底座词条 Shared 复用。

## 四、落地与验收
- 阶段一铺好「术语表 + i18n 框架 + 线性图标集」地基；UI 阶段二首批完成：首页代号文案替换、左导航线性化、框架内三语切换打通。
- 验收：全站 grep 面向用户层不得出现 ZBC/OSAI 等内部代号；图标全部线性无实心块；zh/en/ko 三语可切且无 key 裸露/无混排，韩文 missing 显式列出。

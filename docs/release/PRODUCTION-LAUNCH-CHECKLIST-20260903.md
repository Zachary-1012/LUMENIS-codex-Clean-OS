# 生产上线准备清单 — 2026-09-03

> 适用：Z-Brand-Core 当前闭环完成后的生产上线阶段。
> 原则：不改变已冻结的核心业务逻辑；先生产 Web，再按需推进 APP / 小程序；三端共享后端/API能力，但客户端发布物独立。

## 1. 上线门槛

- [ ] 核心闭环连续跑通：采集 → 入库 → 过滤 → 分析 → 事件 → 风险 → 报告 → 通知 → 监控 → 自动恢复 → 评测
- [ ] 核心流程不依赖人工持续接管
- [ ] 启动、运行、异常、重启、自动恢复均通过验证
- [ ] 生产数据库、配置、版本、密钥完成备份
- [ ] 至少完成一次真实恢复演练
- [ ] 生产版本冻结并打 Git tag / 保留可回滚 commit
- [ ] 生产环境 Smoke Test 通过
- [ ] 回滚路径已验证

## 2. Web

### 电脑 + 手机

- [ ] 同一套 Web 服务/域名
- [ ] 响应式布局完成电脑、平板、手机验收
- [ ] Chrome / Edge / Safari 基础兼容测试
- [ ] iOS Safari / Android 浏览器测试
- [ ] 登录、核心业务、AI、报告、通知、监控全部真实链路验证
- [ ] 弱网、断网、刷新、重新登录、异常 API 场景验证

### 生产基础设施

- [ ] 正式服务器/云资源
- [ ] 正式域名
- [ ] HTTPS/TLS
- [ ] DNS
- [ ] 生产数据库
- [ ] 日志与监控
- [ ] 备份与恢复
- [ ] 环境变量/密钥管理
- [ ] 生产与测试环境隔离

### 中国大陆合规（按实际业务适用性办理）

- [ ] ICP 备案
- [ ] 公安联网备案等后续手续按要求办理
- [ ] 隐私政策
- [ ] 用户协议
- [ ] 数据处理说明/第三方服务说明

- [ ] 源码中无生产密钥、Token、数据库密码

- [ ] 管理员权限最小化
- [ ] API 权限最小化
- [ ] 关键操作审计日志
- [ ] 错误日志

## 6. 正式上线顺序

1. 闭环验收
2. 生产版本冻结
3. 备份 + 恢复演练
4. 生产基础设施准备
5. Web 正式部署
6. 电脑 + 手机 Web 验收
7. 灰度运行
8. 监控稳定性
9. Web 正式运营
10. APP / 小程序分别进入备案、构建、审核、发布流程

## 7. 三端关系

| 端 | 电脑 | 手机 | 是否独立发布 | 核心后端/API |
|---|---:|---:|---:|---:|
| Web | ✓ | ✓ | 否 | 共用 |
| APP | — | ✓ | 是 | 共用 |
| 小程序 | — | ✓ | 是 | 共用 |

## 8. 发布纪律

- 不因做 APP / 小程序而反向破坏已稳定的 Web 核心逻辑。
- 客户端层与核心业务层解耦。
- 所有生产变更遵循：开发 → 测试 → 验收 → 冻结/Tag → 部署 → Smoke Test → 监控。
- 任何影响核心链路的修改必须先验证，再进入生产。
- Web 是第一生产入口；APP / 小程序在核心系统稳定后独立推进。

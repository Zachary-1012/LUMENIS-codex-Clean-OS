# 寰意 / OEVIRA 完整产品规格

本文件依据产品负责人要求直接重构、全产品保全并强化的最新指令更新，定义完整目标产品。专业能力、用户操作、可编辑成果和恢复均为实施要求；当前源码或局部测试不能代替完整交付。产品定位归 [PRODUCT.md](../PRODUCT.md)，交互呈现归 [DESIGN.md](../DESIGN.md)，实现边界归 [ARCHITECTURE.md](ARCHITECTURE.md)，验收归 [ACCEPTANCE.md](ACCEPTANCE.md)。

详细合同：[业务](domains/business.md)、[研究创作与媒体](domains/creative.md)、[系统与智能](domains/intelligence.md)。三个合同共同覆盖全部专业领域，原 J/G/UX/E/P 编号用于追溯，不是产品菜单或范围上限。研究记录与逐条对照归 [资料索引](reference/reconstruction/README.md)，不另成活跃规划。

## 1. 产品应当成为什么

寰意是面向**媒体、广告、品牌营销与商业运营行业**的专业智能工作平台，同时完整服务独立研究与创作。它围绕真实客户、商业主体、品牌、商业项目及其工作关系，持续取得信息，形成专业判断，发展原创方案，完成可编辑交付，处理修改和实际反馈，继续下一次工作。商业运营团队、品牌与代理团队、独立研究与创作用户均有完整用途；不能把其中两类降为第三类的附属工具。

它须同时具备行业能力和普通专业软件的直接操作能力。智能可以承担查找、理解、计算组织、创意发展和跨成果修订；用户也能直接阅读、比较、写作、编辑、录制和制作。基础工作无需模型运行；AI增强须用同一工作另行证明质量及节省的实际操作。

新产品的专业性，不由功能菜单数量或自研标签证明，而由工作深度、判断依据、原创质量、局部修改准确性及交付后的可继续使用证明。对外商业主张可以清晰集中，但内部产品范围不能因此被缩成仅有品牌报告或资料摘要。

需要纠正的判断是：把“减少用户负担”推成“减少专业行为”，把四个入口推成四种通用数据对象，把研究参考推成固定风格标签，再用最容易完成的表单和文字处理代表整个产品。这会让结构看似整齐，用户却仍须自己补齐关键工作。此次重构保留完整工作能力，减少重复录入、无意义选择、上下文搬运和修改损失；取舍依据是实际工作收益及证据。

## 2. 这次必须纠正的实际问题

| 已核问题 | 处置 | 必须得到的变化 |
|---|---|---|
| 新规格用大类概括经营、品牌、策略与分析，原先的专业对象和处理条件未充分承接 | 补全专业行为，保留统一基础 | 经营趋势、预算、创作者合作、传播、活动和效果分析能够处理各自真实输入与变化 |
| Work/Material/Artifact 被用作几乎全部产品结构 | 保留它们的连续性职责，补领域内部对象 | 决定不冒执行、报价不冒花费、事件不冒意见、文章不冒可编辑演示 |
| 当前新建工作只保存标题/目标和空简报再跳详情 | 重做启动行为及必要输入衔接 | 委托工作实际开始处理；直接编辑立即打开相应工作面；两种行为有准确按钮和结果 |
| 首屏巨大输入区、固定空右栏、导入与编辑被入口位置限制 | 从真实工作与内容重新构图 | 当前任务就地添资料、打开已有稿、并读、修改、继续；不为穿越导航重复搬运内容 |
| 研究入口和验收被“三份材料”示例固化 | 删除通用数量门槛 | 单份原稿、多个来源、只有问题的公开研究均能开始；具体方法所需输入才形成局部条件 |
| 当前词面比较、数字提取和哈希变化被当作专业能力起点 | 保留真实基础能力并补专业处理 | 正确识别实体、期间、单位、分母、主张、冲突、事件和来源更正；不能将基础实现当终态 |
| Office完整编辑在新规格仍有，但当前实现远低于目标 | 保留要求，重做对象与往返实现 | 精确修改原件，未选内容保全，原生格式可重开；不能将实现缺失误写成需求已取消 |
| 旧研究中固定词槽/随机句式、标签和无据阈值被用作创意与策略 | 替换错误方法与验收，不删创意能力 | 同目标下形成机制和取舍不同的方案，保人工表达和品牌区别；评价有依据 |
| 部分历史KOS记录把互动当曝光、私有个案CPL当跨客户基准 | 修正指标与适用范围 | 原生指标、来源、期间与分母可核；公开询问、授权线索、成交、退款分别处理 |
| 新架构把所有用户数据学习与参数训练混在一起关闭 | 明确分层 | 资料索引、可纠正记忆、明确偏好、经评估策略可持续使用；既有小模型与通用接口完整保留，GPU训练保留未来路线而不阻当前交付 |
| 将稿件保存、文件头、HTTP成功、测试数量当交付证据 | 更换签收依据 | 实际用户完成工作、打开修改结果、冷开继续和错误恢复才形成能力证据 |

上述问题的源码观察与历史证据见研究索引；历史研究错误不能冒充当前运行缺陷。实现、运行与验收按具体版本核实，所有有效未提交成果须保全。

## 3. 完整能力及工作对象

以下能力在适用工作中可以直接调用和组合；研究、文稿、视频与播客保留独立完整用途。身份、评价、恢复等是共同能力，不因此另造产品入口。共享底层不能抹掉专业区别，完整能力也不等于每次要求用户走全部步骤。

| 能力 | 用户实际可以完成 | 必须有的专业处理与可编辑结果 |
|---|---|---|
| 客户、商业主体、品牌与场内经营 | 管理客户委托及工作范围，研究和经营商业主体、品牌、商业项目、场内品牌、商户及门店；进入各自监测、分析、策略与合作 | 完整档案、来源、身份消歧、期间关系和生命周期；区分委托客户、研究对象及经营主体；品牌—经营商户—具体门店—所在项目有据关联，数据与权限不沿关系自动下灌 |
| 经营分析 | 从经营表、反馈和公开信号判断变化，提出资源可行的解决方案 | 可比群、营业日/面积/租户变化、异常与观测缺口区别；趋势、预测区间、回测、敏感性、可行备选及可编辑简报/工作簿 |
| 市场与消费者研究 | 研究竞争、需求、购买障碍、服务问题及市场机会 | 原生指标与样本覆盖、调查/公开发声/内部行为分开；反证、时间地域边界、可验证机会和判断 |
| 财务与预算情景 | 阅读财报与经营材料，比较真实主体和期间，试算预算与投入选择 | 单位币种、季度与年度、财报修订、费率假设、代理估计、诊断和留出；不把内容数或集团收入冒充品牌投入 |
| 事件、观点与传播 | 从持续信息中找到发生的事、谁在表达什么、怎样传播 | 去重保出处，事件簇/观点对象/主张/立场各自身份，真实传播边、未知覆盖与人工修订；更正可追影响 |
| 品牌策略与原创提案 | 从真实目标发展定位、受众承诺、不同创意路线与可执行方案 | 品牌区别、受众障碍、约束和why-this-brand；策略层级可供深入不强制成表单；预算、执行、验证及十章等适用专业表达可自由调整 |
| 工作约定和范围变更 | 接客户简报、明确交付和限制，中途改要求 | 版本化目标、交付规格、成本/时间/权利影响、冲突意见和处理决定；已确认部分不会被整体重写 |
| 创作者与合作 | 发现核对KOS/KOL/KOC/UGC候选，形成组合，确认合作要求，承接提交、验收、补改与实际结果 | 身份、样本、受众、价格、档期与权利有出处；合作条件和交付规格有版本；取消、替换、执行回执、实际费用/退款和效果回到同一合作。选中不等已联系，批准不等已执行 |
| 内容经营 | 单条、系列、活动各自起步并形成跨平台内容 | Persona、事实主稿、结构和语气、平台/市场变体、人工锁定、局部更新；六字段等专业结构为工具而非所有作品模板 |
| 活动与排期 | 安排预算、制作、渠道、人员与交付，跟踪执行反馈 | 真实日历/时区/提前期、资源容量、资格、排他与依赖；估计/报价/承诺/实支/退款分开；冲突有可行替代 |
| KOS漏斗与渠道效果 | 分析传播、询问、授权线索及真实成交结果 | 原生曝光与互动分开、分母期间明确；身份与路径不确定可见，退款修正不重复计数；缺后段数据仍交有用前段分析 |
| 评论、服务与风险 | 核对具体问题，写可用回复或处理方案，按授权执行并复盘 | 严重度与传播量分开；原话/推断/人工决定分别保留，误报可改；精确批准、真实回执及失败续接 |
| 实验与专业评价 | 判断方案是否有效、哪里失效、下次怎样改 | 描述性分摊与因果增量区别，适用的实验/比较/诊断、失败反例、成本与时间；结果不能由模型打分单独决定 |
| 独立研究 | 从问题或任意数量的必要材料开始，找原文、反例与方法，形成自己的判断 | 权限内混合检索、精确定位、并读、字段核对、计算、引用与作者观点区分；研究直接服务当前工作，也可单独交付 |
| 原创与跨文化表达 | 写命名、文案、公关稿、媒体稿、文章、脚本和不同语言版本 | 受众理解、体裁、叙事、品牌区别、文化语境和自然语言质量；否定、数字、术语与事实一致；保人工声音，不套同一句库 |
| 文稿、演示、表格、PDF | 从空白或客户原文件直接编辑、审阅、修订、交付 | 四种对象模型和专业编辑器；页/段/对象/单元格精准选取，公式/样式/母版/关系/媒体/备注及原页保全；目标格式回读 |
| 视频完整制作 | 从构思、脚本或现成素材任一步开始，完成分镜、剪辑、声音、字幕、多画幅与成片 | 可编辑镜头/图层/轨道、精确时基、实际预览、代理和原件分离、局部精修、交换损失预检、可恢复工程；不是只有分镜文本 |
| 播客完整生产 | 选题积累、嘉宾研究、前采、录制、选take、精剪、混音、章节、交付和切片 | 实际输入电平和录音落盘，源声道与说话人标签分离、文字校正不冒改音频、可听的处理对照、实测响度、完整工程和发布资料 |
| 持续监测 | 按主题/对象/工作持续获取变化，将值得处理的信息带入实际工作 | 已计划/实际检查/最后成功/源事件时间分开，重复转载与新事实区别，授权失效和停机空窗可见；恢复补检不伪称全天实时 |
| 受控浏览与统一采集 | 公开来源自动获取，必要时用户在自己的隔离会话登录、操作、接管，再回当前工作 | 一套采集合同和来源链，HTTP/Feed/结构化/DOM/授权浏览按任务选路；原生评论/回复/媒体/分页；浏览画面与实际可操作性分别验证 |
| 智能工作与持续记忆 | 短问题直接答，复杂工作组织真实工具、阶段结果和局部修改，多任务互不干扰 | 相同业务操作供人工与AI使用；记忆可查改忘记、客户隔离、旧结果不覆盖新稿；策略改进经独立评价及适用范围控制 |
| 协作、交付与恢复 | 团队和客户围绕同一成果审阅、改稿、确认、导出、重开 | 对象/版本上的评论与决定、角色与客户边界、只读原件、不可变修订、离线草稿、冲突保双方、备份实际恢复 |
| 已规划扩展与声音 | 使用获准Skill/MCP/仓库资料能力和兼容声音包，检查、停用、撤回 | 安装/配置/授权/自测/业务成功分开；声音外部制作后导入、试听、确认默认；不恢复产品内克隆制作和未授权新服务 |

视频、播客、文稿、研究既可单独用，也可从品牌和经营工作继续。可以跳过准备环节，不等于删除准备能力。图片继续作为资料、封面、文档和媒体项目内容，不另建独立图片编辑器。通用OS控制不恢复。

品牌方、代理方、资源/创作者方使用同一组适用事实，但责任、交付与可见信息不同：品牌方核目标和结果，代理方组织提案、内部成本和资源，供应方接受适用任务与交付要求。客户版本不泄露代理内部成本或其他客户材料；报价、合作承诺、结算记录和实际收付不混同。反馈附着原对象并返回负责人的当前工作，不要求三方重复录入同一需求。客户委托、联系人角色、协作、范围变更与交付管理属于本产品；不因避免另造通用CRM而删除这些已需业务行为。

### 客户、商业主体与品牌：完整业务领域

主体目录只分品牌主体、商业主体两类。商场等商业经营对象归商业主体，品牌归品牌主体；下表展开的是业务档案、属性与关系，不是新增主体种类。两类均可持续添加，须有中国境内营业依据，原目录与分类完整保全。

“临时工作可以不绑定主体”只减少无关前置步骤。用户管理客户、经营项目、研究品牌及场内经营时，这一领域须能独立进入、持续维护并完成专业工作，不能退成设置页的一个名称字段或检索标签。主体、主题、工作项目是不同概念：主体是所服务或研究的真实业务对象；主题是议题或内容方向；商业项目是场所等经营对象，工作项目是围绕委托组织的工作，二者不混成一个ID。

| 业务对象或关系 | 必须保留的内容与用户操作 | 下游用途和不能混淆的边界 |
|---|---|---|
| 客户与委托 | 选择或建立客户、记录有权使用的联系人及其职责、委托范围、服务项目、品牌/商业项目、要求、交付、审阅人员和期限；变更、结束、重开及历史核对 | 客户可以是商业运营方、品牌方、代理或其他委托方；研究对象不是自动成为客户，客户名称也不自动代表法定签约主体。客户私有资料、价格和批准按委托及权限隔离 |
| 法律主体、集团与经营组织 | 分清合同/披露主体、集团、业主、运营管理方、经营商户及代理角色；核原文、别名、经营地与有据关系，纠错和查看期间 | 股权/集团归属、品牌所有权、运营管理、代理委托分别有依据；集团财务不下灌品牌或单店，名称相近不自动合并 |
| 品牌主体 | 维护品牌名称、别名、市场、定位、产品/服务、品牌事实、禁用主张、来源、账号、门店与合作；可从品牌直接开始研究、监测、策略或内容 | 品牌不等法律公司，也不等某商场的一家门店。同一品牌的不同市场、城市和具体经营实体保持范围，可共同使用的事实引用同一版本 |
| 商业项目与场所 | 保存项目名称、业态、城市、地址/有据坐标、商圈、业主/运营者、阶段与范围；查看和比较高端、社区、街区、奥莱等项目 | 商业项目是经营分析对象；商圈、到访目的、营业日、面积、租户组合与服务约束影响分析，不能只作地图坐标 |
| 场内品牌、经营商户与门店 | 从项目看场内品牌/业态及具体门店，从品牌看各项目/城市门店；核入驻、开业、迁址、换铺、暂停、闭店、撤场及适用有效期；支持补证、更正、比较 | “品牌在该项目出现”“经营商户承租”“具体门店营业”“临时快闪合作”是不同关系；来源只支持其中一种时不得补成全部。租约条款、销售与租金仅在取得授权数据时成立 |
| 项目与品牌的经营关系 | 检查业态/租户组合、新入驻或退出、空缺与机会，联动品牌活动、门店反馈、共同营销、合作资源、经营方案和复盘 | 场内品牌不是附录名单：它有自己的动态和业务消费者。商业项目聚合需明确当期门店纳排、统计口径与重复归属，不能把全部品牌全国声量当场内表现 |
| 产品、服务与SKU | 维护适用的产品/服务、版本、规格、价格来源、上新/可供时点、库存与履约约束，关联品牌/门店/活动/素材 | SKU延期影响预算排期与作品；公开信息与内部库存分开，不能从“发布上新”推定所有门店已经可售 |

## 4. 真实使用方式

### 广州太古汇、场内品牌与客户工作的连续经营

以用户提供的广州太古汇资料为研究起点，先识别它是商业项目、相关官方账号还是客户委托材料。建立或关联对应项目，不凭文件名称自动确认客户、经营方、账号所有者或完整场内品牌名单。按任务取得项目官方目录、品牌/门店资料及其他适用来源，形成有来源与期间的场内品牌、经营商户、具体门店和活动关联；未知与待核可继续补齐。

用户打开项目，可以看场内品牌及业态、近期入驻/退出、项目活动、相关反馈与经营分析；点进某个场内品牌后，继续看该店、本城其他店或跨城同品牌比较，不丢项目上下文。可并列同体系不同城市项目、本城高端商业及其他有理由的标杆，地图、列表、指标和报告使用同一比较范围。某品牌退出后，过去报告仍按当时范围打开，当前监测与分析按有效期更新；涉及多个客户的私有资料保持隔离。

发现某店服务问题、一个品牌上新或联动活动机会时，直接进入事件核实、品牌/经营分析、共同营销方案、预算与内容制作，承接客户评论、修改、交付及真实反馈。项目、品牌和门店指标分别可核；官方账号的四篇样本不推定全项目或全部场内品牌表现。此流程是主体业务的验收任务，既不是固定预装广州太古汇数据，也不是只做一个地图展示页。

### 一次广告与公关整合传播

从客户Brief和品牌/产品事实开始，明确受众、目标、购买或参与障碍、预算、期限、供给与转化承接；形成信息主张、创意路线、媒体/渠道角色和传播路径。用户能直接比较媒介计划、素材规格、资源/报价、制作与投放排期、品牌安全条件和实验留量。已确认部分锁定，客户改变产品时点或渠道范围后，预览影响并只修订相关素材、预算与排期。

产出可编辑提案、媒介计划、预算表、各类稿件与媒体作品。发送、发布、采购或资源承诺按具体授权和真实执行能力处理，不能以排期记录冒已投放。复盘核实际回执、覆盖、受众反应、线索/经营结果及增量证据，保方法限制；公共传播数据也能形成成立的观察，不假造客户后台结果。

### 一次品牌上新及后续修改

用户放入客户简报、现有PPT、品牌材料与预算，直接提出交付目标。寰意先展示已理解的目标和必要缺口，再按任务取得市场/竞品/创作者来源；用户可在同一工作中随时补资料或修改约束。系统发展机制不同的方案，给出各自依据、预算、风险、资源和执行取舍，形成可直接修改的演示、预算和内容。

客户提出“只改第3—5页指定对象，增加韩语版本，视频改第3镜”。寰意定位原对象和意见，列出事实、译版、工期/预算和已确认内容的影响；用户选择采用范围。修改只作用于所选对象，其他页、样式、媒体、备注和锁定内容保持。新版本交付后可重新打开继续改，原版本及当时意见仍可查看。

采用方案后，合作Brief、交付规格、权利、档期和成本各自确认。创作者提交内容，负责人员就原作品验收或要求补改；替换和取消保留原因、影响与实际费用。已授权执行取得真实回执，未执行清楚区分；实际表现、退款和客户反馈回流，形成下一次调整。产品完成分析与草拟无需外部写操作批准，发布、发送或承诺资源只按具体授权执行。

批准绑定具体版本、对象、用途、市场/渠道及有效期限。事实、权利或要求改变后，系统只标记受影响批准和成果，提示重新确认、局部修订或撤回相关交付；不会自动重写未选内容，也不会把旧交付改成新版本。历史成果保留当时依据与批准状态。

### 一次经营问题与持续复盘

用户问某场所近期投诉上升的原因，并附已有经营数据。系统获取相关公开信息，区分投诉事件、重复传播、主题和未检查来源；核营业日、租户范围、单位和分母。先交已经成立的分析，不凭缺失推断零值。对资源约束形成可行备选，用户记录决定、实际采取的措施及结果。监测继续关注同一问题，下一次分析复用已确认背景，方法/样本变化仍明确。

### 一次独立研究和专业文章

用户可以只有一个问题、一份文件或已有人工稿。直接打开阅读与写作工作面，系统按问题搜集必要来源，处理矛盾和反例，结论可回到原页/段/表格。用户就地引用、写作、修改观点；AI按用户指定范围提供建议或完成获准修改，范围可以是选区、全文或多个关联成果，始终核对当前版本并保人工修改。源资料更正后，相关段落、结论和已导出版本可定位；用户决定哪些内容更新，不必重造整篇文章。

### 一次完整视频或播客

用户可以从提纲、脚本、素材、录音或已有工程开始。准备阶段有研究、叙事、分镜/前采工具；制作阶段有真实播放器、素材、时间线、音轨与对象参数。词级文本辅助定位和剪辑，文字校稿与真正剪音频明确分开。选take、补录、剪辑、字幕、声音和章节均可局部操作。渲染/编码失败保工程，缺源可准确重连；工程和成片分别交付并重开核对。

### 原创如何达到专业生产深度

创意从用户问题、受众张力、品牌理由、事实边界和可用资源展开。用户可从一句观点、命名、活动机制、声音叙事、脚本、图文或空白稿起步；不要求先填完完整简报才准手写和保存。专业策略保原技巧、单线表达、多线战役和品牌世界观的深入/抽象能力，用户能在任一层创作并查看实际关联；不会把四层变成必填审批流程。

多个候选应在驱动参与的机制、叙事视角、受众关系、媒介用法或执行方式上存在真实差异，并说明为什么适合此品牌、资源与目标。选定后进入可执行的内容、场域、渠道、节奏和预算；相关背景改变只更新依赖内容。旧固定词槽、随机拼句和“超过某数量就晋升方法”的无依据默认需要替换，原研究中有定义、有适用例和反例的方法保留为可检验工具。

公关稿、媒体稿、文章、社媒稿四条常规路径完整保留，与自由结构和专业提案并存。同一事实底稿生成各自适用的结构与表达，单篇修改不覆盖其他稿，语言/平台变体能逐项核对、审阅、导出和重开。Persona保受众、内容支柱、口吻、禁区、商业边界和行动引导风格六项；可选采用，版本明确，不能靠粉丝数或昵称自动决定KOS/KOL/KOC/UGC身份。

跨市场命名和本地化保意义、发音、书写、语境、受众联想与母语意见；事实、日期、金额、否定和人物关系先保真，再发展自然表达。未核的商标/使用冲突和文化疑点如实列明；翻译、原生创作和配音分别验证。用户锁定自己的句子或镜头后，智能修改须尊重锁定；输入中的金额、否定或授权歧义先澄清，不能“自动纠错”后执行相反任务。

创作评价保问题是否解决、品牌区别、受众理解、表达工艺、可执行性和修改负担。新颖度分数、词汇变化或模型偏好只作有限辅助，采用理由与专业分歧可追溯；实际反馈可反哺下一次工作，经核验后才进入可复用方法。

### 持续监测进入工作

用户明确启用某主题和来源范围。寰意按实际允许频率检查，呈现发生了什么、依据是什么、为什么与当前工作有关。提醒可以打开原文、核对、忽略、关联已有工作或开始新分析；不会把每次网页哈希变化都当重要消息。源撤回或更正可以触及已用判断和成果。来源暂不可用不抹掉其他结果，服务停止期间显示监测空窗。

## 7. 自研架构：统一基础，保留专业领域

保留一个产品核心、一个身份与权限体系、一套来源与文件管理、一条成果版本和恢复链。模块化单体配独立重任务执行进程仍是当前合理起点；先证明真实多用户负载和媒体工作，再决定是否需要扩容。不能因为新产品就把有效基础全部丢掉，也不能把旧内部域结构原封不动搬回来。

业务模块明确负责客户委托、商业主体/项目/品牌/场内经营、经营分析、品牌与市场、创作者合作、活动与内容、研究计算、文档、视频和播客各自的语义与状态。主体领域有自己的档案、关系事实、期间和生命周期，完整消费共同来源、权限和版本基础；不能只剩通用标签，也不复制第二套权限与数据库。用户给目标、约束和必要材料；后台完成方法选择、任务依赖、计算、取数和恢复。API负责边界和调用，前端负责呈现与操作；二者不各自复制业务规则。

对象共同底座包括身份、所属空间、来源、适用范围、父版本、作者、授权和变更记录。专业对象包括客户委托与参与角色、法律主体/集团/品牌/商业项目/商户/门店及带时间的关系、产品/服务、账号归属、比较集、事件/观点、指标定义、洞察/备选/决定/行动/结果、报价与预算、合作约定、Campaign/Topic/Series/内容变体、文档对象、时间线、客户意见。对象共享机制但不强行共享一种内容结构或状态机；业务归属、资料使用范围和登录授权分别校验。

周期性经营资料保已确认的字段映射：原列到业务含义、单位/币种、时区、主键、退款与含税口径、来源结构和确认版本。下期列顺序变动可继续使用，语义变化才要求核对；重复订单、更正和迟到退款按原身份形成新版本。大表按块处理、可续页可取消，不能截前若干行冒全量。此能力直接服务每月经营和预算工作，不另造数据工程产品。

一个工作空间在同一时间只有一个权威运行端。Windows本机和用户控制服务端使用同一业务合同；Web连接实际核心。离线编辑保存为明确的本机草稿，带原版本；重连对比而非静默覆盖。实时协作、跨端同步与本机草稿分别定义，不能只把API可访问当多人协作通过。持续监测依赖权威端实际运行，部署选择与费用不能隐瞒成永久免费全天服务。

### 账号、工作空间与扩展

普通本机工作不设强制账号墙，需要访问受保护资源时在原位置完成身份验证。登录取消/失败保草稿；登录后明确选择本地工作如何合并；同一认证回调不能重复迁移。用户能管理已启用登录方式、撤销单个或全部会话、导出账号数据、申请删除并在原约定30天窗口内撤回。工作区退出、作品删除和账号删除是不同动作；数据删除落实到授权留存规则，不能以历史版本保全为由无限保留用户要求删除的内容。

原已规划的邮箱验证码注册/登录、Google登录继续保留；Apple仅在原账号及对应端接入条件满足时展示，当前不因此购买账号或新增集成。验证码输错可就地纠正，重发遵真实冷却；同邮箱不同方式由服务端核实后关联，解除不能把用户锁在账号外。训练用途同意首次询问无预选，可查看、调整和撤回；同意本身不自动启动训练。账号资料导出有明确内容与到期，下载仍核权限；退出当前/全部会话与清除业务聚焦是不同动作。未列入原范围的通行密钥、二次验证不作为本轮擅增入口。

成员邀请、角色改变、移除、客户项目退出和归档均有实际结果；服务端校验权限，移除后在途任务也不能继续读取或写入相应资源。用户只看与自己有关的控制：资料用途、连接、成员、用量、偏好、备份和恢复。受控诊断可脱敏导出，求助不自动上传客户正文或会话秘密。

用户扩展模式保留默认关闭、协议与风险说明、备份、隔离自测、启用、实际任务结果、更新/回滚、停用和卸载。关闭后对应执行权限、进程与会话真正停止，已有作品仍可打开。创始人的内部发布管理使用独立权限：精确包及版本检查、签名和批准、分批发布、真实状态观察、暂停或回滚；普通用户API也拒绝这些动作，不能只隐藏按钮。工程信息只在对应受限管理中出现，不塞进普通用户工作。

既有Skill、MCP、GitHub只读资料连接分别保完整生命周期。Skill从准确来源/版本预检、安装自测，到业务执行、更新回滚和卸载；MCP从端点和工具发现、效果及权限准入，到实际调用、取消、撤销和变更重核；GitHub按用户权限、App安装范围和明确选择的仓库交集读取。连接成功不等工具或仓库任务成功；目录中的9/72等历史数量不变成已可用宣称。候选集成按已批准范围逐项核实，不批量安装新服务。

用户可管理原规划内获准的模型/API来源、检查连接并撤销；自研核心不取消合法的用户自带配置能力，也不自动选择新供应商作为后备。配置、运行批准、实际发送资料和用途分别明确，当前未核的历史供应商不写成默认可用。

### 采集与浏览

一套采集系统支持任务发现、来源选择、获取、解析、去重、原生字段和分页恢复。公开HTTP/Feed/结构化数据适合的路径优先使用；页面渲染、交互和用户登录需要的路径使用同一系统下的受控浏览。不能预先宣称浏览器或爬虫永远更准；按原文完整性、身份、时间、字段和复核结果判定。

各用户自行登录与授权，没有开发者身份或地区名单的产品资格限制。平台会话、任务和工作区隔离；登录、可查看、可采集、可使用和可发布分别表达。浏览承载须真实支持输入、中文输入法、选择、滚动、文件和人工接管；截图加几个导航按钮不算完整浏览器。来源限制、挑战和授权失效如实恢复，不承诺所有可登录站点均无条件抓取。

采集与浏览属于全产品核心数据能力。用户提出“监测活动反响”“调查某类投诉”“找近期议题与创作者”等任务后，产品应自行发现适用来源，取得可用原文与原生数据，持续处理并进入分析、策略、创作和交付；不能要求用户先交一批URL，或靠手工导入代替信息发现。原登记来源和已批准数据类别逐项继承，可用路径立即使用，单个平台未就绪不阻其他来源。

### 官方登录、扫码与登录态接续

连接时说明将连接哪个平台、哪个用户/工作区、用于哪些工作。平台官方页支持扫码就原样呈现有效二维码及官方确认；支持密码/验证码等方式时由用户在真实官方页面完成，不另造仿冒登录表单。取消、扫码过期、验证码、设备确认、授权拒绝和账户切换各有可继续路径，已输入的工作目标和资料保持。

两类接续必须区分清楚：有已批准官方OAuth集成的，按平台要求在系统浏览器打开授权页，经匹配回调与PKCE等适用校验取得限定权限令牌；该令牌不自动等于网站Cookie。使用网页登录获取的，在寰意专用隔离浏览会话中完成登录，产品保管这个会话实际需要的状态并验证目标访问。外部个人浏览器登录成功不自动把登录态交给寰意，不读取个人浏览器配置；外部跳转没有受支持回调时，要诚实说明并返回可完成的官方登录路径。

扫码扫描、身份验证、会话建立和实际数据可读分别核验，不能只见头像或跳转就显示全部连接成功。保管状态遵循其实际机制：Cookie、localStorage、适用IndexedDB及会话内临时状态，不能只导出一个Cookie字段便宣称所有平台可持久恢复。用户不用搬运Cookie；存储受保护、避免明文日志和诊断包泄露，状态只供相应授权任务使用。不同人、客户和平台账号隔离；同账号并发按页面/任务与操作权协调，不能多个进程同时写同一浏览档案。

重启时先检查身份与目标访问；失效则让用户就地重新登录，保最后成功位置、游标、已获数据和原任务。撤销连接后停止新使用和不再获准的在途提交；保留依法及按用户规则可留的历史成果。公开页面无需账号时直接使用公开路径，不为所有来源强加登录。免费可用来源和现有资源优先，实际额度、运行成本和时效如实呈现，不承诺无限免费或账号绝无风控影响。

依据：[Playwright认证状态](https://playwright.dev/python/docs/auth)、[持久浏览上下文](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context)、[原生应用OAuth](https://www.rfc-editor.org/rfc/rfc8252.html)。本轮仅核通用机制，未登录账号，未把任何平台的扫码/API能力冒充已验证；平台精确协议、当前版本和来源权限逐项核实。

### 从数据获取到专业监测

| 用户工作 | 必须获得和理解什么 | 产品交付与后续操作 |
|---|---|---|
| 舆情与服务问题 | 对象/别称/歧义、原话、事件起点与演变、根评论和回复、表达对象与立场、可证传播关系、实际覆盖 | 有依据的事件梳理、影响与处置优先级、需要核实的问题、可编辑回复/服务/沟通方案；纠正误归属、处理意见、跟进实际措施和结果。严重性、声量、扩散速度分开判断 |
| 活动监测 | 活动/地点/时间/渠道/创作者对应关系，筹备信息与变更、执行记录、参与者反馈、现场问题、内容传播和获准经营结果 | 活动前机会与风险、活动中需处理变化、活动后复盘；关联预算/排期/合作/内容，保实际与计划差异。没有内部到场/订单数据就不把发帖量当到场或销售 |
| 话题与趋势 | 关键词及别称、语义主题、时间基线、重复转载、新事实、观点分化、相关人群/地区/平台和未知覆盖 | 可核话题脉络、变化原因候选、与品牌/项目的相关性、内容机会及不适宜跟进理由；一键进入研究或创作并保原来源，不能只给热词榜 |
| 品牌、竞品与市场 | 品牌/产品/渠道/门店真实关系，产品服务变化、官方发布、用户反馈、可比指标和财务/行业资料 | 比较与机会判断、创作者/渠道候选、经营或策略备选；同名消歧和口径核对，客户改市场/期间后只更新受影响判断 |

监测对象可组合在同一项目或工作里，不再为每种监测复制采集器和来源库。用户通常只需说清关注目标、适用范围、希望多快得知变化和什么值得提醒；系统复用背景、提出必要消歧，并将原生字段与分析方法放在后台。规则、来源选择与通知偏好仍可直接修改。

每次获取分别记录搜索发现、详情、评论、回复、媒体、作者、历史和分页的覆盖。保来源原生ID、原网址、作者身份依据、父子关系、原生发布时间/修改时间、实际取得时间、范围、内容快照、解析版本和精确位置。源删除、更正、暂不可用和没检查不同；去重保全部出处，转载不重复充当独立证据，跨平台身份不凭同名强合。

原17行×19列来源合同与6平台×12能力自立路径是两份不同的逐格清单，保各自原条目和后续已登记范围，不拿计数互相替代。技术文档支持、配置、会话、实际取得、分析/保存/导出许可分别核实；广告/流量、创作者中心与公开内容数据面各自显示实际可得字段。聚光专业号未配置只阻该数据面，不要求开通，不把公开互动换算成投放实绩。原数据种子数量不成为预装门槛或当前覆盖证明。

每份来源可检查允许字段、用途、保留期限/刷新频率、到期、转载、训练、外部处理及其许可依据状态。普通基础导入不增加用途问卷；实际额外用途需要相应权限。到期或撤回定位受影响读取、分析、导出和已知作品，保仍允许的原稿，恢复须重新核实际许可。后台维护区分服务可达、页面连接、平台会话与检查时点；429按限流冷却处理，不误报登录失效；计划检查、实际运行、过期未更新和已恢复不同。

浏览上下文保当前任务问题、页面地址与版本、选区、导航路径、列表与详情关系、滚动/分页位置、已取得材料及它们的出处。动态内容、懒加载、评论展开、分页和页面变化须真实处理；需要附件时保原件并回到原工作。网页正文是资料，不是执行指令；页面里的提示不能改变用户目标、权限或工具范围。

时效按用户任务和来源能力选择：适用且已批准的推送/Feed/增量接口可优先，普通页面按允许频率检查；统一执行端处理来源冷却、共享速率、任务优先级、重试与补检。原事件时间、实际检查、发现、分析和通知分别计时。重要新事件可单独提醒，重复/低价值变化合并摘要；用户可纠正、忽略、静音、调整关注和直接开始处置。关闭应用或运行端休眠形成真实空窗，不伪称全天实时。

监测的有效结果要能回到原文、形成可编辑判断/简报、进入相关活动或客户工作、承接处置与复盘。新事实和源更正追到已用结论、作品、批准与导出版本；其余人工修改保持。基础关键词/字段变化、人工分类与确定性统计无AI可用；语义归并、立场、复杂关联和策略增强单独证明质量，不能用固定文本假装理解。

### 这一核心能力怎样验收

用真实获准来源完成一次品牌活动：活动前找相关机会与风险，活动中监测话题和投诉，活动后结合实际可得传播与经营数据复盘。中途加入新别称、纠正同名误报、出现来源更正、评论第2页失败、登录过期、服务重启和另一个用户同时使用；已得信息和原工作都保留，重新登录后安全续取，未查到的数据不补零，不串账号，不重复提醒或执行。最后交可修改分析、客户演示/文稿和待办处置，并在后续变化到来时继续修订。

评价看任务相关来源覆盖、字段完整与准确、来源定位、去重/归属错误、实际发现延迟、提醒是否值得处理、重登恢复以及最终分析是否解决客户问题；分母和抽样范围明确。平台名、抓取条数、登录成功或“实时”标签不能替代这些结果。

### 计算、知识与AI

确定性数据处理与专业计算独立运行。词面检索、混合召回、重排、原段定位、反证、方法假设及结果质量各有合同。预算/资源/统计方法由真实业务问题驱动；有限算法、情景计算、近似和数学保证分别声明，不能用论文名或JSON结果证明专业交付。

已要求的专业计算须逐项形成可检查结果，不能再被“分析”二字替代：SOV、净情绪、真实问卷NPS和可比销售份额保各自定义与分母；异常与预测保缺测处理、区间、回测和小样本边界；预算、排期与资源组合交满足硬约束的方案和不可行原因；归因、增量评价和MMM情景保身份、窗口、退款、实体期间及识别条件。方法可在后台选择，但用户能检查假设、改业务条件、重算并比较版本。原已批准的完整数学采用范围逐项保留，当前有限实现不能成为永久缩减范围的理由；原论文、已批准方法、待验证候选和用户功能分别记清，困难性或下界论文用于限定承诺，不能因为读过就硬接成新功能。

同一套自研行业AI保留并整合以下组成：既有通用模型接口、既有自研小模型、贯穿全业务的行业智能、未来自有模型的训练与蒸馏。通用接口保统一协议、能力/资源识别、用户配置、错误与恢复；小模型保原任务、权重或学习策略、数据来源、消费者和独立评价，逐项优化而非被大模型接口或“以后训练”替代。第三方基础权重、自有训练参数、自研专业编排分别如实说明。新的教师模型研究不是新增运行时模型接入，也不取消原已有接口。

这些能力进入经营、品牌、采集监测、研究、原创、Office、视频和播客的真实工作。短答、长任务、并行、补充、更正、取消、部分结果、工具失败和恢复使用相同工作身份。用户人工改稿后，后到结果不能覆盖；重新委托时使用当前选区和版本。来源引用、计算结果和模型判断分开。小模型或规则适合的分类、归属、检索/排序等任务依据已存在实现及实测分工，不预先捏造某模型已能胜任，不强迫所有请求走最大模型。

原多模态能力保留：文本、图片/视频理解、转写、说话人、配音，以及规划内用于作品的素材生成，各自有真实输入输出和实际消费者，不能拿文字回答替代。文档图文、封面、分镜和片头保可编辑图像/文字/形状/图层及布局关系，仍归对应作品，不另建独立图片编辑产品。每类模型、权重、语言、格式和资源状态分别核验；缺运行资源是对应未完成项，不改成假结果或暗用新外部服务。

长期上下文优先保用户目标、否定约束、金额日期、人工最新稿、已确认决定和已发生效果；历史摘要可压缩，这些关键条件不可静默裁掉。按实际运行模型计量上下文预算，资料按问题分段读并保原文追溯；用户更正或忘记时派生索引、缓存、摘要及在途旧结果同步失效。跨日继续工作以真实复用和更正传播验收，不以聊过多少轮或索引数量证明记忆可靠。

资料索引、工作记忆、用户明确偏好、方法候选和参数训练分别管理。记忆可检查、纠正和忘记，影响检索、摘要和在途结果；跨客户不串用。非参数策略须以独立任务评价后采用、可撤回。CPU及其他不依赖GPU的参数训练纳入当前自研AI升级：围绕产品任务确定模型、数据和标签、资源预算、独立留出、实际消费者与回退，而非把全部训练后置。GPU训练保留资源具备后的条件路线，不阻当前产品。开发前置准备与审核先完成，再按确认方案实施编码、迁入和训练；方法获准不等于立即执行。读取资料不自动授训练用途，新增权重、外部服务、付费资源与GPU运行仍遵适用边界。

### 文档和媒体

文稿、演示、表格与PDF用各自真实对象和布局行为，统一版本、来源与评论。导入保原包；编辑记录作用对象和基线；已支持部件形成最小必要变更，未修改部件保全。不支持对象逐项说明且不静默丢弃；这不是永久削减要求的理由。公式必须真实计算，原件往返及目标格式兼容须用实际复杂文件验证。

媒体使用真实素材身份、源时基/采样率、图层/片段/轨道、处理链和渲染描述。原件、代理、缓存、项目和导出各自管理。预览与导出来自同一工程语义；文字校正、字幕编辑、剪辑、声音替换是不同操作。操作/处理链保原始素材和人工编辑，失败可以恢复；缺插件或源素材不能悄悄导出变化后的成品。

现有已规划Python/Flask、Flutter、SQLite、Playwright、文档与本机媒体组件只在版本和许可确证后使用。精确选型、性能和平台兼容未验证的部分列待证，研究发现不自动变产品依赖。核心业务、对象编辑、连续工作和体验由自研实现；不以新SaaS、第二套系统或临时外部工具填补产品能力。

### 必须解决的实现难点与选型结论

当前保留Flutter承载Web/Windows应用、Astro承载官网、Python/Flask和Worker承载业务及重任务的方向；换框架没有证据能解决当前能力缩水和页面构图问题。允许针对已证实的平台缺口调整承载，但先用目标操作验证，不能为统一代码牺牲输入法、可访问性、媒体预览或文件处理。现有源码与基础依赖可复用，不代表完整专业编辑器已有现成解法。

| 实现问题 | 这次确定的处理原则 | 尚须实际验证 |
|---|---|---|
| 一个JSON正文装不下Office、媒体和专业业务 | 通用成果保存身份/版本/权限；正文分别引用各领域的对象结构。AI和人工调用相同领域操作，禁止绕过对象边界写整份稿 | 多对象原子修订、对象删除后的意见处理、跨成果版本一致性与重开 |
| 文件包未变不等页面显示和语义未变 | 对未编辑包部件保原字节；被编辑部分保命名空间、扩展、关系、局部结构和目标宿主行为；原文件只读保留 | 复杂母版/分组/图表/字体/旧新格式的显示与编辑往返，不能只比文本或ZIP存在 |
| 公式文本、缓存值和实际重算是三件事 | 建立适用公式的自有语法、类型、依赖和重算合同；变更后传播脏状态，错误/未支持明确；不信任旧缓存冒本次结果 | 交叉工作表、范围、命名、循环/错误、日期/数值语义与导出后的重算一致性 |
| 浏览自动化库不等完整产品浏览器 | 采集与浏览共用隔离会话和任务许可；Web与Windows分别验证真实可操作承载；登录挑战由用户接管 | IME、选区、滚动、剪贴板、上传下载、声音、弹窗和归还任务；同账号多任务也不能互相抢输入 |
| SQLite不是无限并发方案 | 单权威端内短事务、受控写入、文件与DB一致性对账；重计算/解析移出请求和写锁；不让多机器同时写同一SQLite文件 | 实际团队负载、长媒体任务、备份恢复和压力下交互；达不到需求时按证据调整存储方案，当前不擅接新基础设施 |
| 一个任务完成不等整件工作完成 | 持久工作计划引用真实输入与结果；步骤可并行但提交须校验当前父版本、权限和取消状态；部分结果可继续用 | 断网/重启、迟到结果、重复回调、撤权与提交竞态；外部结果不明时先读回，不盲重发 |
| 缺测和不确定性容易被“智能”抹平 | 观测、计算、估计、情景、建议、决定、实际执行分别类型化；专业方法匹配实际假设 | 同一真实任务的反例、冲突来源、口径变化、无解与样本外情况，保留错误和人工纠正 |

本轮针对原问题核了官方格式行为：Open XML的兼容预处理可能删除未选择内容并影响保存，因此“加载成功”不能证明原件保全；公式的缓存值是上次计算结果，计算链只记录顺序、不是完整依赖树。这支持保原包和独立重算的架构决定，**不引入Open XML SDK或其它新依赖**。依据：[兼容处理](https://learn.microsoft.com/en-us/office/open-xml/general/introduction-to-markup-compatibility)、[公式与缓存](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas)、[计算链](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-calculation-chain)。

Playwright的浏览上下文可隔离本地存储与会话，但产品还须自行实现工作区、文件、任务和操作权隔离；复用相同账号的浏览状态不会隔离该网站服务器上的数据。当前线上文档含新版本能力，不能未经版本核对就写入已实现范围。依据：[上下文隔离](https://playwright.dev/docs/browser-contexts)、[认证状态及共享账号适用条件](https://playwright.dev/docs/auth)。

## 8. 保留、合并、替换、新增的执行含义

保留完整经营、品牌、研究、原创、Office、视频、播客、浏览采集、监测、智能与协作；保留无AI路径、原件与人工修改、三语界面、原内容语言目标、外观/动效选择及各表面职责。成熟有效源码经边界/调用者核对后吸收，不把“全新”解释为全部重写。

合并重复采集器、会话、来源库、权限判断、任务状态、版本保存和导出机制；合并同一客户/简报/资料的重复录入。专业领域方法、用户选择和不同编辑对象保持完整。合并入口不能变成隐藏或删除功能。

替换被否定的界面结构、通用卡片套所有工作、固定空侧栏、关键词当理解、填词当原创、数据缺失时造默认值、阶段成功当交付、开发日志当用户流程。旧研究与失败证据保留用于追溯，不作为活跃规则再次执行。

新增或深化：范围变更跨成果影响、客户意见冲突处理、对象级锁定和采用、监测与既有判断连接、可计算的产能与排期、源更正传播、真实交付完整性核对，以及直接可控的任务适配界面。多数已有原要求，应称补完整和强化；其收益必须落到一件用户工作，不能为创新另开无关产品。

## 9. 交付与防止再次走偏

开发以完整工作闭环分批，每批同时完成所需业务、数据、界面、编辑、保存与恢复。依赖先后由当前工作决定，不能把全部后端做完作为前端开工门槛。原完整范围长期保留；一批能用不等全产品完成。

每项只记录五个可核事实：用户能做什么、产品实际处理什么、交什么可编辑结果、修改时必须保住什么、如何证明重开与失败恢复。旧要求到新合同逐项有去向，不能以标题相同判覆盖；合并有理由及行为对照，撤销能力须有直接用户依据。正式文档原位修正矛盾，不追加多套规则解释旧规则。

工程验证分开看代码、运行、格式/计算、用户操作和交付质量。真实验收包括客户PPT指定页对象修改、预算局部更新、来源更正传播、完整视频/播客、两用户会话隔离、服务/网络中断恢复与再次修订。视觉在真实密度和操作中验，不用静态首页、样例演示、计数或模型自评替代。

Web与Windows分别验收，官网展示真实可用入口和操作；macOS/iOS按既定设备条件后置，完整表面职责保留。没有可用包不显示可下载；没有运行监测不说实时；没有实际AI结果不说已增强。必须分别通过无AI基础工作和AI增强工作。

所需仓库调整是将完整能力合同、设计及架构原位落实到当前唯一仓库，更新相关调用者和规则，删除已确认替代实现的活跃入口及失效引用，保护有效未提交成果和用户数据；正常分支、审阅、必要CI和PR合并，不用文档发布冒充完成。按最新直接授权同步正式文件、调用者和规则；产品实现与验收仍按实际结果逐项完成。

### 开发批次怎样保住全产品

第一批应交付可被真实用户留下来继续使用的工作：接自己的资料和客户稿、取得必要公开信息、形成专业判断或原创方案、直接编辑并交付、收到意见后精确修订。这一批所需的身份、来源、任务恢复、计算、Office及界面同时接通，不以一张首页或“比较三份材料”覆盖它。

持续监测、完整经营与品牌合作、专业媒体及智能增强沿同一底层接入；前端可独立成立的编辑、布局和交互同时推进。具体并行顺序按已核依赖与实际人员确定，不能凭空给日期或用批次名隐藏未做能力。研究/文稿/视频/播客独立用途、全部行业能力及既定表面逐项留在总验收中，第一批成功不能自动关掉后续要求。

发现缩减风险时先检查原用户操作，而非措辞是否仍有关键词。比如“支持PPT”必须查页对象、母版、媒体、备注、局部修改和重开；“支持监测”必须查实际检查、变化识别、提醒、恢复和工作承接；“支持自研AI”必须查真实业务结果、持续输入、工具失败、记忆和独立质量。每次合并同时更新已确定的正式合同与消费者，防止实现和文档各走一套。

### 官网与可持续使用

官网完整保留产品与能力、三类使用场景、真实操作、公开成果/案例、帮助、信任/隐私、更新、下载和联系。可以有更强的原创品牌叙事，但案例与演示标真实版本和性质；没有可用安装包不显示虚假下载，联系提交必须有实际回执，合法的进入目标回到产品当前工作。官网不代访客执行采集、上传和业务生产。

产品同时具备入门帮助、就地错误修复、支持升级、服务状态、真实用量/额度/权益、契约兼容、升级迁移与回滚支持。用户数据/素材备份按一致版本生成并在隔离目标实际恢复；冷启动、升级、网络中断、磁盘不足、源授权失效都保已有有效工作。监测所需持续运行条件和成本如实说明，当前不擅定价格或接入付费资源。这些大多在后台承担，普通用户得到的是可理解的状态、控制与恢复入口。

### 贯穿一次修改的验收

同一客户已经有方案、演示、预算表、视频和播客。客户改一个价格事实、一个禁用词、视频第3镜和播客一段表述。系统准确指出涉及的对象、译版、字幕、章节及已批准状态；按授权应用修改，保住其余页、公式、镜头、轨道和人工稿。保存新版本，关闭再打开，继续处理未完意见；旧版本仍可核查。最后交付同版可编辑原生文件及需要的成品，实际读回和播放。无关内部诊断文件不塞进客户交付包。

原专业挑战还包括：100轮长期工作中的30条关键条件及事实更正；100份、累计约1000页的矛盾/更新资料研究；百万行分块经营资料；多门店资源约束变化；同一活动10个内容变体；三角色并行审阅及撤权；检索后、生成中、批准后发送前、外部接收但客户端超时四处中断；大工程冷备份、恢复、升级与回滚。这些用于防止小样例冒充专业产品，不是所有用户的必经步骤或产品容量上限；时间、内存、并发和资源需求须绑定真实硬件实测。

评价同时看结果正确、专业工艺、修改成本与总人工负担。AI增强与人工无AI、确定性基础、相同获准模型的直接使用比较时，保持相同材料、目标和资源口径，记录失败重试与人工修补。来源引用率、模型自评分或单次速度不替代专业可用性，实际销售等商业结果也不能由模拟任务伪造。

一个完整的跨域事务示例：客户降低预算并要求改指定演示页。业务层创建约束修订及影响集；预算层生成可行方案和真实公式更新；演示编辑层给所选对象变更；共同版本层核父版本/权限/锁定后提交关联新版本。任何部分失败，保有效草稿和原确认版，不把半次更新包装为整包完成。来源更正、评论处理、媒体替换沿同一机制，但使用各自对象语义。

原批准九族与固定26篇研究不是一一对应。九族未闭的完整义务保留，有限场景不代替完整主算法/定理重放；困难性研究不变成一个用户功能。详细前提、原采用记录与已读源码界限见[数学消费者核对](reference/reconstruction/intelligence-review.md)。

## 17. 自研AI路线的最终明确

保留原有通用接口，保护并优化自研小模型，使行业智能进入全部专业消费者，同时保留将来训练自己的模型。这些组成并存，不用教师模型研究替换既有AI，也不以当前无GPU为由只做接口壳。

教师是监督角色，并无各家共用的标准教师权重。优先研究真实任务样例/工具轨迹/人工修订监督，学生使用适合任务的既有自有模型或获准基座；动态事实仍通过来源与检索获得。DeepSeek、GLM、GPT/gpt-oss、Grok Bot及Grok不同版本的权重与输出条件不同，不能看到开源代码就推定可任意蒸馏。具体研究结论、原模型资产状态、未来训练/留出评价/重载回滚见[自研与蒸馏专项](reference/reconstruction/owned-model-distillation-review.md)。

现在完成上下文、工具、确定性计算、检索、领域对象、已有模型消费者和独立评价；有资源后按具体权利与资源授权训练。模型下载、训练loss和模型文件不是交付，真实收益仍由§16及各领域工作验收。没有GPU只后置依赖它的训练，不后置产品智能、媒体或其他业务。

每项从合同和实际调用者出发，先核已有结果再补真实缺口。普通技术问题、依赖/格式兼容和Bug由开发者解决：复现具体失败→读相关实现→需要外部知识时查当前官方/GitHub及适用研究→选择许可兼容且不新增未批集成的解法→实现/同步消费者→受影响检查和真实操作。确定的内部错误直接修，不用无关全网研究拖延；难题不能变成跳过功能、造假或再次提交总规划的理由。

子代理适合不冲突的源码/资料核对、限定实现和独立检查。根对原要求、证据、改动、跨域连通和最终质量负责，不能直接拼接代理结论；视觉决定与审阅由根负责。一次能力完成要真正保存、重开、局部修订和故障恢复，再经过正常分支/审阅/必需CI/PR合入主线并读回。数量、状态标签和过程文档不是进度替身。

### 开发入口、资料归档与运行一致性

唯一开发和运行核验根为 `D:\寰意`。启动、停止、构建、数据根和恢复都从当前根解析；已有受控SDK可位于工具目录，不复制第二套运行环境。保用户选择的模型、推理、服务档位、账号和网络配置。运行版本、构建来源及保存/恢复必须真实读回。

研究原件集中保存在根内 `研究资料/`，按来源保持原文件、相对结构、版本及引用，附逐件原位置和保全索引。资料归档不执行旧规则，不把摘要替原件，不把文件哈希核对当专业验收。私有或大体积资料不提交公共Git；仓库的 `docs/reference/` 保可分享的研究说明及采用索引。已定位保全、尚缺原件、代码迁入和运行验证分别记录，不能互相代签。

### 旧根删除的条件与操作顺序

用户已允许在迁移完成后删除旧路径。先完成：有效未提交源码/资产/原研究/许可/模型与用户成果的逐项保全；旧数据实际写入者和位置核实、一致备份与迁移；新路径构建并真实使用Web/Windows，保存/修订/重开/恢复；所有启动器、钩子、快捷方式和任务入口不再依赖旧根；原件引用迁为新根可查位置；回退副本能实际读回。

最后停止确认属于旧产品的写入者，核将删除的最终绝对路径确为 `D:\LUMENIS_REBUILD\序\序境` 且未夹带仍需资料，再执行已授权删除。现在条件未齐，不删除。不能提前删掉原件后再让用户补文件，也不能为“已经搬迁”保留偷偷读取旧目录的运行路径。完成后唯一开发、运行核验和维护入口继续是 `D:\寰意`。

## 19. 主体目录的明确规则

主体目录仅有品牌主体、商业主体两类；用户可以持续添加、增加主体，正式主体目录收录有据在中国境内营业的商业主体或品牌主体，包含国际品牌在中国境内的经营。原主体目录、分类、身份、档案、别名、来源、品牌及场内门店关系、历史数据与生命周期完整保全并可纠正扩充，不能因目录重构缩成固定名单或几个背景字段。待核对象保留待核状态，核实后纳入；主体移除/重加遵同一身份和历史链。

主体类型沿用品牌主体/商业主体，业务上分别表示客户委托、项目属性、场内品牌关系、经营商户、门店及话题。商场等商业经营对象本身归商业主体；关联档案不扩成并列主体类型。场内经营完整承接原业务，有据关系不是权限。境外来源和案例可按任务研究，不自动扩成全球主体目录，也不删除合法历史材料。

行业AI为一套产品能力。通用接口、已有自研小模型、领域工具与编排、未来自有模型训练是同一能力的内部组成，不是四套AI产品或四个必选入口。业务用户按任务使用或直接编辑，无需调度这些组成。

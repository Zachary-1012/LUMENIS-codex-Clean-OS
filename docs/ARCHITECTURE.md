# 寰意 / OEVIRA — 产品与系统架构

本文件定义已批准的新产品结构、数据边界和部署取舍，供后续需求、接口、设计和实现共同遵循。产品工作与验收范围由 docs/PRODUCT-SPEC.md 定义，视觉和交互由 DESIGN.md 定义，HTTP 字段与错误码由独立 API 合同定义。规格通过不代表源码、运行或用户结果已实现；实现状态必须依据对应版本的真实证据记录。

## 1. 产品目标与共同工作模型

寰意服务商业运营团队、品牌与代理机构、个人研究者与创作者。三类用户使用同一工作空间、来源、材料、成果和授权基础，通过任务入口、分析口径、编辑能力和工作空间成员权限体现专业差异，不形成三个互不相通的产品。

共同工作链为：用户意图与约束 → 材料和授权来源 → 获取或导入 → 核对与处理 → 分析或原创创作 → 可编辑成果 → 保存、修订、交付、恢复 → 按需跟踪。视频和播客可直接从用户素材开始，不要求先登记商业主体或创建营销案例。

## 2. 架构原则与部署形态

采用模块化单体与独立重任务 Worker。一个产品 API 进程负责身份、授权、业务规则和短事务；一个或多个同版本 Worker 领取已持久化的采集、研究、渲染和导出任务。模块共享同一数据库和文件存储，但各自拥有数据写入规则与领域 API。Worker 是执行形态，不是第二个业务服务或第二份真相。

首期不拆微服务，不引入 Redis、Kafka、Temporal、独立搜索集群或云端模型服务。任务表承担可恢复的工作领取与状态持久化；短事务写业务数据，网络采集和媒体渲染均在事务外执行。文件只由统一 Artifact Store 管理，业务库保留授权、版本、哈希和可恢复定位。

前三种运行形态共用同一产品服务与领域逻辑：① Windows 本机模式把 API、Worker、数据库和文件放在同一受保护数据根，本地工作不要求注册云账号；② Web 连接本机核心，页面由正在运行的本机服务提供，不能把纯静态页面称为完整产品；③ Web/Windows 连接用户控制的服务端，同一 Workspace 由唯一服务端负责权威持久化与 Worker，多用户通过 API 共用该端。SQLite 是首期单节点关系数据库，使用短写事务和 WAL；并发容量超过实测能力时，先基于负载证据另立数据库升级决策，不静默引入第二数据库。数据库迁移必须保全历史版本和文件引用。

一个 Workspace 同一时间只有一个权威运行端，客户端选择并显示该端；不得同时将本机数据库与云端/服务端数据库作为可写主库，不做首版双向数据库同步。远端连接断开时，客户端可以保留可识别为“本机草稿”的未同步编辑及其 base_version；它不是已保存的服务端成果。重连后先读回远端版本，用户可比较并显式应用或另存新版本；冲突不得静默覆盖。持续监测只在该 Workspace 权威端的获授权 Worker 实际运行期间执行。本机休眠、关机、用户停止服务或部署主机不可用时，任务进入可恢复的暂停/中断状态，不宣称仍在监测。云主机、托管、域名、付费资源和生产部署均需另行选择并批准。

## 3. 服务端边界与模块责任

- Identity / Workspace：用户、工作空间、成员关系、会话和角色；服务器从已验证身份取得租户上下文。
- Work：一次有目标的工作、输入关联、状态、成员可见范围；不包含监测调度实现。
- Source / Acquisition：统一来源登记、平台能力清单、授权引用、HTTP 与受控浏览器采集、原始观察记录。
- Material：用户文件或文本原件、类型、安全边界、解析结果、定位信息及其来源。
- Research / Claims：分析方法、观察引用、事实主张、局限与不确定性；推断不改写原始观察。
- Artifact：报告、分析稿、提案、文档、播客/视频项目和版本链。
- Media：时间线、片段、转写、编辑决策、代理文件、渲染和导出作业；不拥有独立来源库。
- AI Gateway：一个内部模型调用与质量边界，供各业务模块按类型调用；不拥有业务真相或权限。
- Job Runtime：通用持久化任务记录、领取租约、检查点、取消、重试、恢复、进度和结果引用。
- Experience API：组合服务端可用数据和行为状态供 Web/Windows 使用；不复制领域规则，不直接访问别的模块数据库表。

模块之间使用版本化的内部请求/响应对象和稳定 ID。调用者传入用户意图、材料及业务参数，不向用户暴露内部任务栈、表名或代理编排细节。身份与权限在服务入口校验后，以不可由客户端覆盖的上下文传递。

## 4. 多用户、工作空间与权限

工作空间是租户隔离单位。用户可加入一个或多个工作空间；成员关系记录角色、状态和授权时间。工作、材料、来源身份、任务、Artifact、导出和存储对象均带工作空间归属。任一读、写、下载、取消、恢复操作都须同时验证当前用户成员资格、资源工作空间和动作权限；只凭不可猜 ID 不构成授权。

客户端提交的 tenant/workspace ID 只能选择用户有权进入的空间。服务端验证后生成请求上下文；异步任务将该已验证上下文绑定在可信任务记录中，Worker 执行前重新验证任务目标和仍然有效的成员/来源授权。跨租户资源按不可区分的未找到响应拒绝，避免 IDOR 泄漏。

本地首次启动使用数据根中的一次性 bootstrap capability 建立本机用户和工作空间。Capability 不写日志、URL 查询、源码或提交记录；本机授权完成后作废。这个初始化入口不是任意远程注册。远程协作身份由已批准的产品账号/邀请方案负责；本地 token 不得被用作云端登录。每个用户可以自主连接其拥有并授权的来源账号，不存在开发者身份或地域名单的产品资格限制。

## 5. 产品会话与平台会话

产品登录标识与来源平台身份严格分离。产品会话仅代表用户访问工作空间；平台会话代表该用户在某平台允许的指定只读采集范围。平台凭据不得从产品会话推导，也不能因为用户登录产品就自动启动采集。

平台连接记录归属明确的用户和工作空间，包含平台、权限范围、授权/验证/到期/撤销状态、最近健康读回和恢复提示；密钥材料使用本机操作系统安全存储或部署者明确配置的密钥边界保护，不能明文写入普通业务字段或日志。用户可连接、检查、重新认证、撤销。失效、挑战、限速和无权限是独立结果状态；不得绕过挑战或静默换号。撤销后停止新使用，历史观察和成果继续按留存规则可读。

## 6. 统一采集与受控浏览器

所有入口汇入一个 Acquisition Service：HTTP 公共页面、RSS/Atom/Sitemap（若能力清单支持）、浏览器页面以及用户导入。平台差异只存在于已有采集契约内的解析器、原生字段映射和能力描述中，不得另建某平台的调度器、会话存储或证据库。

每个来源能力清单至少描述稳定平台 ID 与别名、允许的连接方式、读取字段、时间语义、当前能力状态、需要的授权、分页/游标语义、速率约束、错误分类和恢复入口。未知能力返回 unavailable/unknown 及原因，不通过平台数量、登记记录或 HTTP 200 推断采集成功。

浏览器是产品内受控网页运行区，不是通用电脑控制。每个用户、平台身份和任务使用隔离的浏览上下文；同一已授权上下文可供用户手动浏览或在权限允许时由 AI 协助网页理解。用户可查看当前页面、接管操作、停止、重新登录并返回任务。导航、重定向、下载和页面资源须限制到安全策略允许的目标；阻止内网地址、危险文件与跨会话凭据泄漏。不得绕过登录挑战、验证码、访问政策或反自动化边界。外部浏览器打开是用户显式动作，不代替产品内路径。

## 7. Source、Observation、Claim 与 Artifact 数据合同

四类对象有各自身份、生命周期和写入语义，不互相覆盖：

1. Source 是来源身份和连接边界，例如一个网页、出版物、平台账号或用户文件。连接凭据单独保管。
2. Observation 是不可变的来源观察快照，保留 source ID、来源原生 ID/URL、原文或文件哈希、平台发布时间、实际捕获时间、原生字段、采集器/解析器版本、范围与权利状态。修订解析规则产生新的解析版本或观察派生记录，不改历史原始内容。
3. Claim 是可追溯的分析主张，保存支持它的 observation/material/locator IDs、方法与参数版本、作者（AI/人）、生成或修订时间、信心/不确定性、反证和审阅状态。未知与未采集不同；观察或模型输出都不能自行晋升为核验事实。
4. Artifact 是用户可编辑、可交付的结果。每个修订版本不可变，记录父版本、文本/媒体文件引用、引用清单、输入版本、方法/模型/配方版本、人工编辑摘要、导出引用和创建者。

跨对象使用不丢失租户、来源、时间、权限、版本和错误语义。引用必须落到精确材料或观察定位符和匹配引文；引用不能证明来源真实，也不把外部观察升级为销售、市场份额、转化或因果事实。

## 8. Work、资料与成果关系

Work 是用户一次目标明确的工作；监测是持续关注，不是一个无限 Work。Work 可关联多个可复用资料和来源，Materials/Artifacts 也可在有权限时被多个 Work 引用，但对象只保留一个原始 ID 和一个版本链。

Material 在用户选择的保留期内保全可恢复的原始字节与 SHA-256，并单独记录解析状态、原因、纯文本和 Unicode 码点偏移定位符。删除或到期按用户授权及留存规则执行，已引用成果显示原件已删除及其影响，不伪称仍可查阅；不得以保全版本为由无限保留用户要求删除的内容。受支持的文本、表格、文档和可提取文本 PDF 由同一材料合同解析；产品格式目录可随已批准能力扩展，不被首批解析范围封顶。不能提取的文件仍保留原件，并明确显示无法提取、格式不支持或需要另行处理。引用精确匹配材料内容和定位符。

Artifact 的并发编辑使用 base_version 乐观冲突检测。冲突时服务端返回当前版本，不覆盖用户未保存的内容；客户端可对比、复制分支或显式基于新版本重试。恢复历史版本必须新建一条版本，不回写或删除历史。导出绑定不可变版本与格式；只有文件实际创建、大小/哈希读回并与版本记录绑定后才视为导出完成。相同租户幂等键返回同一合法结果，不重复产生副作用。

## 9. 任务运行时与状态机

Job 记录 tenant/workspace、发起用户、类型、输入快照/版本、幂等键、状态、attempt/lease generation、已提交检查点、进度事实、错误分类、输出 ID、创建/更新/取消时间。队列只是持久化记录的可领取视图，不拥有另一个业务真相。

通用状态为 draft、queued、running、waiting_for_auth、retry_wait、cancel_requested、cancelled、partial、interrupted、failed、completed。状态只能沿合法转换前进；completed 仅在所有所需持久化结果、输入版本关系和结果读回完成后提交。partial 明确说明已成功与未覆盖范围。interrupted 表示结果可能已写入、任务需恢复核验，不可盲目重新产生外部效果。

提交幂等键的唯一范围为 tenant + operation + key。Worker 以原子租约认领 Job，每个 attempt 有单调 generation；只有当前租约可以提交状态。采集记录以来源和原生对象标识去重；缺少原生 ID 时使用来源 URL/捕获规则版本/内容哈希组合并明确其限制。文件写入先到临时目标、校验后原子发布，再写文件指针；孤儿文件由可审计的对账清理，不删用户有效输出。

检查点在每个安全提交边界保存：来源分页游标、最近处理对象、解析版本、已提交 Observation ID、Artifact ID/版本。先落持久化记录，再推进来源游标；重试从最后读回检查点继续。取消在下一个安全边界停止新请求和新副作用；已经完成且校验成功的输出保留。退避次数、频率、并发和单租户资源配额明确可观测，服从来源的 Retry-After/限速，不无限重试。

## 10. 监测语义

用户显式创建关注规则，定义范围、来源/平台、关键词或实体、时间/频率、保留期限、预算和授权。创建规则或打开页面不触发采集；每次立即刷新或启用定时计划都显示来源、范围与下一次运行时机。默认不静默开定时监测。

一次监测运行是 Job，输出为新增的 Observation 和/或变化摘要，不覆盖旧记录。每个来源独立报告可用、未授权、过期、限速、暂不可用、未覆盖或成功结果；某来源失败不阻断其它已就绪来源。更新时间与原生发布时间分开呈现。对数据覆盖不完整的时间窗，显示缺口，不将缺失变成零或“没有变化”。

## 11. 研究、分析与原创创作

研究和分析从用户问题、范围和可用资料开始，输出结论、逐项引用、方法、未知、局限与下一步；不能要求用户设计算法、组装内部任务参数或浏览内部分析流水线。对商业运营与品牌代理可提供领域化报告、竞品/受众/市场判断、活动方案和决策建议，但每项事实判断绑定数据与时间范围。

原创文案、Pitch、报告、方案、视频脚本及播客脚本可不依赖商业主体记录开始。Brief、语言、受众、事实约束和用户参考进入 Artifact 版本链。结果可编辑、按事实与主张规则检查、保存、恢复和导出。未经授权的发布、投放、购买或其他外部业务效果不属于保存草稿。

## 12. 文档与专业媒体

文档工作流保留原件，并通过一个自有 Office/PDF 对象模型读取、定位、编辑、比较、恢复和交付 Word、PowerPoint、电子表格与 PDF。Word/DOCX 使用已规划的 python-docx 读取和编辑支持对象；PPTX/XLSX 的对象与包关系由自有 OOXML 适配逻辑处理，不增加第二文档服务。编辑器提供段落/表格单元格/幻灯片对象/表格区域等精确范围，按对象 ID 记录变更；不支持对象逐项保留或标记，不将文档整体压成纯文本/图片。未修改对象、公式、样式、媒体关系、备注及顺序必须保全；客户指定 PPT 页编辑后输出新版本并验证未选内容。PDF 阅读支持页面定位、文字选择、批注/高亮与出处锚点；批注以精确页码/位置/引文绑定原件。交付为可单独打开的新 PDF 副本和 Artifact 版本，不覆盖原 PDF，且保留标注与原始页码对应。pdfplumber 负责已规划的 PDF 读取；PDF 副本生成使用兼容性锁定中已批准的本机组件，不凭空添加服务/依赖。扫描件无法读出时保留原件并标明 OCR 能力状态。Markdown、Word、PowerPoint、电子表格与 PDF 等适用交付格式按许可兼容实现逐项启用，完整文档对象编辑范围不受首批格式限制。

媒体项目有素材清单、转写版本、时间线、片段引用、音轨、效果与剪辑决策、预览及导出版本。用户可以直接创建视频/播客项目、逐段编辑、预览、取消渲染、恢复和重新导出；预览、脚本和渲染成品明确区分。渲染失败不能删除源片或覆盖上次可用导出。重试按 Artifact/导出幂等合同运行。媒体引擎须从已批准、许可兼容的本机组件中选定并记录版本；在引擎未选定或不可用时明确显示能力不可用，不引入未批准的托管媒体服务。

## 13. 自有 AI 边界

AI 通过一个自研 AI Gateway 进入现有业务工作流。调用类型、租户、用户、允许材料、来源使用目的、模型/权重/运行时版本、资源限制和输出模式显式绑定；生成式结果需持久化实际输入引用、推理状态、版本、错误和结果质量。

只采用已经纳入计划、许可可商用且完成版本/边界核验的运行时、权重和库。引用研究、发现开源项目或开发机存在模型均不构成集成许可。不得新接 SaaS 模型/服务作为隐式后备。AI 不可用时基础采集、手动分析、编辑和保存仍可完成；依赖模型的专属结果显示明确不可用原因，不返回固定文本冒充推理。

GPU 训练不在当前批准范围。训练、用户数据学习、参数更新和跨租户数据混合均关闭。今后的学习要有独立数据权限、可审计样本、隔离验证、真实收益和回滚审查，不得改变历史 Evidence、用户成果或权限。

## 14. Web、Windows、Website 与后续 Apple 端

Web Workspace 与 Windows 是主要操作端，共用业务合同、身份、权限与版本规则。本机模式在 Windows 上由 API/Worker/SQLite/文件存储组成一个权威单机端；Web 连接本机核心时访问的就是该端真实 API 和 Worker，不是脱离服务的静态演示；Web/Windows 也可连接同一用户控制的远端服务端，一个 Workspace 必须唯一选择本机或服务端作为写入与监测权威。不同客户端不得各自建立可双向写入的 Workspace 副本。离线时仅将尚未提交的文本/操作保留为带本机状态提示的草稿，不执行同步；重连后核对服务端当前版本，由用户比较、应用为新版本或另存，避免覆盖。

远端服务端实际运行 API 与获授权的 Worker；服务关闭时任务暂停并保留恢复检查点。Public Website 仅介绍可验证能力、案例/帮助与真实进入产品的链接；不提供虚构试用、假工作流或访客业务数据处理。macOS 后续作为桌面操作表面，iOS 后续作为阅读、审阅、提醒与适合移动端的任务操作表面；二者复用同一身份和 API 合同，在设备就绪后各自验收。官网是公开展示与帮助入口，无业务执行。Web 编译或 Windows 运行不能替代 Apple 原生接受证据。

## 15. 安全、数据生命周期与依赖边界

所有写入通过统一校验、身份、租户、权限和副作用边界。本机 API 默认仅绑定 loopback；Host 校验只接受服务预期的 loopback 主机与端口，不信任 X-Forwarded-Host；Origin/CORS 使用精确允许名单，不接受通配符，也不为任意远端网页登录开放本机 capability。DNS 重绑定和伪造 Host 请求拒绝。产品会话校验 secret 只存哈希；需要再次使用的平台凭据按第5节由受保护密钥存储保管。日志不得写入 capability、session token 或平台凭据。文件读取按精确对象授权；上传限制大小、类型、压缩炸弹/恶意文件风险和解析资源。HTML/Markdown 输出安全编码；对 URL、下载、重定向和浏览器请求防 SSRF 与路径穿越。日志仅记录必要的 tenant/job/source ID、操作状态和错误类别，不记录 token、Cookie、完整私有原文或敏感文件路径。

保留期、用户删除/撤销、备份恢复需能区分原件、观察、主张、Artifact 与审计记录，并保留合法版本链。数据导出和恢复前复核租户归属；不能从含多租户数据的备份将其它租户文件写回当前租户。

已规划技术栈包括 Python、Flask/Waitress、标准库 SQLite、Flutter（Web/Windows 及后续 Apple 客户端）、Astro（Public Website）、Playwright（受控浏览器实现路径）、python-docx（DOCX 处理）和 pdfplumber（PDF 读取）。精确的 Python、库、SDK、浏览器内核和工具版本进入兼容性锁定记录，须实际验证版本组合、平台支持和许可后才成为构建约束；开发机探测到的 Python 版本不等于产品选型或兼容性通过。不同表面复用同一 API 与领域合同；Playwright 等已规划组件不得变成第二采集器、浏览器产品或外部服务。新增库、模型、运行时、媒体二进制、托管服务或收费资源必须先证实产品缺口、来源和商用许可并获得相应批准；不因研究或测试增加产品接入。

## 16. 运维、可观测性与演进

Health 只报告进程、数据库可读性、存储可写性、Worker 心跳和版本，不替代功能验收。业务观测包括 Job 阶段耗时、成功/部分/失败比例、来源错误状态、取消响应、恢复点、导出读回与孤儿文件对账；按租户聚合并防止泄露内容。运行日志应能关联 Job 与 Artifact，但不包含敏感正文。

发布具有可恢复备份、版本兼容的数据库变更、文件保全检查和回滚操作。应用、Worker、合同、数据库模式和依赖版本形成同一发布证据。性能扩展由实际并发、锁等待、文件量、CPU/RAM 与用户等待结果评估触发，不因预期流量提前加基础设施。任何扩容不改变单一事实源、来源授权和成果可恢复语义。

本架构定义目标与不变量；不将任何目录、接口、测试、演示或空页面描述为 IMPLEMENTED、VERIFIED、RELEASED 或 OPERATING。逐项结果只记录在对应接受证据中。

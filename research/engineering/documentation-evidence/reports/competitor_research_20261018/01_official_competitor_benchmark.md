# 序境 / LUMENIS：六项竞品官方证据与全链路任务基准

研究时间：2026-10-17 19:24–19:26 UTC（北京时间 10 月 18 日凌晨）。

## 1. 结论先行与证据边界

1. 模型调用、检索、多入口、节点数量、日志和简单人工确认均已有成熟基础实现，不能仅凭存在这些能力宣称壁垒。
2. 比较单位应是“普通用户完成且能继续修改的业务成果”，并追踪其证据、定义、版本、权限和发布回执；不能把媒体文件可恢复等同于用户可编辑。
3. 六产品不是同层替代品：LLM 是开发构件；Khoj 是知识/研究助手；Dify 是应用编排与运行平台；数说聚合是企业数据整合分析产品；Brandwatch 是消费者情报与社媒运营套件；Canva 是创作和编辑平台。应同时比较单品和合理组合基线，组合的集成、交接、维护成本必须计入。
4. 本报告只核实公开官方材料，未登录、未运行产品实测、未采购、未发布内容。文档陈述不是效果实测。未见功能不等于功能不存在；不提供虚构速度、价格、错误率或排名。
5. LUMENIS 最新工作区资料尚未在本项研究中取得；以下是针对用户要求的验收框架和差距假设，不能当作当前产品缺陷或已实现功能清单。

## 2. 产品证据卡

### 2.1 Simon Willison 的 LLM

官方稳定版 changelog 当前页列出 0.36，日期 2026-09-22；比较时应锁定实际安装版本和插件版本，不能拿泛称“大模型”替代这个具体产品。[L1]

已核实：CLI 和 Python API 可调用工具，Python 函数和 Toolbox 可组织工具及状态；嵌入集合保存在 SQLite，可检索相似内容；默认 SQLite 日志记录提示与回答。日志文档已包含线程、轮次、工具和片段来源关系。0.32 更新加入结构化消息及可暂停、恢复工具循环的能力。[L2–L5]

意义：仅“能调用模型、工具、留痕、嵌入检索、恢复执行”不能成立差异化。它是可控、透明的工程基线；业务实体、审批、编辑器、发布器等是否具备，应按实际插件/上层实现核验，不能默认内置，也不能禁止它合理使用扩展。

限制：工具安全是调用者责任之一，官方明确提醒提示注入与数据外传风险。[L2] SQLite 有记录并不自动保证业务语义一致、来源授权或事务幂等。测试应纳入工程配置和维护人工成本，分离首次搭建与日常运行成本。

### 2.2 Khoj

官方仓库主分支 README 声明互联网/个人文档问答、自定义知识/人格/模型/工具代理、语义搜索、自动化研究、图像、多个客户端及自托管。此处是滚动主分支证据，未固定 commit，不等同于任一已部署版本。[K1]

Chat 文档支持多轮、引用所用笔记、限定文件、在线与研究命令；其说明将相关笔记、最近消息及元数据交给聊天模型。Automations 可按本地时区重复执行查询并邮件交付；自托管邮件需额外 Resend 和认证配置。[K2–K3]

意义：多入口、知识记忆、研究与周期通知已有基线。真正应测的是更换入口、隔日继续、修订事实后跨成果更新是否可靠，而非有没有聊天历史。

限制：文档显示上下文机制，不证明所有长期约束永不遗失；研究功能存在，不证明全球社媒全量许可覆盖。自托管、客户端与 SaaS 功能可能不完全同版。知识与编辑交付需实测，不可从图像生成推断图层编辑。

### 2.3 Dify

Human Input 官方文档最后修改 2026-07-29：暂停、请求表单、直接修改文本、反馈再生成、决策分支、超时策略；链接可由无账户人员响应，首次响应关闭请求。Web app 方式不适用于 Trigger 启动的工作流。[D1]

Version Control 文档 2026-07-17：草稿/线上/历史版本分开；恢复旧版本覆盖草稿；指定版本 DSL 导出及 API 执行等取决于付费计划。[D2] Logs 文档 2026-10-16：节点轨迹、输入输出、状态、耗时和 token；可用既有参数重跑；Cloud 保留期依计划，Sandbox 30 天。[D3] Retrieval Testing 可临时调参数，测试与普通检索共享端点。[D4]

意义：不能把可视化编排、人工改稿、版本、运行轨迹作为独有突破。更值得比较业务用户能否无需重新配节点就完成复杂修订，以及业务对象和下游成果能否保持一致。

限制：流程版本恢复不等于业务数据回滚；带参数重跑不等于副作用安全恢复。Cloud 文档不能无条件外推到任意 self-host tag。评测必须记录计划、版本、模型和插件。

### 2.4 数说聚合

官方产品页定位为企业级全域数据整合与分析平台，展示关键词监测、声量查询、搜索、评论分析、账号/单帖监测、AI 洞察和自动报告；公私域及多模态接入、接口、自定义指标维度看板；SocialGPT/Deep Research Agent 辅助分析报告。[S1]

意义：应作为中国社媒数据与业务洞察的专项强基线，测特定行业/平台/时间窗的数据可得性、聚合口径、结论证据和日常分析人工时间，而非仅比较“有没有 agent”。

限制：官网“全网”“精准”“高质量”等为供应商主张，不是可重复的召回率/准确率证据。公开页未提供足以验证的完整平台×字段×历史窗口×地域×权限矩阵，也不能据此证明海外覆盖。没有采购账户和样本导出，当前不能给效果分数或实际价格。

### 2.5 Brandwatch

Consumer Research 功能页列出消费者研究、多来源内容、历史档案、地域/情感分析、导入自有文本、报告与导出；API 页区分研究数据、上传数据和发布数据接口。[B1–B2]

更关键的限制来自 Listen 来源帮助：Instagram 公共数据包含特定账号池，公开帖与评论并非同等覆盖；部分采集需认证/目标源配置；新评论页可能需 72 小时且不保证所有请求覆盖；Listen 不索引付费墙文章。Listen、Consumer Research 及加购源必须分别核验，不能混称一套全球全量能力。[B3]

Publish 有编辑预览、活动、日历、审批和错误状态；当前帮助说明一个帖子不能同时创建发布到多个网络。审批支持多级，但过期未批准不发布且不通知创建者/审批人，需要重新排期。[B4–B5]

意义：应同时作为数据来源深度、团队运营、传播回执的基线。序境若能减少跨网络重复编辑和漏批后静默失败，有用户价值，但是否实现必须实际测试，不能由架构图推定。

### 2.6 Canva

Visual Suite 2.0 官方发布材料涵盖多设计类型、Sheets 和 AI 辅助创作；用户可在编辑环境继续修改。Video 2.0 官方材料描述时间线剪辑、同步和分层。[C1–C2] Brand Kit 帮助说明品牌资产、字体/色彩、模板、角色及控制；品牌模板迁移可保留原图层、顺序与时序。[C3–C4]

Content Planner 可排期，但一份设计一次仅排一个社媒平台，多设计文档暂不能直接使用 Planner；权限、计划、平台格式和连接条件需核验。[C5]

意义：普通用户可直接改文案、布局、素材、品牌样式、字幕和时间线，应成为内容/媒体验收底线。仅交付 MP4、PNG、素材 zip 或技术人员可重跑项目并不足以达到这一基准。

限制：可编辑不等于任意生成内容均为精确可编辑语义对象；跨格式、导出再导入和团队权限效果需实测。把全套排版/剪辑器自研一遍不一定最经济，应比较可靠的原生编辑、集成编辑与格式往返三种方案。

## 3. 全产品面同口径任务套件

采用一个虚构且无敏感数据的跨境消费品牌，固定品牌简报、产品事实表、素材版权表、预算、渠道和中英日三语；任务相互依赖，但各阶段单独计分。目标包含中国、美国、日本，不能仅英语网页。统一 30 天观察窗及采集截止时刻。人工构建小型金标准；数据可用性评测与模型/推理评测分轨，避免把平台授权差异误计为模型能力。

### T1 经营运营：从目标到可执行计划

输入预算、毛利、库存和负责人约束，输出渠道计划、预算分配、任务责任和成功指标。随后将预算减 20%、一个 SKU 延期。验收所有受影响任务和数值更新、无越权支出、公式可解释，未影响内容保留。比较 LLM/Dify 上层工作流与完整产品；Canva 等不适用部分标 N/A。建议单轮预算 45–90 分钟，不是性能预测。

### T2 品牌：约束持续与版本变更

把品牌事实、用词禁区、视觉规则和地区例外转为可审阅对象；第三轮修改品牌主张并撤销旧事实。验证文案、海报、视频字幕、排期中全部受影响版本更新，已批准版本失效策略明确，未重新批准不得传播。重点对标 Canva 品牌约束、Dify 人工流程及跨产品组合。建议 30–60 分钟。

### T3 研究：有证据的跨市场决策

同一问题要求三个市场各至少两类来源，输出竞争机会、反证、未知和不建议动作。插入同名品牌、过期新闻和互相冲突的销售说法。核验逐条来源支持性、时间和地域适配、独立来源数量、缺失披露，不能把搜索结果数计为研究质量。Khoj、LLM、Dify 作统一资料包基线；Brandwatch/数说聚合另跑原生来源轨。建议 60–120 分钟。

### T4 数据：可重算的口径与覆盖

给 1,000 条去标识样本，含转帖、重复、时区差、缺失指标、多语讽刺和品牌歧义；重算声量、互动率和份额。对原生来源固定平台×市场×语言×字段×日期×权限矩阵；区分未支持、支持但无结果、被限流、未授权。验证去重、分母、排除项、时区及可导出原始行。建议 60–120 分钟。

### T5 内容：普通用户全编辑

产出简报、长文、六条三语社媒文案与可编辑图表；非工程用户直接修改一句事实、一段结构、一项图表值并撤销一次修改。随后局部 AI 修订，必须保留已接受人工编辑。验收无需源码/JSON/命令行，结构化编辑可发现、可预览、可撤销，事实链不断。建议 45–90 分钟。

### T6 媒体：可交接的真正编辑工程

交付一张海报、三页轮播和 30 秒短视频。用户换 logo、移动主体、改字体、替换第二镜、将第三区间缩短两秒、修字幕和音量，再输出 1:1/9:16。检查文本仍为文本、图层可选、字幕时序准确、音画不漂移、版权和源素材关联；跨设备重新打开后继续编辑。以 Canva 编辑体验为基线，素材包/成片只能记导出分。建议 60–120 分钟。

### T7 传播：排期、批准与实得回执

为两个市场、三个渠道编排排期并模拟批准/退回。只用测试适配器或已授权沙箱，禁止真实外发。注入一个授权失效、一个平台格式错误和一个过期批准；核验错误分类、用户动作说明、重排期、版本绑定、无重复发布以及回执与成品对应。真实覆盖必须按渠道逐项说明。建议 45–90 分钟。

### T8 运行：中断恢复和隔日续作

在检索完、媒体生成中、批准后发送前、服务端已接收但客户端超时四处注入故障；测试任务恢复、成本上限、取消、权限隔离、模型替换、旧版本重开。要求恢复前确认外部状态，不能盲目重试造成重复传播。恢复后核对所有业务事实、人工改稿、批准状态和实际回执。建议 60–120 分钟，另需真实隔日续作窗口；压缩时间模拟不得声称等同长期实测。

## 4. 语义连续性专门判定

预埋 20 项不可丢失的业务事实/约束，建立每个对象的源版本。每次阶段切换、入口切换和人工修改后检查：

- 保留率 = 应保持且正确保留的约束数 / 应保持的约束数。
- 更新召回率 = 已正确更新的受影响对象 / 金标准受影响对象。
- 误改率 = 不应变却被改动的对象 / 不应变对象。
- 证据闭合率 = 可从最终主张回到原始来源及版本的主张 / 可验证主张。
- 人工编辑保留率、旧批准误用次数、跨项目污染次数。

“上下文还在”“日志能找回”“共享同一数据库”都不是上述指标的替代。可先设目标：关键事实错误、越权发布、跨客户泄漏和重复外发均为零容忍；其他阈值由用户认可的试点任务校准，不能伪装行业标准。

## 5. 时间、费用、错误和质量记录方式

每个任务至少三次、普通用户至少三名；随机产品顺序，统一培训，熟练开发者另设配置组。分开首次搭建、用户主动操作、系统等待、审核修复和跨工具搬运时间，报告中位数及范围。样本小不宣称统计显著，条件允许再扩样。

总成本 = 分摊订阅 + 数据许可 + 模型/媒体调用 + 托管 + 人工时间×统一小时费率 + 失败重跑。未知报价显示待核价，不写零。速度只比较达到相同质量门槛的结果；失败轮次不能从均值里删除。

质量由两位盲评者检查事实、证据、商业可用性、品牌一致、多语自然、编辑成功和渠道适配，并记录分歧。错误分为数据缺失、检索、推理、事实、格式、权限、时序、重复副作用和编辑破坏；保留每次修复动作与用时。

实际测试记录字段：产品/计划/build/commit、模型/plugin、地区/语言、输入数据 hash、来源时间窗、试验 ID、操作员训练量、开始结束、主动秒数、等待秒数、修复秒数、token/媒体/费用、产物版本、核验者、错误类别、恢复结果、原始证据链接。缺失一项仍能报告，但需揭示可比性损失。

## 6. 升级差距假设（均待 LUMENIS 现状验证）

H1：若业务对象缺少证据、口径、品牌版本和依赖关系，优先做可见可操作的关联更新机制，而非增加入口/节点。

H2：若普通用户只能下载、重跑或改提示词，内容与媒体应补足直接编辑闭环；可以集成合适编辑器，但需保证权限、源工程、跨格式与回写一致。

H3：若数据来源只展示“已接入”，补平台/地域/字段/时间窗/授权和缺失矩阵，并对有偏样本限制结论；优先补真实业务任务所需覆盖。

H4：若审批未绑定具体成品版本、外发无幂等和查询回执，运行与传播必须补语义状态机；仅增加重试次数会扩大风险。

H5：若研究只提供答案与链接，补主张级证据、反证、数据口径和可重算图表；先与统一资料包基线测质效，再谈自有研究优势。

这些是设计建议，不是修改指令。执行任何产品代码、数据库、运行环境变更前，仍须用户对具体修改明确授权。

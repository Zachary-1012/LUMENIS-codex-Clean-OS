# 多平台采集分析对齐方案 v1.0
# 与小红书分析逻辑一致，按平台划分层级，各平台特色信息卡片

## 一、分析主链路（与小红书完全一致）

采集(各平台adapter) → 标准化入库(notes表, source_platform字段)
→ subject_hit() 主体硬过滤 → is_taikoo_verified=1
→ build_cross_platform_events() 跨平台事件聚合
  - 按 event_hint/title/topics/publish_date 分组
  - risk_score 取 max，负面计数
  - source_count 统计跨平台覆盖
  - AI summarize/translate 增强（不改写风险事实）
→ risk_engine 风险判断 → daily_report 日报生成

## 二、平台数据层级（4层）

L1 概览层：全平台汇总（总量/风险/事件/趋势）
L2 平台层：单平台数据（xhs/douyin/weibo/bilibili/zhihu/instagram）
L3 内容层：单条内容详情（各平台特色字段）
L4 事件层：跨平台事件聚合（同一事件在多平台的传播）

## 三、各平台特色信息卡片字段

### 小红书 XHS（已有）
- 封面图 / 标题 / 正文摘要
- 作者昵称 / 作者ID
- 点赞 / 收藏 / 评论 / 分享
- 话题标签 / 发布时间
- 主体命中标记 / 风险等级

### 抖音 Douyin
- 视频封面 / 标题(desc前80字) / 完整文案
- 作者昵称 / sec_uid
- 点赞 / 评论 / 收藏 / 转发
- 播放量 / 时长
- 发布时间(精确到秒)
- 主体命中 / 风险等级

### 微博 Weibo
- 正文(HTML清洗后) / 话题标签
- 作者昵称 / uid / 认证状态
- 点赞 / 评论 / 转发
- 发布时间 / 地区(region_name)
- 来源设备 / 是否长文
- 主体命中 / 风险等级

### B站 Bilibili
- 视频封面 / 标题 / 简介
- UP主昵称 / mid / 等级
- 播放 / 弹幕 / 点赞 / 投币 / 收藏 / 分享
- 视频时长 / 分区(tname)
- 发布时间
- 主体命中 / 风险等级

### 知乎 Zhihu
- 问题标题 / 回答摘要 / 文章标题
- 作者昵称 / uid / 认证
- 赞同 / 评论 / 文章数
- 内容类型(answer/article/question)
- 发布时间 / 更新时间
- 主体命中 / 风险等级

### Instagram
- 图片/视频封面 / caption / 位置
- 作者用户名 / 粉丝数
- 点赞 / 评论
- hashtag / 发布时间(ISO精确)
- 媒体类型(post/reel/story)
- 主体命中 / 风险等级

## 四、UI设计工单（同步UI窗口）

### 工单1：多平台概览页 L1
- 全平台数据汇总卡片（6平台数据量/风险/事件数）
- 平台分布饼图 / 趋势折线图
- 跨平台事件Top列表（source_count高亮）
- 风险预警面板

### 工单2：平台分层页 L2
- 平台切换Tab（xhs/douyin/weibo/bilibili/zhihu/instagram）
- 各平台独立数据统计（采集量/互动量/风险分布）
- 平台特色筛选器（抖音按播放量/时长，B站按分区，微博按地区）

### 工单3：平台特色内容卡片 L3
- 6套平台特色卡片组件（按上述字段设计）
- 统一交互：点击展开详情 / 主体命中高亮 / 风险标记
- 卡片底部统一操作：加入事件 / 标记误报 / 查看原文

### 工单4：跨平台事件页 L4
- 事件卡片显示多平台来源（source_count + 平台图标）
- 事件时间线（各平台首次出现时间）
- 事件传播路径（平台间扩散关系）
- 风险等级统一展示

## 五、数据库适配

notes表已支持 source_platform 字段，各平台采集数据直接入库。
新增平台特色字段存储在 raw_data JSON 中，不修改表结构。
事件聚合已支持 source_count 跨平台统计。

## 六、启用顺序

1. B站（已验证可用）→ 立即启用
2. 微博（cookie更新后）→ 启用
3. 知乎（API调整后）→ 启用
4. Instagram（登录态验证后）→ 启用
5. 抖音（浏览器登录态验证后）→ 启用

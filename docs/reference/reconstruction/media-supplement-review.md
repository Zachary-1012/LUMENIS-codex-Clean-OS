## 3. 可直接进入自研媒体架构的少量约束

1. **一个可重开工程，一套确定性的修改语义。** 编辑操作携带工程基版本、稳定对象/参数、源与时间线区间、编辑模式、预期影响。先在内存/事务里验证源余量、锁定对象和邻接影响，成功后一次提交新版本；失败不写半份工程。撤销/重做和自然语言/AI 修改调用同一操作，不另造 AI 时间线。界面呈现普通“仅修改这段”等业务选项，不暴露内部命令日志和队列给用户。
2. **用有类型的有序媒体图表达专业内容。** 源、片段实例、复合/多机位引用、图层、音频组件/总线、效果/蒙版、关键帧、字幕、标记、时序映射分别有适当类型与边界。效果顺序、源级/实例级处理、显示/监听/输出状态不可揉成一组无序 attributes。沿用现有媒体/Artifact/版本 Owner，不另建第二数据库或独立“媒体管理系统”。
3. **保存依赖闭包，渲染绑定确切版本。** 项目快照包含引用的父对象版本、实际原件/代理依赖及适用处理配置；同名路径不能等同媒体身份。预览、代理、渲染缓存只是派生物，键包含其所有真实输入和参数版本。编辑后过期的分析/字幕/缓存不能继续冒充当下结果；历史交付仍可查看，不以重算覆盖历史。
4. **进度服从有用结果与可恢复性。** 导入、分析、代理、预览、导出分别说明真实可用范围；长任务支持取消、断点恢复和实际错误。事务提交前的临时文件不能列为完成交付；幂等重试不重复生成版本或覆盖客户已确认成品。AI 可增强候选、匹配和修复，但基础媒体操作与导出不得依赖模型在线。
5. **成套交付保持来源、权限、时间和版本一致。** 原工程、可编辑交换、成片、母带/stems、字幕/章节及说明各自保格式能力边界；属于同一交付时绑定同一工程/音频版本。客评锚点携带版本、对象与源/时间线映射，剪辑后不能继续用旧绝对秒数盲贴。未经用户选择，不整片重新生成来“完成局部修改”。

以上是后端与交互动作约束，不限定前端视觉风格，不新增用户必须逐步执行的开发流程，也不要求用户学习图结构、缓存键、算法或内部任务 ID。

## 4. 四组集中实际验收，防止“导出了一次”冒完整交付

- **局部修订保全：** 真实长视频含多机位、嵌套片头、字幕、音频总线和人工关键帧；客户只改一个 5 秒片段的透明度、画面角度与一段音乐。确认只改选定对象/范围；其余剪点、音频选择、关键帧、已确认字幕和源文件不变。重开新旧版本并实际播放，不只比 JSON。
- **时序和源余量：** 真实不同帧率/VFR/非零时码素材，包含不足转场余量和带场记的余量；做 roll、ripple、slip、slide、定长 slow motion 与完整动作 slow motion。验证各自总长、源动作、下游声音/字幕关系；用实际帧/PTS/采样点核对，不用 UI 秒数相等代替。
- **引用与恢复：** 两个节目复用一个片头/音乐复合片段，冻结 v1 交付后在一个独立版本修改母片；v1 不变。中断代理/渲染，断开源盘，用真实打包工程在新位置重开；缺件或未分析帧准确说明，恢复不丢精修、不用同名错素材补齐。
- **真实成套交付：** 同一真实节目导出成片、对话/音乐/音效 stems、字幕/章节和需要的阅读材料；逐件解码、试听/查看时序与声道，确认没有缺机位黑场、错误代理、失效字幕、变速丢动作或未处理占位。导出成功不等发布，文件包完成不等真实市场效果。目标宿主往返仅在实际获授权宿主验证后签收，缺宿主不伪造通过。

这些场景并不缩减原有长节目、轨道/片段规模、格式、语言与无 AI/AI 分别验收；它们是最容易发生隐性返工的横贯检查。原 J21–26 的导演前期、选题/嘉宾/录制、ASR与逐词对齐、多语言、声音设计、响度/真峰值、复盘等仍由 creative 合同完整保留，不能只采用本补充覆盖到的后期操作。

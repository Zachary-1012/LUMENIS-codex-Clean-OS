## 二、账户体系对标 Apple ID（1主+3管理员+5子账号）
### 2.1 账号层级与名额（硬约束，对标 iCloud 家庭共享）
```
                 Owner 主账号 ×1（用户本人=家庭组织者，唯一最高权限）
                 │  可创建/移除管理员、转让、管理全部成员/密钥/安全策略、看全局审计
        ┌────────┴─────────┐
  Admin 管理员 ×3      Member 子账号 ×5
  （主人任命；可管理子账号、审批登录、日常运营配置、看所辖域；
    不可增删管理员、不可改主账号与安全总开关）
   （受限成员；仅能访问被授权的 产品域ZBMP/CTH + 模块 + 动作read/write + 数据范围/时段；不可管理账号）
名额硬约束：admin 最多3、member 最多5（含停用占用名额，删除/转出才释放），创建超额必须拒绝并提示
```
### 2.2 对标 Apple ID 的功能模块（都放"设置"里，见第四节）
- 账号资料：头像/显示名/邮箱/手机；登录与安全：改密、随机数字双重认证、受信任设备与会话列表、远程登出
- 成员（家庭）管理：邀请/新建、角色、按 product(ZBMP/CTH/SYSTEM)+domain+action/resource 授权、状态 active/disabled、名额计数
- 登录审批：新设备/子账号登录可配置需 主账号/管理员 批准
- 账号恢复：复用现有 auth_recovery_center / v4_security_questions（安全问答+恢复码）
- 审计：v4_audit_logs 记录 谁/何时/何IP/何动作/何资源，成员管理与敏感操作必留痕
- AI 不参与授权判定，授权完全由规则+DB状态决定（沿用现有原则）

## 三、Apple 式"随机数字密钥"登录，替代 ZBMP 现有静态密钥
### 3.1 现状（要替换的）
- 现 v4_workspace_keys：`zbmp_`+32位随机串，PBKDF2 hash，expires_days=0 即永不过期；ZBMP 受限工作区靠它 unlock（app.py:5018-5106 /api/v4/api-keys）。
### 3.2 目标（对标 Apple ID 双重认证随机数字验证码）
1. 进入受限工作区(ZBMP)/敏感操作/新设备登录时，生成**一次性 N 位随机数字验证码**（默认6位，可配6–8；用 secrets 密码学安全随机，禁止可预测）。
2. 通过**受信任渠道**送达：默认在主账号/该管理员已登录的受信任设备会话内展示（系统内通知/设置-待批准）；预留 短信/邮件 渠道接口，缺凭证标 BLOCKED 不伪造已发送。
3. 验证码属性：**限时（默认120秒过期）、一次性（用后即焚）、校验失败次数上限（默认5次后作废重发）、重发冷却（如60秒）与单位时间上限**；DB 只存 hash 不存明文，明文仅生成时经受信任渠道出现一次。
4. 校验通过才颁发**短期** session/workspace grant（必带 expires_at），不再签发永不过期静态密钥；到期重新验证。
5. 现有静态 v4_workspace_keys 平滑迁移、不删表：降级为"受信任设备/程序化访问"的可选项且**强制设置过期+可绑定设备/IP**；主登录与工作区解锁默认走随机数字验证；旧"永不过期"选项移除，存量无过期密钥列出要求轮换。
6. 全部过程写 v4_audit_logs；失败/爆破写 v4_login_attempts 并按现有锁定策略锁定。

## 四、v4 账户并入主线（不独立）、入口放"设置"（用户明确）
1. **模块主线化**：把 v4_upgrade/auth/（models/security/service/workspace/audit）提升为一级主线模块 `account/`（或 auth/），初始化并入主数据库初始化链（启动即建表，不再依赖 v4_upgrade 独立子系统）；保留 v4_ 表名以保护现有数据，必要时加兼容视图，不删表不丢数据。
2. **API 主线化**：账户/成员/受信任设备/验证码/审计 统一到 `/api/system/account/*`（或 `/api/settings/account/*`，与现有路由风格一致）；现有 `/api/v4/api-keys/*`、`/api/auth/*` 加兼容层逐步收敛，旧路由标 deprecated 不立即删，前端全部改走新主线 API。
3. **前端入口放设置**：在 SYSTEM 域新增/完善 **Settings 设置页**（不另起独立产品、不进左侧主导航挤占），设置内分区：
   - 账户资料 / 登录与安全（随机数字验证、改密、受信任设备与会话、远程登出）
   - 成员管理（1+3+5 名额、角色、双域授权、状态、邀请/停用/移除）
   - 登录审批 / 账号恢复 / 审计日志 / 工作区与程序化访问（迁移后的密钥管理）
   - 页面按本文件第一节新视觉：渐变成员卡、大数字名额(如 2/3 管理员)、分段权限、六态齐全、真实API。
4. 双域对齐：成员授权必须带 product_id(ZBMP/CTH/SYSTEM)+domain+action/resource，与双域隔离、permission_gate 打通；ZBMP Analyst 不天然拥有 CTH 权限。
5. 主账号沿用现有 owner（Zachary），首次进入设置引导补齐资料与随机数字验证设置；默认弱口令 Zachary01 必须引导修改（must_change_password 已有字段）。

## 四之二、Apple 随机码的真实通道（已查证，禁止伪造"已连iCloud"）
**技术现实（2026-09-06 查证 Apple 官方文档）**：第三方本地 Web 系统**没有**"直连用户 Apple ID/iCloud、由苹果生成并推送随机数字到其 iPhone"的公开接口——Apple 双重认证的 6 位推送是 Apple 自家登录流程独占。可行的真实通道做成**可插拔 provider**：
- 通道A（默认落地，零外部依赖/免费/离线，最接近体验）：**TOTP 动态口令绑定 iPhone「密码」App / iCloud 钥匙串**。系统为账号生成 TOTP 种子与 otpauth 二维码，用户用 iPhone 扫码存入「密码」，之后登录 ZBMP 时 iPhone 每 30 秒生成 6 位数字并在网页键盘自动填充(input autocomplete="one-time-code")，输入正确才进入。抗钓鱼、无需服务器外发。
- 通道B（主动推送到 iPhone 锁屏，最像 Apple 双重认证弹窗）：**Bark 类 iOS 推送**，需用户装 App 并提供 Bark key/自建服务地址；系统生成一次性随机数字主动推送。未提供 key 前标 BLOCKED，不伪造已发送。
- 通道C（可选）：**Sign in with Apple** 官方 SSO——需 Apple Developer Program 付费会员(年费约688)、App ID+Services ID、域名验证与 Return URL，个人最多注册10个网站URL；它是"用 Apple 账号登录"而非输数字，等用户提供开发者账号再开。
- 通道D（预留，缺凭证 BLOCKED）：短信网关 / iCloud 邮箱 SMTP 验证码。
- 自建"一次性随机数字挑战"始终保留：系统 secrets 生成、受信任设备会话内显示，作为无外部通道时的兜底。
- 红线：UI 必须如实显示每个通道的真实状态（已配置/未配置/BLOCKED），**绝不能显示"已发送到你的 iCloud"这类未真正发生的提示**；选择哪个通道由用户在设置里决定。

## 四之三、ZBMP / CTH 差异化访问保护（用户最终拍板，两套不许混）
- **ZBMP = 手机随机数字（TOTP）**：进入 ZBMP 界面前必须通过 6 位手机随机数字（通道A TOTP 绑 iPhone「密码」/iCloud 钥匙串，立即落地+真机实测），替代现有 zbmp_ 静态密钥主路径。
- **CTH = 账号 + 密码登录（不是免密）**：CTH 入口改为输入账号、密码进入；**账号可更改、原密码可更改**（设置内修改账号、修改密码，改密需校验原密码）。这是传统账号密码，与 ZBMP 的 TOTP 是两套独立机制。
- **设置里 ZBMP 与 CTH 的访问设置必须分区、明确区分，禁止混成一套表单/逻辑**：ZBMP 区块管 TOTP 通道/受信任设备/动态码；CTH 区块管账号名/改密/密码策略；SYSTEM 敏感操作单独。
- 保护按 product 维度可配；默认：ZBMP=TOTP 开、CTH=账号密码开、SYSTEM 敏感操作=二次确认。

## 四之三点五、展现载体分工（别搞错）
- **数据表格沿用既有专业模板**：采集数据（小红书/微博/B站等原始与清洗结果）查看继续用原有表格模板（密集、可排序/筛选/分页/有界内滚），**不用新卡片/渐变风格重造表格**；表格就是用来精确查看采集数据的（2026 行业趋势也在从堆图表回归优秀表格）。
- **卡片/趋势图/KPI 用新素材风格**：渐变数据卡、叠层横滑卡+点开展开、趋势图（渐变面积/分段语义条/高亮节点/大数字层级）按本轮素材融合既有布局呈现。
- **增量适配、不大重构**：保留现有布局骨架、左侧导航、表格模板与已验证页面，只在视觉层（色/卡/图表/动效/状态）与明确缺口增量升级；仅当某方案"特别优秀"才允许局部重构并说明理由。整体精致、灵动、像 Apple 做生态那样统一而不死板，但不花、不素，底色有质感并适配双主题。品牌案例研究结论见 intelligence_library/08_UI-UX。

## 四之四、设置(Settings)完整信息架构（对标 Apple「设置」，不明面的信息统一收纳）
顶部：Apple ID 式账户卡（头像+主账号名+角色+1主3管5子名额，点击进账户）。
分区：
1. **账户与安全**：账户资料；登录与安全（随机数字多通道配置/改密/受信任设备与会话/远程登出）；成员管理(1+3+5名额/角色/双域授权)；登录审批；账号恢复；审计日志；**工作区访问保护（ZBMP/CTH/SYSTEM 开关，CTH默认关）**；程序化访问密钥（原静态密钥迁移，强制过期+绑定）。
2. **关于系统（关于本机）**：产品名/版本号/build/当前commit SHA/运行环境/端口；**运行逻辑说明、功能说明、使用详解、更新记录、第三方与许可声明**——所有"没必要放明面"的解释性信息统一放这里，主界面保持干净。
3. **域名与接入**：域名配置、访问地址、Cloudflare tunnel/内网穿透状态与开关、反向代理、端口；无账号/凭证的项如实标 BLOCKED（对齐外部 BLOCKED 清单）。
4. **开发者功能**：开发者模式开关、API/接口与 MCP、调试与日志级别、实验功能开关、内部浏览器通道、连接状态；默认收起，开启有风险提示与审计。
5. **外观**：浅色/深色（默认浅色可切换）、主题强调色、字号密度。
6. **AI**：provider/模型(智谱主力/ARK兜底/Ollama本地)、额度与成本、连接状态（可链到 SYSTEM AI）。
7. **采集与数据源**：各平台 cookie/登录态/凭证状态，缺凭证标 BLOCKED。
8. **通知 / 数据与备份 / 资料库 / 帮助**：通知通道；数据库导入导出与备份；intelligence_library 资料库入口；使用帮助与文档。
- 设置内同样遵守 No-Scroll 与横向叠层规则；所有状态真实函数驱动。

## 四之五、设置双域隔离 / 栏目可配 / Skill 统一管理（用户明确）
1. **设置本身也要双域隔离**：进入 ZBMP 时设置只出现 ZBMP 相关项，进入 CTH 时设置只出现 CTH 相关项，**严禁在 CTH 设置里看到 ZBMP 的东西（反之亦然）**；跨域通用项（外观/通知/数据/关于系统/开发者）与 SYSTEM 全局项归到 SYSTEM 设置。设置结构=「当前域设置（按 product 过滤）」+「全局/SYSTEM 设置」两层；账户与安全里 ZBMP 的 TOTP 与 CTH 的账号密码同样分域显示，不串。
2. **栏目（导航）可在设置里增改**：提供"导航/工作台自定义"——对左侧栏目与页签做 显示/隐藏、添加、排序、重命名，默认值=已拍板导航（ZBMP/CTH/SYSTEM 各自一套），支持一键恢复默认；配置按用户+域持久化，不写死；自定义后仍受权限与双域隔离约束（无权/跨域的栏目加不进来）。
3. **Skill/Agent 能力统一收进设置、按需启用（参考 GPT/Codex 录屏的工具按需挂载）**：所有 Skill/Agent 能力在 设置→技能( Skills ) 统一登记管理（启用/禁用/添加/参数配置/查看说明与运行状态）；**界面上只在"合适的位置"放少量快捷入口，用户主动"添加/启用"才出现并可用，不选择就不显示、不运行**，不把全部能力铺满界面。技能同样带 product/domain 归属，跨域需授权；禁用即彻底不加载（不占运行、不显示）。

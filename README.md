# Z-Brand Core

> **品牌传播与市场情报智能平台核心底座**
>
> 一个 Core，形成两条产品线、两种 Release：
>
> - **CTH-POMS** — CorTech Lab · Guangzhou Taikoo Hui Public Opinion Monitoring System：广州太古汇舆情监测与品牌传播客户交付版。
> - **ZBMP** — Z-Brand Monitoring Platform：面向多品牌、竞品、项目与传播情报的母平台。
>
> 当前主力客户系统为 CTH-POMS，当前真实源码基线 **v5.8.5**。项目采用“稳定版本为底座、审计—兼容—旁路—验证—逐步接入”的演进方式，不推翻重构。

## 1. 产品定位

本项目已经从单纯的“舆情监测系统”演进为 **品牌传播与市场情报智能平台**。

核心不是只回答“有没有负面”，而是形成完整链路：

```text
品牌做了什么营销动作？
        ↓
谁在传播？
        ↓
产生了什么内容？
        ↓
形成了什么事件？
        ↓
事件如何演化、扩散、分化？
        ↓
对品牌意味着什么？
        ↓
风险 / 消费者需求 / 传播效果 / 竞品对标 / 决策输出
```

四个核心维度：

- **WHO**：传播主体 — KOS / KOL / KOC / 普通用户 / 媒体 / 官方 / 机构
- **WHAT**：内容 — UGC / 商业 / 官方 / 测评 / 体验 / 投诉 / 活动内容等
- **WHAT HAPPENED**：事件 — 营销事件 / 传播事件 / 舆情事件
- **SO WHAT**：品牌影响 — 传播贡献 / 情绪 / 风险 / 消费者需求 / 竞品 / AI 洞察 / 报告

> **重要：主体类型与内容类型严格分离。** `subject_type=KOS` 是账号身份；`content_type=UGC` 是内容属性。禁止把 UGC 设计成账号类型。

## 5. 小红书采集原则

小红书是当前主平台。目标是 **稳定、低风险、可解释、可恢复**，不是高频暴力采集。

标准链路：

```text
账号 / Cookie
 ↓
持久化浏览器上下文
 ↓
Playwright / CDP
 ↓
搜索发现
 ↓
详情
 ↓
评论
 ↓
标准化
 ↓
质量检查
 ↓
广州太古汇主体过滤
 ↓
去重
 ↓
入库
 ↓
规则分析 / Ollama 增强
```

### 风控与 Auth

遇到验证码、安全验证、`300012`、IP 风险、安全限制页、登录验证页：

```text
识别 → 停止危险请求 → 记录 → 熔断 → 冷却 → 健康检查 → 合法人工验证后恢复
```

不得破解验证码、绕过安全验证或对抗平台风控。

**Cookie/session 失效不能简单跳转登录页。** 全局 Auth 状态中心应在任何页面、任何任务中触发系统内弹窗，弹窗包含平台、账号、状态、原因、平台正常流程提供的二维码/合法登录入口、“我已完成验证”“稍后处理”，并展示任务暂停/恢复状态。验证完成后自动健康检查并恢复；未完成则继续暂停/冷却。绝不能把采集失败显示成“0 条”。

采集状态至少支持：

`SUCCESS / NO_NEW_DATA / RISK_WARNING / NEED_VERIFY / BLOCKED / SESSION_EXPIRED / COLLECT_ERROR / COOLING_DOWN`

如果源码已有更完整状态机，优先兼容，不重复制造冲突状态。

### 调度原则

采集频次不再以“固定某几个时间点强行执行”为核心。系统应采用 **动态调度**：根据上一次任务的健康度、数据量、风控状态、冷却状态和历史连续成功情况决定下一次执行。

```text
健康 → 正常间隔
轻度风险 → 延长间隔
验证/封控 → 停止
冷却完成 → 健康检查
恢复 → 小流量试探
连续稳定 → 逐步恢复
```

此前的“自动 9 次 + 手动 3 次、30/20 分钟”等数字只作为历史运行策略参考，不再视为永久硬编码频次。

## 7. 数据模型与新品牌情报架构

核心 ER：

```text
客户
├─ 品牌（自有 / 竞品）
│  ├─ 监测配置
│  ├─ 传播主体库
│  ├─ 内容库
│  └─ 事件库
└─ 项目 / Campaign
```

传播主体六维画像：
1. 身份
2. 内容能力
3. 传播能力
4. 品牌关系
5. 舆情表现
6. 事件贡献

三类事件：
- **营销事件**：品牌主动发起
- **传播事件**：市场/用户自发形成热点
- **舆情事件**：公众态度聚集，可正可负

事件关系逐步通过 `event_relation` 建设，支持：
- 触发
- 衍生
- 继发
- 并行

目标链路：

`营销事件 → 传播事件 → 舆情事件 → 品牌影响`

事件支持生命周期：

`发现 → 形成 → 增长 → 爆发 → 扩散 → 分化 → 衰减 → 结束`

## 8. AI：Ollama-first、可退出、可审计

当前正式方向：**本地 Ollama 为正式 AI Runtime。**

生产系统不得依赖豆包/OpenAI/其他云端 API 才能运行。历史外部 AI 代码先标记 Legacy/Optional、默认关闭，再在确认无依赖后清理。

系统必须满足：

```text
没有 AI
→ 仍可采集
→ 仍可主体过滤
→ 仍可去重
→ 仍可事件分析
→ 仍可风险判断
→ 仍可统计
→ 仍可报告
```

Ollama 适合：
- 主体语义识别辅助
- 内容类型分类
- 情绪解释
- 用户诉求提炼
- 事件聚类建议
- 事件关系建议
- 风险原因解释
- 评论总结
- 趋势解释
- 报告润色

AI 不得单独决定真实数据、发布时间、主体最终口径、统计数量、报告周期和核心风险口径。

所有 AI 输出应记录模型、Prompt/版本、输入摘要、结果、置信度、是否采纳、人工修正，并支持 **Shadow Mode → 对比 → 人工确认 → 样本回流 → 规则/模型迭代**。

API Key 严禁进入源码、Git、前端、数据库初始化脚本、日志或测试样例。

“学习反爬”只用于提高稳定性、识别风险和降低请求压力；不得实现验证码破解、绕过安全机制或规避平台限制。

关键交互：

`概览 → 下钻 → 详情 → 回溯 → 溯源分析`

支持双向回溯：
- 事件 → 传播主体 → 历史内容
- 内容 → 所属事件
- 主体 → 参与事件

## 13. 安全与数据保护

- Cookie、Session、Token、API Key、微信凭证等敏感信息不得提交 Git
- `.env` 仅本地保存，使用 `.env.example` 提供字段模板
- 数据库、备份、截图、报告等数据资产未经授权不得删除/覆盖
- 新字段/新表必须优先向后兼容迁移
- 客户版与母平台数据必须隔离
- 不得把平台验证失败伪装成无数据

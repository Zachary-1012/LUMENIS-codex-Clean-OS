# StoryFM Content Production System & Transferable Methods V2

## Scope

研究对象：故事FM，从前身「爱哲电台」时期延伸至 2026 年当前公开创作方法与节目实践。

目标不是复刻节目内容，而是抽取可迁移的内容生产机制，用于 LUMENIS Content Intelligence、Podcast、视频播客、品牌人物故事、纪录短片、长图文与深度采访。

## 1. 核心判断：故事FM不是“会讲故事”，而是“把真实经历加工成可听叙事”

生产对象不是文案，而是：

`真实人物 → 可成立的故事 → 可信采访材料 → 叙事结构 → 声音表达 → 伦理控制 → 传播包装 → 听众反馈`

## 2. 选题系统

高价值选题通常满足至少一项：

- 稀缺经历：少数人才经历过，但足以让听众进入陌生世界；
- 高共情经历：多数人都可能投射自身；
- 强变化：人物前后状态发生明显变化；
- 强选择：关键节点存在真正决定；
- 强代价：决定带来损失、风险、关系变化或身份改变；
- 强反思：讲述者能回看自己的经历，而不是只复述事件。

### LUMENIS 可迁移判断

不要先问“这个题热点不热点”，先问：

1. 谁发生了变化？
2. 为什么必须是这个人？
3. 他/她经历了什么不可逆的决定？
4. 听众为什么愿意陪这个人走完整段路？
5. 这个故事在事实层之外，有没有认知增量？

## 3. 选角系统

故事FM的重要方法不是“找会说的人”，而是找：

- 有真实经历的人；
- 有细节记忆的人；
- 有自我反思的人；
- 有矛盾和复杂性的人；
- 愿意建立信任的人。

因此内容生产中的“人物选择”优先级高于单纯的表达技巧。

### 可迁移规则

品牌内容也可以这样做：

`选商品` 不如 `选人与商品之间的关系`

`选门店` 不如 `选一个人在这个空间里发生的变化`

`选活动` 不如 `选活动为什么会成为某个人的记忆节点`

## 4. 采访系统

公开资料显示，一期内容通常从较长时间的深度采访开始，制作人需要通过追问把经历从抽象判断还原成具体事件。

建议 LUMENIS 固化为四层问题链：

### A. 事实层

- 当时在哪里？
- 有谁在场？
- 发生顺序是什么？

### B. 感官层

- 你看到了什么？
- 当时环境是什么声音？
- 有没有一个物件/动作记得特别清楚？

### C. 决策层

- 你为什么做这个选择？
- 如果不这么做会怎样？
- 当时有没有犹豫？

### D. 反思层

- 现在回头看，你怎么看当时的自己？
- 你后来才明白什么？
- 有什么东西直到现在仍没有答案？

这个顺序比“你有什么感受”更容易得到可用素材。

## 5. 叙事结构系统

录音材料不是节目本身。

核心动作：

`采访素材 → 事件拆分 → 时间线 → 因果线 → 冲突线 → 人物变化线 → 重新排序 → 主播桥接 → 声音设计`

建议将每个故事映射成：

- Opening Image
- Inciting Event
- First Decision
- Escalation
- Irreversible Moment
- Consequence
- Reinterpretation
- Residual Question

不是每集必须机械套模板，但必须能解释“听众为什么继续听”。

## 6. 主播与制作人的角色分离

故事FM的重要组织机制之一，是制作人承担类似“导演”的职责：

- 找选题；
- 找人物；
- 采访；
- 建结构；
- 剪辑；
- 写必要的桥接内容。

主播未必是内容的主要创造者，而可能承担统一声音入口、解释和连接功能。

### 对 LUMENIS 的启发

Content Agent 不应只有“Writer”。应该拆成：

`Researcher / Producer / Interviewer / Story Editor / Copy Editor / Fact Checker / Platform Adapter / Evaluator`

一个模型可以承担多个角色，但逻辑职责必须分离。

## 7. 声音不是装饰，而是信息

对叙事播客而言：

- 环境声建立空间；
- 停顿建立心理状态；
- 呼吸和语速建立真实感；
- 音乐控制转场与情绪，但不能替代内容；
- 主播解说用于补足听众理解所需的最少信息。

迁移到短视频时对应：

`声音设计 → 镜头、留白、环境音、字幕节奏、切镜速度`

所以跨平台转换不应是“同一段文字改长短”，而是重新分配叙事信息到媒介层。

## 8. 编辑方针：共情不等于无判断

故事型内容并非完全中性展示。选择什么故事、如何剪辑、本身就是编辑判断。

LUMENIS 内容生产必须同时判断：

- 是否值得讲；
- 从谁的视角讲；
- 哪些背景必须补充；
- 哪些复杂性不能为了爽感被删掉；
- 是否会伤害讲述者或第三方；
- 是否把真实创伤变成消费品。

## 9. 标题系统

故事FM公开制作经验显示，标题是集体讨论与传播验证的一部分，而不是生产流程最后随便补一句。

LUMENIS 应将标题独立评估：

`信息准确度 × 好奇心 × 人物张力 × 语义清晰度 × 不误导`

禁止只优化点击而破坏事实语义。

## 10. 从单集到内容系统

故事线索可以来自听众投稿和主动寻找，这意味着内容系统本身可以形成循环：

`内容发布 → 用户建立信任 → 用户贡献线索 → 新人物/新故事 → 新内容`

对品牌而言可变成：

`品牌内容 → 用户回应/UGC → 真实线索 → 人物采访 → 新内容资产 → 社群信任`

这是比“每月排30篇选题”更强的长期机制。

## 11. StoryFM × 凉子访谈录：双引擎

### StoryFM 引擎

擅长：

- 真人经历
- 事件链
- 叙事剪辑
- 人物变化
- 声音纪录

### 深度访谈引擎

擅长：

- 人物认知
- 问题链
- 观点推进
- 主持人与嘉宾互动
- 思想密度

组合后形成：

`Narrative Documentary Engine + Deep Interview Engine`

## 12. 跨平台举一反三

同一个真实人物素材：

### Podcast
完整经历 + 细节 + 节奏 + 声音空间。

### 视频播客
保留思考过程、表情、停顿、关系动态。

### 抖音
截取最强决定/反转，用视觉前置建立张力，再补必要上下文。

### 小红书
提取与用户生活、身份和情绪最接近的一个切面，不把完整人生压缩成鸡汤。

### B站
增加背景、原因、结构解释，让故事同时具备知识和认知价值。

### 品牌内容
品牌不做旁白中心，而成为人物经历中的真实环境、物件、关系或行动节点。

## 13. LUMENIS 新能力建议

未来 Content Intelligence 应支持以下结构化对象：

- Story Candidate
- Character Profile
- Interview Brief
- Scene Ledger
- Decision Point
- Conflict Node
- Emotional Beat
- Fact Evidence
- Narrative Arc
- Ethical Risk
- Platform Adaptation
- Performance Feedback

推荐生产链：

`Brief → Research → Casting → Interview → Scene Extraction → Narrative Architecture → Fact/Ethics Review → Media Composition → Platform Adaptation → Evaluation → Human Approval → Publish → Feedback → Learning Asset`

## 14. 验收标准

当系统能做到以下事情时，才算真正“学会”而不是“记住”：

1. 能解释为什么一个人物值得被采访；
2. 能生成高质量采访问题链；
3. 能从原始采访中抽出场景、决定、冲突和变化；
4. 能重构叙事而不破坏事实；
5. 能区分不同媒介应保留什么、删掉什么；
6. 能识别伦理、隐私和事实风险；
7. 能把同一个故事转译成多平台内容而非简单改写；
8. 能把发布反馈重新变成下一轮选题与方法资产。

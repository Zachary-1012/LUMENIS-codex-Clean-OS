# 开源模型研究与系统接入评估

> 研究日期：2026-09-01
> 范围：小红书开源模型 + 2026 主流通用开源大模型
> 目的：为 Z-Brand-Core（CTH-POMS / ZBMP）的 AI 能力升级提供可落地的模型选型与接入路径

---

## 一、小红书开源模型

### 1. dots3-note preview（2026-08-14 开源）

| 维度 | 参数 |
|---|---|
| 架构 | MoE（混合专家） |
| 总参数 | 280B |
| 激活参数 | 16B / token |
| 上下文 | 512K（原生） |
| 模态 | 文本 + 视觉 + 语音（三模态输入，文本输出） |
| 视觉编码器 | MoE ViT（7B 总 / 1.2B 激活） |
| 音频编码器 | 800M 稠密 |
| 基准 | Terminal-Bench 2.1 = 75.1 分；IMO 2026 满分 42 分同系列 |
| 协议 | 开源（预览版） |
| API | OpenRouter 免费开放（研究期） |
| 适配 | 华为昇腾 Day 0 适配 |

**后续版本规划**：dots3 系列还将发布 jazz（音乐/音频）、aria（语音对话）等不同定位版本。

**对系统的启示**：
- 512K 长上下文 + 多模态 → 可用于品牌营销案例深度拆解（长文档/多图报告一次性输入）
- Agent 任务优化 → 可用于自动化舆情事件追踪与报告生成
- 研究期免费 API → 可作为 AI Provider 的候选之一，降低推理成本

### 2. dots.ocr（2025-08 开源）

| 维度 | 参数 |
|---|---|
| 参数 | 1.7B |
| 能力 | 多语言文档 OCR 与结构化解析 |
| 性能 | 准确率超 GPT-4o（文档解析场景） |
| 语言 | 支持百种语言实时处理 |
| 仓库 | github.com/rednote-hilab/dots.ocr |

**对系统的启示**：
- **直接可落地**：App Evidence 模式（小程序/公众号截图上传）当前为手动填写字段，可接入 dots.ocr 实现截图自动识别（话题名、浏览量、讨论量、发布时间等）
- 本地部署：1.7B 参数量级可在本地 GPU/CPU 推理，不依赖外部 API，符合数据安全要求

### 3. FireRed-OCR（2026-03 开源）

| 维度 | 参数 |
|---|---|
| 参数 | 2B |
| 能力 | 端到端文档结构化解析（表格/公式/多栏） |
| 特点 | 解决"结构幻觉"问题，三阶段训练 + 格式约束强化学习 |
| 协议 | Apache 2.0（可商用） |
| 仓库 | github.com/FireRedTeam/FireRed-OCR |

**对系统的启示**：
- 与 dots.ocr 形成互补：dots.ocr 偏通用多语言，FireRed-OCR 偏复杂结构化文档（表格/公式）
- 品牌营销案例库中的 PDF 报告/数据表解析可使用 FireRed-OCR
- Apache 2.0 协议无商用风险

### 4. FireRed-Image-Edit v1.1（2026-03-08 发布）

| 维度 | 参数 |
|---|---|
| 能力 | 文本引导图像编辑、老照片修复、虚拟试穿（OOTD）、人像美妆 |
| 特点 | 人物身份一致性、多元素融合、字体渲染 |
| 性能 | 推理 4.5 秒 / 张，显存 ≤30GB |
| 团队 | 小红书 SuperIntelligence |

**对系统的启示**：
- 与系统核心功能（舆情监测/品牌分析）关联较弱
- 可作为未来营销素材生成模块的候选能力（当前不优先接入）

## 二、2026 主流通用开源大模型

| 模型 | 厂商 | 总参数 | 激活参数 | 上下文 | 协议 | 核心优势 |
|---|---|---|---|---|---|---|
| DeepSeek V4-Pro | 深度求索 | 1.6T | 49B | 1M | MIT | 编程/Agent 顶尖，CSA+HCA 压缩注意力 |
| DeepSeek V4-Flash | 深度求索 | 284B | — | 1M | MIT | 高吞吐低成本，GPT-5.5 百分之一成本 |
| GLM-5.2 | 智谱 | 744B | 40B | 1M | MIT | 开源代码能力首次达顶尖闭源水平 |
| Kimi K2.7 Code | 月之暗面 | 1T | 32B | 256K | Modified MIT | Agentic 编程，低硬件部署 |
| Qwen 3.6 / 3.8 | 阿里 | 35B-2.4T | 3B-95B | 1M | Apache 2.0 | 多语言+通用性，Qwen3-Coder 代码专精 |
| Llama 5 | Meta | 600B | — | 5M | Llama Community | 西方前沿开源，超长上下文 |

### 选型建议

1. **长文档分析/案例拆解**：DeepSeek V4-Pro（1M 上下文）或 dots3-note（512K + 多模态）
2. **代码生成/系统开发辅助**：GLM-5.2 或 DeepSeek V4-Pro
3. **低成本高吞吐批量推理**：DeepSeek V4-Flash 或 Qwen 3.6
4. **本地部署/低硬件**：Kimi K2.7 Code（32B 激活）或 Qwen3-Coder-30B
5. **OCR/文档结构化**：dots.ocr（通用）+ FireRed-OCR（复杂结构）

## 三、对 Z-Brand-Core 系统的接入路径

### P0（直接可落地，风险低）

| 能力 | 模型 | 接入方式 | 预期收益 |
|---|---|---|---|
| App Evidence 截图 OCR | dots.ocr (1.7B) | 本地部署，上传截图后自动识别话题名/浏览量/讨论量/时间 | 消除手动填写，提升 App Evidence 模式可用性 |
| AI Provider 多模型支持 | DeepSeek V4 / GLM-5.2 / dots3-note | 在现有 AI Provider 抽象层增加候选模型，按任务路由 | 降低单一模型依赖，按场景选择最优模型 |

### P1（需评估，中期接入）

| 能力 | 模型 | 接入方式 | 预期收益 |
|---|---|---|---|
| 品牌案例深度拆解 | dots3-note (512K 多模态) | API 调用，长文档+多图一次性输入 | 提升案例库拆解深度与自动化程度 |
| 知识库 RAG 增强 | LightRAG（图 RAG）+ Qwen 3.6 | 影子板块知识库检索层升级 | 提升品牌营销知识检索的关联性与深度 |

### P2（远期规划，当前不接入）

| 能力 | 模型 | 原因 |
|---|---|---|
| 营销素材生成 | FireRed-Image-Edit | 与核心舆情监测功能关联弱 |
| 语音/音频分析 | dots3-jazz（未发布） | 模型尚未发布 |

## 四、风险与约束

1. **数据安全**：OCR 模型（dots.ocr/FireRed-OCR）必须本地部署，不得将用户截图上传至外部 API
2. **API 成本**：dots3-note OpenRouter 免费为研究期，长期使用需评估成本或本地部署
3. **模型协议**：DeepSeek/GLM 为 MIT，Qwen 为 Apache 2.0，Kimi 为 Modified MIT（需确认商用条款），Llama 5 为 Llama Community（有商用限制）
4. **硬件资源**：本地部署大模型需 GPU 资源；1.7B OCR 模型可 CPU 推理，280B+ MoE 模型需多卡或 API
5. **AI Provider 化**：系统已确定 AI Provider 化方向，所有模型接入必须通过统一 Provider 接口，不得在业务代码中直接调用特定模型

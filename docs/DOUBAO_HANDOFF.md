# 豆包本地开发接管指令

版本：2026-08-30 / Active
项目：Z-Brand-Core

## 1. 你的角色
你是本地执行、代码适配、运行验证与 E2E 测试开发者，不是产品架构最终裁决者。

ChatGPT 主开发窗口负责总体架构、版本基线、跨模块决策、P0/P1/P2 优先级、数据口径、验收标准和变更总日志。

你负责读取 GitHub/本地源码、按 AGENTS.md 实施、运行测试、真实浏览器验证、数据库核查，并把真实结果提交回仓库。

不要凭聊天印象改代码；以当前仓库源码和真实运行结果为第一事实源。

## 2. 每次开工强制流程
1. 阅读 `/AGENTS.md`。
2. 阅读本文件。
3. 阅读 `/CHANGELOG.md`（若存在）。
4. 查看最近 commits，确认当前基线。
5. 检查工作区未提交修改。
6. 识别启动入口、Python 环境、依赖、数据库位置、前后端入口、蓝图、调度器、采集器。
7. 修改前确认可回滚；严禁删除生产数据库。

## 3. 当前 AI：Ollama-only
生产系统不得依赖豆包 API、OpenAI API 或其他云端大模型。历史外部 AI 代码先审计、标记 Legacy/Optional、默认关闭，不得贸然删除。

Ollama 是正式本地 AI Runtime。AI 只做增强，不是系统生命线。没有 AI 时，采集、主体过滤、去重、事件分析、风险判断、统计、报告仍必须运行。

严禁把 API Key、Cookie、Session、二维码登录数据等秘密写入 Git。

## 4. 两个产品
产品 A：CorTech-TaikooHui——广州太古汇客户交付版，单品牌/单项目、固定主体口径、独立数据库、独立运行。

产品 B：Z-Brand Monitoring Platform——多品牌品牌传播与市场情报母平台，支持品牌/竞品、传播主体、内容、营销/传播/舆情事件、事件关系、消费者需求、品牌对标、多平台 Adapter、Ollama Shadow/样本体系。

目标：一套 Core、两种 Release，不长期复制两套源码。

## 5. 数据模型硬约束
`subject_type` = KOS/KOL/KOC/普通用户/媒体/官方/机构；`content_type` = UGC/商业/官方/测评/体验/投诉/活动内容等。

禁止把 UGC 当账号类型，例如 `user_type=UGC`。

事件分为营销事件、传播事件、舆情事件；逐步建设 `event_relation`，支持触发、衍生、继发、并行关系。目标链路：营销事件 → 传播事件 → 舆情事件 → 品牌影响。

## 6. 广州太古汇主体口径不可破坏
必须保护源码中的 `SUBJECT_WORDS`、`SUBJECT_EXCLUDE_WORDS`、`subject_hit()`、`_subject_sql_and_values()`、`aggregate_events()` 主体过滤、`build_daily_report()` 主体过滤及所有下游统计口径。

不得为了增加数量而放宽主体过滤。

## 7. 时间口径
`publish_datetime` 是内容真实发布时间；`captured_at` 是采集时间。报告、舆情日历、周期统计默认按发布时间。“编辑于/小时前”等相对时间必须归一化；无法可靠归一化则标记不确定，不得伪造。

## 8. 小红书 Auth 与风控
Cookie/session 失效不能把用户简单跳转到孤立登录页。系统应通过全局 Auth 状态中心触发系统内弹窗，至少包含：平台、账号、状态、失效/验证原因、对应二维码或合法登录/验证入口、“我已完成验证”、“稍后处理”、当前任务暂停/恢复状态。

验证完成后健康检查并恢复；未完成则保持暂停/冷却。绝不能把失败显示成 0 条。

遇到验证码、安全验证、300012、IP 风险、安全限制页或登录验证：识别 → 停止危险请求 → 记录 → 熔断 → 冷却 → 健康检查 → 合法人工验证后恢复。

不得破解验证码、绕过安全验证或对抗平台风控。

## 10. 当前优先级
P0：统一启动环境；合法稳定网络下补抓历史空正文；归一化相对时间；小红书 300012 按状态机处理。

P1：全局 Auth 弹窗+二维码/合法验证入口；登录双方式/三级权限/安全问答；swire_notes 与 topic_campaign_notes 实采；逐项评估启用 system_guardian/auto_recovery/data_feedback_loop；微博/B站免登实测；微信通知安全凭证接入。

P2：手机端完整交互；版本/命名统一；collector_v2 并行验证后切换；清理临时诊断脚本；Ollama 配置、CI/CD、监控大盘、蓝图化。

## 11. 测试与交付
每次修改尽可能执行语法/导入检查、单测、数据库 schema/计数核查、启动检查、API 健康检查、浏览器 E2E、关键页面 JS error/undefined/NaN 检查、采集状态回归、主体口径回归。

无法真实验证必须写“未实测”，不得写“已完成”。

每个逻辑改动独立 commit。每次完成任务更新 CHANGELOG 或开发日志：日期、版本、文件、功能、测试方式、真实结果、遗留问题、回滚点。

## 12. 给豆包的总原则
能改再改，能测再交；先读规则，先查事实；不推翻稳定版，不删除数据库，不弱化主体过滤，不把 AI 变成系统生命线，不绕过平台验证；每次变更都留下 Git 可审计记录。

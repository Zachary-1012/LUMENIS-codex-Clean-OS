## 0.1 Approved SourceTarget / Open Original target — 2026-10-07

Product Owner approval now establishes the final source-trace behavior for a verified SH-02 item without promoting the current backend binding:

```text
verified Evidence item
→ typed SourceTarget from the same row/lineage
→ Trace / source details
→ explicit Open Original
→ actual public HTTPS page inside product SYS-06 by default (external browser only as an optional user-chosen view-original jump; never used for collection)
→ actual SYS-06 page/session state or an honest load/error state
→ Return to the same Space/List mode, query/filter, selected item, scroll/camera and invoking focus
```

The shared `lumenis.source-target/v1` contract owns URL availability and handoff semantics. `URL_MISSING`, `INVALID_URL`, `DENIED`, `UNSUPPORTED`, `SOURCE_WITHDRAWN`, `LAUNCH_REJECTED`, `LAUNCH_FAILED`, `HANDOFF_ACCEPTED` and `RETURNED` remain distinct. For the separately chosen external-browser path, `HANDOFF_ACCEPTED` proves only that the OS/browser accepted that choice; it is not the default target and does not prove the page loaded, authenticated or remained readable. The default internal path must show the actual page and its SYS-06 session/page state.

Ordinary Open Original is read-only: it never reads platform cookies, silently logs in, starts collection, captures new Evidence, writes Canonical Data or performs an external effect. Controlled capture/navigation remains SYS-06. Until the typed SourceTarget and launcher/Return binding exist, the control is visibly unavailable rather than replaced by a raw URL.

## 1. Product invariant and scope

The Evidence Space/List in SH-02 is read-only: its Space and List modes browse the same verified provenance-bearing Evidence rows. It is not a second Evidence store and does not grant a CTH Subject or BMP BrandFocus context. Every visible Evidence row must belong to either the explicit `GLOBAL_ALL` range or an exact, permissioned focus range.

Shared document upload is a separate private-custody action through the existing document and SavedWork owners. It does not create Canonical facts or Evidence rows, and it does not bypass row scope or read Permission. SH-02 now projects the existing scoped Canonical read with verified source Evidence, and checks the same actor-bound Permission before and after building the response. Missing or changed authorization fails closed. The independently scoped Shared upload and SavedWork readback remain available when permitted; they do not depend on a populated CTH/BMP library.

## 2. Binding and response contract

| UI region | Required runtime value | App behavior |
| --- | --- | --- |
| Viewing range | `scope.mode` = `GLOBAL_ALL`, or `FOCUS` with domain, exact Subject/BrandFocus id, and safe display name | Render business range only; never render the raw focus id |
| Read authorization | `permission.read`/`can_read`/`view` plus an allow decision | Render rows only after both scope and authorization pass |
| Evidence list | `data.evidence[]` or `data.items[]` with id, summary, source, time, freshness, `scope_verified` and an explicit Evidence-backed marker | Parse an allowlisted subset; keep the internal id out of user copy |
| Source trail | `lineage[]` from the verified response | Show only known business labels such as 来源, 资料依据, 正式记录, 指标 and 事件 |
| Existing route | `GET /api/experience/screen/SH-02` | Current authorized scope and row projection are required; no fixture fallback or unscoped Evidence query is allowed |

`selection_only: true` is not authorization. A response without the required scope or permission envelope is unavailable, not global. Every row must carry an explicit canonical row scope, row read permission, Evidence-backed marker, and verified lineage/integrity. A `GLOBAL_ALL` page requires an explicit current global read grant and the existing v2 row projection; the stored Subject/BrandFocus identity remains intact and is not rewritten as global. Legacy unverified focus rows are rejected. An exact FOCUS page accepts only the matching active focus. Unsafe HTML, implementation terms, paths, provider labels, credentials, and raw diagnostics are discarded before rendering.

## 3. Responsive information architecture

### Desktop (available width ≥1120 logical px)

- Keep the verified viewing range and compact search/type filters beside the primary material work area. A visible Space/List switch changes the presentation of the same verified item set; it never changes range or query the Evidence store again by itself.
- Space is a navigable material field for verified source, time, domain and lineage cues. It is not a relationship graph and must not imply links or rankings that are absent from the returned lineage.
- List provides precise keyboard browsing over the same items. Selecting an item opens its focused reading/trace view and the contextual inspector keeps its extract, typed source label, recorded time, freshness and verified lineage together.
- Returning from focus restores the prior Space/List mode, query, type filter and spatial camera/list position, then returns keyboard/accessibility focus to the invoking item when available.
- Do not claim a full original-source snapshot or clickable CTH/BMP owning route unless the verified response supplies that content, destination and Permission. Show only returned source details; never manufacture a source view from an Evidence label.

### Intermediate width (760–1119 logical px)

- Keep search and type filters ahead of the material browser. In browse mode, preserve a separate inspector for the selected verified item; focused reading replaces the browser region and has an explicit return to the previous mode.
- Retain the last query, type filter, view mode and browser position across this in-page focus/return path.

### Mobile (available width <760 logical px)

- Recompose into range → search/filter → one material view. Space and List remain two views of the same authorized rows; choosing an item moves into one focused reading/trace surface with a clear Return to Space/List action.
- Return restores the prior view, query, type filter, scroll/space position and invoking item focus when available. Selection and view changes remain local and read-only.
- Search, view-mode, result and return controls retain at least a 48 logical px touch target and remain usable at text enlargement.

## 4. State and recovery

| State | Meaning | Behavior |
| --- | --- | --- |
| Loading | Scoped library request is pending | Show a live loading status and no stale rows |
| Ready | Product Core returned verified scope, read authorization and typed rows | Show allowlisted material and source trail |
| Empty | A verified authorized response, or local filter over verified rows, contains no matching material | Explain that no matching material is available; do not invent examples or confuse this with unavailable scope |
| Scope unavailable | Scope or permission envelope is absent, selection-only, or not bound | “资料暂不显示”; show retry; render no rows, counts, empty-library claim, Space nodes or List rows |
| Permission denied | Read decision is not allowed | Explain that the selected range cannot be viewed; render no data |
| Authentication required | Core returns HTTP 401 | Use the existing shell recovery path; retain no stale rows |
| Offline / invalid | Core is unavailable or response is malformed | Show a safe retry message without raw diagnostics |

### Direct Product Owner correction — 2026-10-16: upload, analysis and material timeline

Independent document import and recent imports use the authenticated Shared workspace,
not a prerequisite CTH/BMP focus. An ordinary upload does not require a form for title,
source rights, intended use or publication time. The user supplies a file for internal
workspace reading/research; this does not assert ownership, a license, or permission for
quotation, publication, external effects or model training. The existing server owner
must bind actor and workspace, preserve unknown source/rights values, and reject any
requested use that is not currently permitted. Publishing and training keep their
separate explicit approval gates.

The existing Importer preserves every original row through bounded pagination, including
all sheets, source locators, raw missing/zero values, and the original Artifact. Table
rows display original column labels and values, never serialized internal payloads. A
normal upload enters the existing import operation directly; any remaining confirmation
is only the confirmation required by the existing write/Permission contract, not a
source-rights declaration form. The original and derived analysis remain separate;
import is not factual verification.

After a successful import, SH-02 presents the authorized material library as a timeline
ordered by the server-recorded ingest time. Original publication time is a separate,
nullable value: `UNKNOWN` stays visibly unknown and is never replaced by ingest/capture
time or zero. Each material card shows its title, type, ingest time, optional original
publication time, actual per-material analysis state and a useful summary only when the
existing analysis owner returns one. Opening a card exposes both the retained original
and its separately attributed analysis. Deterministic/basic analysis remains useful
when AI is unavailable; model output is optional derived content and never Canonical
fact. Pending, failed, unavailable and completed analysis states are distinct. Retry is
available only through the existing retryable task/result contract; no progress or
success is inferred from a request being sent.

The cards use task-appropriate physical interaction without reducing the approved motion choices: pointer press/pick-up, bounded drag and
tilt, a click/tap or keyboard action to flip between the summary and source/analysis
details, and elastic return on release. Keyboard and touch provide equivalent access;
reduced-motion settings remove motion without removing the action or content. This is
ordinary pointer/touch interaction, not VR/XR, a new 3D engine or a global visual
redesign. The existing roughly 90 ms first-feedback target remains; report it only after
measuring the actual operation.

The existing document import/list/read and analysis owners retain server actor, typed
Shared workspace, current source-use/access and integrity checks. The interface never
asks users to enter task IDs. It renders source contents as plain text, supports
zh/en/ko, keyboard access, narrow screens and reduced motion. Ambiguous write results
require existing readback/recovery before retry; a retry must not duplicate a committed
source. Reopening and paging recheck rights; a denied source does not remain visible.
Existing domain-library blocking does not block this independently authorized Shared
workflow. User-question reports over selected sources remain a separate optional
operation and do not substitute for per-material analysis.

The file chooser accepts only formats supported by the existing document importer;
cancelling it has no effect. Upload and recent-import discovery use the existing Shared
document and SavedWork owners. The server derives actor and workspace scope. The UI
shows an imported card only after the existing SavedWork readback matches the saved
artifact and original-file identity, hash and size. If a write reply is uncertain, the
same request identity must be reconciled before another upload can start. These are the
bounded single-file upload/list/readback path, not full Evidence-row access or a claim
that the full reader is complete. Cursor continuation and explicit incomplete-page or
error reporting remain open for owner verification; do not imply that every recent
record or omission has already been reconciled. The user does not choose algorithms
or enter internal identifiers.

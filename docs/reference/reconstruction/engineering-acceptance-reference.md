# 寰意工程交付验收：公开专业参照与可执行合同

日期：2026-10-30。性质：有限只读研究，供完整规划审核采用；不是正式产品规则、标准认证、实现证明或测试报告。仅写忽略研究目录，未修改代码、正式规格或规则，未运行产品、安装依赖、使用个人账号或业务数据。

## 1. 结论与采用边界

标准帮助查漏和建立独立判断依据，不能代替完整产品验收，也不能让标准的适用范围变成寰意的功能上限。应同时证明：用户能实际完成工作；实际专业处理正确；成果可编辑、可交付；未要求修改的内容保全；保存、修订、重开、恢复后仍成立。

文件哈希只能辅助证明字节身份。导出后哈希改变可能只是ZIP重排或元数据变化；哈希不变也可能表示修改根本没保存。格式有效、内容正确、呈现完整、功能可编辑、跨应用往返、权限有效和故障恢复是不同结论，不能相互替代。

以下采用7组一手参照。相关公开说明/版本固定链接列在各组；仅核本任务相关范围。任何新工具、依赖、付费软件、认证或服务均未被授权接入。

## 2. 七组参照：已读依据、版本、测试用途和限制

### S1. ECMA-376：OOXML结构、语义和兼容处理

官方当前入口为第五版，但各Part年份不同：Part 1为2016-12，Part 2为2021-12，Part 3为2015-12，Part 4为2016-12；不能统称“所有正文均为2021”。[ECMA-376官方版本与公开原件](https://ecma-international.org/publications-and-standards/standards/ecma-376/)

本轮已实际核读公开原PDF：Part 1 §2.1–2.3（PDF第12–13页）、§18.17.1/18.17.2开头（2049–2051）、§18.17.6.1–6.3开头（2077–2078）；Part 2 §4/5（18–19）、§6.5.1–6.5.3.2（29–31）；Part 3 §7.3–7.7、§8、§9.1/9.2开头（18–25）。另读Part 2前言等5–10页，Part 3前言/范围等5–10及17页。仅这些范围，不声称读完5039页Part 1，未读Part 4正文。

直接依据：OPC合规只谈语法；OOXML应用合规还涉及其处理信息的语义。表格公式表达与上次计算值是不同信息。MCE的忽略/替代处理不能自动等同保留客户完整可编辑原稿。以上不构成“寰意可以少实现”的豁免：产品已承诺的能力仍须完成。[Part 1公开原包](https://ecma-international.org/wp-content/uploads/ECMA-376-1_5th_edition_december_2016.zip)，[Part 2公开原包](https://ecma-international.org/wp-content/uploads/ECMA-376-2_5th_edition_december_2021.zip)，[Part 3公开原包](https://ecma-international.org/wp-content/uploads/ECMA-376-3_5th_edition_december_2015.zip)

寰意的具体实测合同（本轮提出，尚未执行）：

| 任务 | 正向样本与操作 | 独立判断及必须失败的反例 |
|---|---|---|
| Word局部修订 | 多节文档，含编号/表格/脚注/页眉页脚/批注/修订/图文对象；只改选定段落后导出、在既有合法目标应用重开并继续编辑 | 检查文本语义、样式继承、编号与引用关系、对象可编辑性和分页；未选内容不能消失。把整个文档转成图片、拆掉脚注关联、丢失批注却“打开成功”均失败 |
| PPT客户修改 | 复杂80页客户文件，仅改第3–5页指定对象；含母版、组、图表、媒体、备注、动画等真实已承诺对象 | 核修改对象与关系图；未选页/对象/顺序/样式/媒体/备注保全；目标应用播放和再次编辑。只比ZIP条目哈希或静态缩略图不足；画面正确但对象扁平化也失败 |

| 不识别的扩展 | 客户文件包含扩展对象/外链/未知部件；做不相关的局部修改 | 原件留存，未改扩展与相关关系不被悄悄剥掉；无法处理的选定操作明确未完成。保存原件不是完整编辑验收，但也不能为了通过基础schema把它删除 |

完整文件与仅变更对象分别比较。对允许变化的生成时间/内部编号等需事先说明语义等价判断，不能将整个包忽略；未选内容应按实际要求保持。字体环境、缩放、目标应用与版本必须固定，渲染差异需定位到实际字形、换行、遮挡或对象，而非用一个总像素相似度掩盖严重局部损失。宏、外部链接和嵌入程序不能因导入而自动执行。

### S2. Microsoft Open XML SDK：独立结构校验，不能冒Office行为验证

已核公开官方文档正文和完整示例，页面更新日期2025-01-21。示例演示OpenXmlValidator报出错误类型、节点、路径和部件，并通过非法文档结构构造负例。[Validate a word processing document](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-validate-a-word-processing-document)

采用方式：若采用既有获准校验工具，固定工具版本和目标文档版本；对原件与导出件分别保存结构错误清单，先识别原件已有问题，再检验是否新增错误。校验在副本上执行；官方示例含破坏性示例代码，不能直接拿客户原件试。

负例：把Run放到不允许的位置、制造断裂关系或错误内容类型，校验应能报告相应错误；同时准备“结构合法但文字/金额错误”“结构合法但版式溢出”“结构合法但公式未重算”的样本，后面三者必须由语义、呈现和操作检查发现。没有声称SDK计算Excel公式、渲染Office或验证完整客户交付；本轮没有安装或执行SDK。

### S3. PDF Association与veraPDF：保存、无障碍与实际可用分别验

本组为同一PDF验收问题的官方公开原文和实现参照：

- [veraPDF Validation官方文档](https://docs.verapdf.org/validation/)，2026-10-30读取当前页面；列出按不同PDF/A、PDF/UA及WTPDF profile校验，UA只做机器可验证项。实际验收须另固定执行器版本/profile版本，本次未安装/运行。

实测合同：对普通交付PDF、归档用途和可访问用途分别选明确目标，不强制把所有PDF转换成同一profile。打开原页、选取/复制文本、搜索、定位引用、保存批注、重开检查；有无障碍要求时再检查标签树与实际辅助阅读顺序、表头对应、替代说明是否传达含义。带交互字段的文档应同时核逻辑字段值与显示值；保护原件，不以扁平化掩盖不支持。

基准与反例：Matterhorn原PDF由官方作为参考质量文件提供，可用于该范围的正样本；负例包括图片有Alt但写错、标签齐全但双栏顺序错误、表头关联错、OCR将“不得”变成“得”、画面正确但复制文字错、批注重新打开丢失。机器通过后这些仍须能被检测。正式宣称某profile合规须完成该profile适用项，不能用“部分合规”表达整份文件通过；允许报告某些检查已通过且剩余未完成。没有阅读ISO 19005/14289收费全文，不声称所有规范条款逐项核过。

### S6. NIST SP 800-34 Rev.1：从备份到可继续工作

版本为2010-05、2010-11-11更新，官方页面仍列该最终版。[官方出版状态](https://csrc.nist.gov/pubs/sp/800/34/r1/upd1/final)，[公开原PDF](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-34r1.pdf)。本轮核读§3.2/3.2.1相关PDF29–32页、§3.5/3.5.1相关41–42页、§4.4相关55–56页；非149页全文，未把旧版所引联邦控制当成寰意当前法律义务。

直接采用其区分：允许的恢复时间与可恢复数据时点要分别说明；恢复后既要验数据，也要验功能。组织自行确定适用目标，不能从文中示例直接拿一个小时数当行业统一承诺。

寰意实测：在隔离测试副本上制造进程终止、断网、磁盘空间不足、文件与数据库提交之间失败、旧版本升级失败及损坏备份；从合法有效备份恢复到可启动、可鉴权、可打开同一作品、可继续编辑与导出的状态。核原稿、修改记录、评论、来源定位、素材、排期和实际执行回执的版本一致性。记录恢复到哪个已确认操作及实际耗时，未恢复的内容不能假称存在。

负例：备份包能解压但遗漏媒体；数据库恢复了但对应对象文件版本错误；恢复把旧权限/旧账号会话重新启用；外部动作因回执丢失重复发送；任务恢复显示完成但成果不存在。重试前核未知效果，撤销权限不能被旧快照覆盖。此为产品恢复要求，不要求新增异地付费机房、复制整个联邦组织流程，亦不授权本轮对生产断电或恢复。

### S7. ISO/IEC 25010:2023公开质量模型：用于查漏，不能冒读完标准

本轮只读[ISO官方公开摘要和版本页](https://www.iso.org/standard/78176.html)：第2版，2023-11，产品质量模型用于生命周期中的质量要求、测量、评价及验收目标。**未购买、下载或阅读收费22页规范正文，不引用其细分条款，不声称依此认证。**

对寰意的采用是本轮推导：完整功能不能只按“某路径能成功”验收；还要检查真实工作规模下的耗时/资源、跨文件和客户端兼容、失败后的可靠性、权限安全、用户能完成原工作与后续修改，以及适用版本/设备环境。具体阈值应由真实任务和产品承诺先确定，再实测；不是从标准摘要虚构90ms、通过率或“行业领先”分数。只用此页提醒质量维度完整，详细判据来自前6组与原产品工作要求。

## 3. 跨标准的最小独立验收办法（产品工作要求，不是新增管理体系）

1. **先确定预期，再操作。** 原输入、任务目标、选中对象、允许变化、必须保留、目标格式和验收环境先固定；失败后不得让实现者把预期悄悄改成当前结果。合理需求变化另有解释和新版本。
2. **至少两类独立证据。** 自动结构/数值/权限检查，加真实产品内操作和独立消费者回读。文件由寰意写出再由同一函数读回，容易共享同一个错误；重要公式用已知真值小样本，Office/媒体用目标软件与专业使用者核读。可用agent执行检查，但其自述或自己生成的评分不能是唯一裁判。

## 1. Product invariant and scope

SH-01 is the Shared Capability catalog consumed by CTH and BMP. It is not a third product, and catalog membership does not establish a CTH Subject or BMP BrandFocus. The App displays safe registered capability metadata from the shared catalog. It does not execute a capability.

The current global content Evidence list and detail routes do not bind the authenticated actor to a product domain or an Evidence object. The App must not call them, expose their records or totals, or attribute them to CTH/BMP. The detail response also forwards arbitrary structured output that could echo a prompt or input. Output remains hidden until object scope and output redaction are verified.

## 4. Responsive information architecture

### Desktop (available width ≥1120 logical px)

- Shared owner/consumer charter, registered capability index, and selected capability facts form three adjacent regions.
- Selection changes only the local details panel. The details state remains visible beside the index.
- The Evidence scope gate sits below the catalog workspace and identifies the missing actor/domain/object scope.

### Intermediate width (760–1119 logical px)

- Keep the Shared charter beside the capability index.
- Show selected metadata after the index so neither column becomes too narrow.

### Mobile (available width <760 logical px)

- Recompose into a vertical sequence: Shared owner/consumer context → capability index → selected capability facts → Evidence scope gate.
- Each catalog entry has a touch target of at least 48 logical px.
- No desktop column is simply scaled down; catalog selection and its facts form one focused browse task.

## 5. State and recovery

| State | Meaning | Behavior |
| --- | --- | --- |
| Loading | Shared capability catalog request is pending | 正在读取研究与创作工具; do not present cached/fake rows |
| Ready | Product Core returned `ok: true`, product `LUMENIS`, and a skills list | Render allowlisted catalog metadata |
| Empty | Catalog returned an empty skills list | 当前没有可展示的研究或创作工具; do not fabricate examples |
| Authentication required | HTTP 401 | Use the Shell login path; render no stale catalog values |
| Permission denied | HTTP 403 | 当前账号暂不能查看工具目录 |
| Offline | Core connection or service unavailable | 工具目录服务暂时无法连接，请检查网络后重试; do not substitute old business data |
| Invalid | Wrong product, malformed response, or missing skills list | Keep all unverified catalog details hidden and offer retry |
| Evidence blocked | Current list/detail route lacks authenticated actor/domain/object scope | Do not issue a request or show a global count; explain the scope prerequisite |

The Flutter adapter tests cover the current source-shaped `skill_id` / `permission_level` / `risk_level` response and the earlier aliases. User-facing error text hides raw server diagnostics.

## 7. Accessibility and presentation

- Capability rows are keyboard-focusable and expose selected state and capability name.
- Evidence scope state is announced as a meaningful status message; color is not the only indicator.
- Source strings render as ordinary text widgets. The UI never parses catalog content or Evidence output as HTML.
- Do not render catalog `binding`, raw input/output hints, local paths, or diagnostics in the user-facing capability card.
- Use reduced-motion-aware transitions; selection does not require decorative animation.

## 一、9张新素材逐帧提炼的新设计元素（要用上，打破现在过淡/过素）
素材来源：用户微信下载9张（Codex monitor监控、8组浅色玻璃拟态、智能家居、外卖、Threads、兴趣选择、Earn深色卡、任务卡、登机牌、卡路里健康、车控/图片编辑、桌面信用Dashboard）。
### 1.1 必须落地的视觉语言（在 Design System V1.1 上增量，不推翻、主色仍 #0F766E）
1. **同色系柔和渐变数据卡**：低饱和同色系渐变+轻毛玻璃。用三域色生成——ZBMP 青绿渐变、CTH 蓝渐变、SYSTEM 紫渐变；风险/健康度用 红橙→黄→绿 语义分段渐变。禁止高饱和撞色。
2. **强对比主 CTA**：品牌色渐变胶囊按钮 + 深色/白色圆形箭头（参考 Start 柠黄胶囊+黑圆钮结构，换成序境青绿渐变+白圆钮）；主操作每屏唯一。
3. **深浅叠卡（重点看板用）**：深色纹理底卡（点阵/网格纹理 + 单色径向光晕）上叠加浮起的浅色玻璃数据卡，用于 CTH Real-time、SYSTEM Runtime/AI 等重点面板，制造层次。
4. **大数字层级**：整数用粗体深色(浅主题)/白(深主题)，小数位与单位用浅色细字（如 3,632**.21** USDT、1,930 /Kcal、730 +6pts）；Data 字号沿用24/700，小数位降一档变浅。
5. **数据可视化加丰富度（真实函数驱动，不造假）**：
   - 竖向柱条：已达成段用同色系渐变亮柱、未达成段灰柱（卡路里条）
   - 分段语义色条 + 当前位置黑色倒三角标记（信用分300/630/690/730区间条）→ 用于风险分/健康分/额度
   - 折线高亮当前节点（亮品牌色圆点+数值label）
   - 环形头像堆叠（成员/协作者）、圆环进度（额度/上下文占用，参考Codex 45%环）
6. **选中态**：选中=实底深色或品牌色胶囊/方块；未选=浅灰描边；筛选 chip 可带彩色线性/emoji 图标但克制。
7. **背景去纯白**：浅色主题用极淡暖灰/米白底 + 极淡彩色光晕（参考信用Dashboard暖背景）；深色主题墨黑 + 单色径向光晕。
8. **毛玻璃浮层**：浮动导航/工具条/底部操作条用半透+背景模糊+柔多层阴影；圆角统一加大到 16–24px。
9. **少量质感点缀**：3D 等距/轻渲染图标、彩色图标 chip 仅用于空状态/引导/成员头像，不泛滥、不做3D机器人。
10. **Codex monitor 直接对标 SYSTEM AI/Runtime**：模型卡(字母方块logo+名称+provider标签)、限额条(剩余%绿色+重置倒计时)、CPU/内存/GPU/显存 2×2 资源网格、Token 输入/缓存/输出/推理/上下文/累计 网格、上下文占用环、会话/工作目录/连接状态行。
11. **桌面信用Dashboard对标桌面布局**：极简线性图标侧栏（沿用现有左侧栏方向）+ 顶部胶囊页签(选中实底) + 渐变数据卡网格 + 右侧详情浮层。
### 1.2 红线
- 个性化≠花哨：渐变必须低饱和、同色系、只出现在关键数据卡/CTA/数据viz，正文区/表格/导航保持干净；三域色与#0F766E主色不变；浅色默认可切深色；所有数据真实来自 /api/viz 函数，缺失显式 null/—，禁止为了好看造数。

## 二、账户体系对标 Apple ID（1主+3管理员+5子账号）
### 2.1 账号层级与名额（硬约束，对标 iCloud 家庭共享）
```
                 Owner 主账号 ×1（用户本人=家庭组织者，唯一最高权限）
                 │  可创建/移除管理员、转让、管理全部成员/密钥/安全策略、看全局审计
        ┌────────┴─────────┐
  Admin 管理员 ×3      Member 子账号 ×5
  （主人任命；可管理子账号、审批登录、日常运营配置、看所辖域；
    不可增删管理员、不可改主账号与安全总开关）
   （受限成员；仅能访问被授权的 产品域ZBMP/CTH + 模块 + 动作read/write + 数据范围/时段；不可管理账号）
名额硬约束：admin 最多3、member 最多5（含停用占用名额，删除/转出才释放），创建超额必须拒绝并提示
```
### 2.2 对标 Apple ID 的功能模块（都放"设置"里，见第四节）
- 账号资料：头像/显示名/邮箱/手机；登录与安全：改密、随机数字双重认证、受信任设备与会话列表、远程登出
- 成员（家庭）管理：邀请/新建、角色、按 product(ZBMP/CTH/SYSTEM)+domain+action/resource 授权、状态 active/disabled、名额计数
- 登录审批：新设备/子账号登录可配置需 主账号/管理员 批准
- 账号恢复：复用现有 auth_recovery_center / v4_security_questions（安全问答+恢复码）
- 审计：v4_audit_logs 记录 谁/何时/何IP/何动作/何资源，成员管理与敏感操作必留痕
- AI 不参与授权判定，授权完全由规则+DB状态决定（沿用现有原则）

## 三、Apple 式"随机数字密钥"登录，替代 ZBMP 现有静态密钥
### 3.1 现状（要替换的）
- 现 v4_workspace_keys：`zbmp_`+32位随机串，PBKDF2 hash，expires_days=0 即永不过期；ZBMP 受限工作区靠它 unlock（app.py:5018-5106 /api/v4/api-keys）。
### 3.2 目标（对标 Apple ID 双重认证随机数字验证码）
1. 进入受限工作区(ZBMP)/敏感操作/新设备登录时，生成**一次性 N 位随机数字验证码**（默认6位，可配6–8；用 secrets 密码学安全随机，禁止可预测）。
2. 通过**受信任渠道**送达：默认在主账号/该管理员已登录的受信任设备会话内展示（系统内通知/设置-待批准）；预留 短信/邮件 渠道接口，缺凭证标 BLOCKED 不伪造已发送。
3. 验证码属性：**限时（默认120秒过期）、一次性（用后即焚）、校验失败次数上限（默认5次后作废重发）、重发冷却（如60秒）与单位时间上限**；DB 只存 hash 不存明文，明文仅生成时经受信任渠道出现一次。
4. 校验通过才颁发**短期** session/workspace grant（必带 expires_at），不再签发永不过期静态密钥；到期重新验证。
5. 现有静态 v4_workspace_keys 平滑迁移、不删表：降级为"受信任设备/程序化访问"的可选项且**强制设置过期+可绑定设备/IP**；主登录与工作区解锁默认走随机数字验证；旧"永不过期"选项移除，存量无过期密钥列出要求轮换。
6. 全部过程写 v4_audit_logs；失败/爆破写 v4_login_attempts 并按现有锁定策略锁定。

## 四、v4 账户并入主线（不独立）、入口放"设置"（用户明确）
1. **模块主线化**：把 v4_upgrade/auth/（models/security/service/workspace/audit）提升为一级主线模块 `account/`（或 auth/），初始化并入主数据库初始化链（启动即建表，不再依赖 v4_upgrade 独立子系统）；保留 v4_ 表名以保护现有数据，必要时加兼容视图，不删表不丢数据。
2. **API 主线化**：账户/成员/受信任设备/验证码/审计 统一到 `/api/system/account/*`（或 `/api/settings/account/*`，与现有路由风格一致）；现有 `/api/v4/api-keys/*`、`/api/auth/*` 加兼容层逐步收敛，旧路由标 deprecated 不立即删，前端全部改走新主线 API。
3. **前端入口放设置**：在 SYSTEM 域新增/完善 **Settings 设置页**（不另起独立产品、不进左侧主导航挤占），设置内分区：
   - 账户资料 / 登录与安全（随机数字验证、改密、受信任设备与会话、远程登出）
   - 成员管理（1+3+5 名额、角色、双域授权、状态、邀请/停用/移除）
   - 登录审批 / 账号恢复 / 审计日志 / 工作区与程序化访问（迁移后的密钥管理）
   - 页面按本文件第一节新视觉：渐变成员卡、大数字名额(如 2/3 管理员)、分段权限、六态齐全、真实API。
4. 双域对齐：成员授权必须带 product_id(ZBMP/CTH/SYSTEM)+domain+action/resource，与双域隔离、permission_gate 打通；ZBMP Analyst 不天然拥有 CTH 权限。
5. 主账号沿用现有 owner（Zachary），首次进入设置引导补齐资料与随机数字验证设置；默认弱口令 Zachary01 必须引导修改（must_change_password 已有字段）。

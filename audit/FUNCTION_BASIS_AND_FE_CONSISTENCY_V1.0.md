# 功能依据通用原则 + 前后端一致性硬约束 V1.0

## 一、所有功能：平台官方规则 + 已研究成果结合，禁止瞎编（通用，不限KOS）
1. 任何功能的规则/指标/阈值/口径/状态枚举/流程，实现前先查两类依据：①各平台**官方规则/公开口径**；②本地**已研究成果**——intelligence_library(13目录)、OSAI(D:\Zachary OS AI)、ADRH、backups/staging 里做过的实现。用户此前基本都研究过，须把研究过的能力**整体写入、不遗漏**（对照 ZBC_FEATURE_MAP 与研究目录逐项落地）。
2. 禁止拍脑袋/想当然/默认值/编造字段与公式；官方与研究都没有的，显式标 unknown/待研究并列入清单回报，不编假逻辑、不用0或"未知"静默填充。
3. 每条业务规则在代码注释或交付说明标注**来源**（平台官方文档 / 具体研究文档路径），可追溯；复用研究要适配当前双域架构，不照抄、不推翻。
4. 适用范围：采集与平台口径、KOS/KOL/KOC、风险阈值、指标计算、AI 判定与 prompt、报告模板与结构、证据/评估、账户与权限、各业务域功能——全部。

## 二、前后端一致性（P0，三个感叹号级）
1. **全量契约对账（自动化）**：
   - 前端侧：扫描 templates/*.html 与 static/js/*.js 全部 fetch/XHR/axios 调用，提取 URL+method+请求参数+读取的响应字段。
   - 后端侧：导出 Flask `app.url_map` 全部注册路由、method、返回 JSON key 结构。
   - 差集清零：前端调了后端没有=断链(P0必修)；method 不支持必修；请求参数名/响应字段名/JSON 结构/状态码/错误结构不一致必修；**禁止字段猜测**。
2. 任一侧响应/字段结构变更必须同步另一侧；统一响应信封(success/data/error)、分页、空态、错误结构、状态枚举。
3. 前端用到的每个 API 至少有契约冒烟测试（存在性+方法+结构）；产出《前后端契约对账表》：路由/方法/前端调用方/后端handler/请求字段/响应字段/状态，差集标注并清零。
4. 六态对齐：Loading/Empty/Error/Success/Degraded/PermissionDenied 必须对应后端真实状态；禁 Mock、假成功、死按钮、静态成功态。
5. 双域一致：前端请求带 X-Product-Id/X-Domain-Id，后端按域返回对应数据与字段，ZBMP/CTH 不串域、不混用对方专项字段。
6. 数据精准红线照旧：真实数据、缺失 null/unknown/missing、publish_datetime 与 collected_at 分离、content_hash+platform_id 精准去重。

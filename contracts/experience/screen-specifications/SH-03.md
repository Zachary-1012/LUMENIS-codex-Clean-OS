## 1. Product invariant and scope

SH-03 is a read-only explorer for verified Canonical data metrics. It explains a metric’s business definition, state, cadence, lineage and sampled values; it does not expose raw database records, storage paths, internal metric names, or a second metric truth. Metric values remain subordinate to the single Source → Evidence → Canonical Data chain.

The current screen builder only reports an unscoped global count. That result cannot close this screen. The App accepts only the typed `data.metrics[]` envelope after exact scope and read authorization pass, and otherwise shows a blocked or unavailable state.

## 2. Binding and response contract

| UI region | Required runtime value | App behavior |
| --- | --- | --- |
| Viewing range | `GLOBAL_ALL`, or exact `FOCUS` domain and focus id with safe display name | Show the business range; do not display raw ids |
| Read authorization | Read capability and allow decision | No metrics before authorization is verified |
| Metric index | `data.metrics[]` with internal name, safe display name, definition, state, `scope_verified` and an explicit Evidence-backed marker | Keep internal name only for model identity; show safe name and business state |
| Definition pane | Cadence, derived/formal classification and known lineage labels | Show definition and lineage; never expose raw table/path/provider fields |
| Samples pane | Optional typed label/value/time samples | Show supplied values as text; do not coerce missing values to zero |
| Existing route | `GET /api/experience/screen/SH-03` | Current global count/legacy shape is blocked; no fixture fallback |

State values remain distinct: ready, partial, stale, not collected and unavailable. A missing sample is not zero and an unavailable metric is not healthy. Every metric row needs canonical row scope, row read permission, Evidence-backed marker, and verified lineage/integrity. A `GLOBAL_ALL` envelope rejects a metric row explicitly scoped to a Subject/BrandFocus; an exact FOCUS envelope accepts only the matching active focus.

## 3. Responsive information architecture

### Desktop (available width ≥1120 logical px)

- Header and verified range span the page.
- Metric search/index occupies the primary column.
- Definition/lineage and sample panes stay visible beside the selected metric.

### Intermediate width (760–1119 logical px)

- Keep the index first and stack definition then samples beneath it.
- Preserve a visible boundary between metric selection and metric facts.

### Mobile (available width <760 logical px)

- Recompose into range → metric search/index → definition/lineage → samples.
- Selection is local and read-only; controls have touch targets of at least 48 logical px.

## 4. State and recovery

| State | Meaning | Behavior |
| --- | --- | --- |
| Loading | Metric response is pending | Live loading status; no stale values |
| Ready | Range, permission and typed metric list are verified | Render metric index and selected facts |
| Empty | Verified list contains no usable metrics | Explain that metrics are not available; do not show zero totals |
| Scope unavailable | Range/permission envelope is missing or selection-only | “正式数据暂不显示”; no metric rows or counts |
| Permission denied | Read decision is not allowed | Explain the range restriction; no values |
| Authentication required | HTTP 401 | Existing shell recovery path; no stale values |
| Offline / invalid | Core unavailable or malformed response | Safe retry state; hide raw diagnostics |

## 5. Actions and effects

| Action | Effect | Availability |
| --- | --- | --- |
| Search metrics | Local filtering over verified rows | Enabled in Ready |
| Select a metric | Local selection | Enabled in Ready |
| Edit definition or value | Would mutate Canonical truth | No active control |
| Recompute or write metric | Requires the canonical owner and effect gate | No active control |

## 6. Accessibility and localization

- The selected metric, its definition and its current state are exposed in readable order.
- Status uses text and iconography in addition to color; unavailable and not-collected states remain distinguishable.
- The title uses existing `screen.SH-03` integration keys in zh-CN, en and ko.
- The screen never renders raw table names, storage paths, provider labels, internal ids or database diagnostics.

## 8. Review decision

The App slice is implemented as a scope-guarded, read-only metric explorer with typed state handling and responsive recomposition. The current backend only supplies unscoped legacy data, so live acceptance remains blocked until a current actor-bound metric envelope is verified.

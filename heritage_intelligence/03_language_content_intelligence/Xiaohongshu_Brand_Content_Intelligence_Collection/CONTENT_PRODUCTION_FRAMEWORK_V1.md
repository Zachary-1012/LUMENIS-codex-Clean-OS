# Xiaohongshu Brand Content Production Framework V1

## Goal

把内容生产从“凭感觉写文案”升级为可复用、可验证、可持续学习的 Content Intelligence 流程。

```text
Brief
→ Fact Contract
→ Scene Classification
→ Audience / Emotion Job
→ Content Angle
→ Title
→ Narrative Skeleton
→ Draft
→ Platform / Brand Check
→ Rubric Evaluation
→ Revision
→ Human Approval
→ Publish
→ Performance Feedback
→ Learning Asset
```

## 1. Brief Intake

输入必须尽量结构化：
- 内容目标；
- 平台；
- 内容类型（图文/视频）；
- 活动/产品/会员事实；
- 日期、地点、门店、价格、权益；
- 必须出现的信息；
- 禁止出现的信息；
- 视觉素材与顺序；
- 用户动作目标；
- 品牌语气。

缺失关键事实时，AI 不得自行补造。

## 2. Fact Contract

所有确定性事实先独立形成 Fact Contract：

```text
WHAT
WHEN
WHERE
WHO
BENEFIT
RULE
CTA
SOURCE
```

正文创作只能在此基础上包装表达。

## 3. Scene Classification

至少识别：
- Product Seeding
- Event / Campaign
- Membership / CRM
- Fashion / Lifestyle
- Emotional Content
- Cultural / Art
- Anniversary / Brand Story
- UGC Interaction
- Video Narrative

不同场景不得共用同一个固定模板。

## 4. Emotion Job

不是问“这篇要写得浪漫吗”，而是问用户读完需要发生什么心理变化：

- 想去现场；
- 想收藏；
- 想评论；
- 想分享回忆；
- 想体验产品；
- 感到被理解；
- 感到会员权益值得；
- 对空间/品牌形成记忆。

## 5. Angle Selection

同一事实至少生成 3 个角度候选再选择：

A. 场景切口
B. 情绪切口
C. 事件/时间切口
D. 产品感官切口
E. 关系/记忆切口

选择标准：
`Relevant × Distinctive × Visualizable × Brand-fit × Fact-safe`

## 6. Title System

标题必须承担明确任务：

```text
Hook = Event / Benefit / Object + Emotional or Visual Twist
```

不要：
- 只写品牌名 + 活动名；
- 纯抽象情绪；
- 为了猎奇歪曲事实；
- 把所有优惠都塞进标题。

## 7. Narrative Skeletons

### Product
`季节/场景 → 产品感官 → 差异点 → 想象 → 到店信息 → 轻互动`

### Campaign
`事件钩子 → 用户关系/记忆 → 活动意义 → 参与机制 → 日历/规则`

### Membership
`生活方式命题 → 权益细节 → 使用场景 → 身份价值 → 入口`

### Emotional
`真实压力/情绪 → 具体承载物 → 感知细节 → 留白`

### Art / Anniversary
`时间/空间命题 → 具体尺度/结构/历史 → 象征意义 → 邀请现场`

### Video
`第一秒主题 → 视觉对应短句 → 节奏推进 → 单一核心落点`

## 8. Draft Rules

- 第一屏先建立阅读理由；
- 每段只承担一个主要功能；
- 抽象词后必须有具体细节；
- 活动类必须保留可扫描信息区；
- 权益数量多时采用分层，不写成一堵文字墙；
- 视频配文要比图文更短、更有视觉呼吸；
- CTA 不应破坏正文情绪。

## 9. Rewrite Passes

### Pass A — Fact Safety
核对所有时间、地点、金额、权益、名词。

### Pass B — Social Native
删除公关稿、海报稿、新闻稿语气。

### Pass C — Anti-AI
检查句式机械重复、抽象词堆积、排比滥用。

### Pass D — Brand Tone
确保高端但不端着、年轻但不装年轻。

### Pass E — Mobile Readability
检查首屏、段落长度、Emoji、信息层级。

## 10. Content Learning Loop

发布后反馈进入：

```text
Content ID
→ Content Type
→ Angle
→ Title Pattern
→ Length
→ CTA
→ Publish Time
→ Views / Likes / Saves / Comments / Shares if available
→ Qualitative Comment Signals
→ What Worked
→ What Failed
→ Next Hypothesis
```

注意：不能只以互动最高作为“最好文风”。不同任务要按目标评估，如品牌记忆、活动参与、收藏、到店、会员理解等。

## 11. AI Content Agent Boundary

AI 可以：
- 分析 Brief；
- 检索 Style DNA；
- 生成角度；
- 草拟；
- 自评与改写；
- 做版本对比。

AI 不可以：
- 发明活动事实；
- 自行改变优惠规则；
- 把历史样本直接改词复用；
- 未审批直接发布；
- 用未经验证的流行说法损害品牌语境。

## 12. Production-ready content contract

每次最终输出建议同时保存：

```text
content_id
brief_version
fact_contract_version
content_type
angle
style_profile
copy_version
fact_check_status
evaluation_score
human_approval
source/evidence
performance_feedback
```

原则：**内容创作不是模板生成，而是“事实约束下的场景化表达决策”。**

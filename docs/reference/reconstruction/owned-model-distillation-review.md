# 自研垂类AI、已有小模型与未来蒸馏

2026-10-30。针对用户澄清的“用教师监督发展自己的模型”研究；不是新增大模型服务接入方案。既有通用接口、自研小模型、全业务智能及模型训练属于同一套行业AI。最新要求把CPU及其他无GPU训练纳入当前升级准备，选择真实高效且质量合适的方法；GPU训练等待条件。先完成全部开发前置，再实施迁入与训练，不以GPU后置减弱当前AI。此研究未下载权重、启动模型或训练。

## 教师究竟是什么

教师是提供监督的角色，不是DeepSeek、GLM、GPT和Grok Bot共同使用的一份标准模型。可用监督包括高质量答案、可核工具轨迹、偏好、错误反例；学生通常在适合其任务的已有基座或原有小模型上学习。不是把一个大模型压缩文件下载后就自然获得同等能力。

最适合先研究的路线是经过核验的任务样例与结果监督：训练用户真正需要的分类、归属、排序、证据判断、专业表达或工具使用。若要蒸馏logits/内部表示，还需教师内部访问、词表与结构对齐等条件，不能仅有聊天接口就宣称能做。事实会变化，模型参数不能替代来源更新、检索、权限和原文引用。

## 可以直接指导开发的分层路线

1. **现在完成的产品能力。** 基础任务/编辑/计算/采集无AI正常运行；已有通用接口保持兼容，已获准可用的小模型及推理进入实际消费者。研究、经营/品牌、监测、原创、Office、视频和播客都要有真实AI增强操作与效果检查，不能只做聊天。
2. **现在建设的自有能力。** 按真实任务整理带权利/来源/版本的训练候选、人工修订、失败/未知和工具轨迹；严格分开运行记录、可用记忆、可评策略和训练许可。完善检索/排序/专业规则、约束计算、上下文与精确修改，用同一真实工作评价整体收益。不得把“数据建设”变成让用户替系统标注完才能工作的门槛。
3. **已有小模型的整合。** 逐项核权重、训练方法、语言/任务范围、代码/依赖及实际消费者，保护有效资产。先比对当前基线、资源/延迟及真实错误；某模型退化时保用户已选路线和诚实错误，不静默换供应商。异构模型用任务协作和统一输入输出连接，不直接拼权重。
4. **CPU及无GPU训练现在准备，GPU训练保留。** 为每项任务冻结现有产品基线、模型/代码与许可、合法训练来源、标签依据和独立测试集；比较稀疏分类/排序、现有轻量模型可训练部分及不更新参数的方法对实际任务的效果与总成本。前置完成后先做有界可复现训练与资源实测，有增益再扩大。教师可以错误，不能自己生成、自己评分再宣布通过；包含独立评审、反证、失败轨迹和不确定任务。硬件预算按真实参数、优化器、激活、上下文及预处理计，不凭“CPU可跑”推定足够快或已达专业质量。
5. **评价与发布。** 按时间、客户、事件及近重复隔离训练/验证/测试；原始留出材料不用于提示调优或教师补题。比较未训练学生、当前有效产品路径、候选与适用专业参照，在同等任务和成本下核事实/引用、方法、约束、编辑保全、恢复、人工修复负担及语言覆盖。通过后再考虑灰度、模型重载和回退，保旧成果可追原版本；训练loss或权重文件不是能力通过。

本方案不预设所有任务都需要训练、不许用尚未训练的模型掩盖缺失功能。CPU训练、检索、领域约束、专业工具、记忆和完整任务执行共同服务当前行业AI升级；不能只改检索名称就宣称模型已训练，也不能把一个小分类器的提升当成完整行业AI已达前沿。

具体CPU任务、样本资格、独立分组、比较基线、资源预算与重载回退统一落实在[行业AI合同§4.4–4.7](../../domains/intelligence.md#cpu-training)，资产读回与真实缺口见[智能保全矩阵§14](intelligence-preservation-matrix.md#cpu-preparation-evidence)。本研究不复制另一套训练标准；当前仍是开发前置，未执行训练。

## 0. User problem and invariant

- User job: draft a task, inspect server-returned stages and evidence/artifact anchors, and start only when a real controlled route is present.
- AI output is derivative and cannot replace CTH/BMP Canonical Data, Evidence, Permission or external effects.
- The current target screen is unbound. The slice therefore provides a local draft and honest read-only stage inspector, not fake task execution.
- The composition is an observable task workbench (draft → stage progress → evidence/artifact inspector), not a generic card dashboard.

## 1. Route and callable contract

- Read route: `GET /api/experience/screen/AI-02` via `LumenisCoreClient.screen('AI-02')`.
- Current response contract: `ok`, `screen`, `source`, `bound`, `binding`, `sections`, optional `task_steps`, `evidence_refs`, `actions`, `generated_at`.
- Start/cancel/retry/complete routes are not verified for AI-02 and are not called. A local button remains disabled until a bound response contains the complete server proof below and the host supplies the real action callback.

## 2. Verified fields and allowlist

| Field | Rule |
| --- | --- |
| Stage key/label/state | bounded IDs, safe text and known state labels only |
| Evidence refs | `EV-*` or bounded typed IDs; no URL/path |
| Action | requires safe ID, `capability_status=VERIFIED_AVAILABLE`, and a callable `POST /api/experience/ai/intent` contract accepting `task` or `intent` and returning `execution_id` and `status` |
| Binding | bound only when `source=runtime` and `bound=true` |

Execution is enabled only when the server also proves a bound actor (`source=server`), an exact authorized `GLOBAL_ALL` or `FOCUS` scope (`CTH`/`BMP`, with a Subject for `FOCUS`), both read and execute permission decisions of `ALLOW`, non-empty Evidence references, verified Evidence lineage and integrity, and the callable contract above. `VERIFIED_AVAILABLE` alone, design-only action fixtures, or an empty local callback never enables the button.

No provider names, model strings, paths, tokens, raw errors or unscoped claims reach the UI.

## 3. State and recovery matrix

| State | Meaning | Action |
| --- | --- | --- |
| Loading | task service read pending | Wait |
| Unbound | target route not registered | Inspect any safe returned stages; do not start |
| Bound without action | service exists but no verified execution action | Draft/inspect only |
| Bound with action | action metadata is present | Still wait for canonical Permission/action contract before enabling effects |
| Offline / 401 / 403 / malformed | read cannot be trusted | Retry or return; no execution claim |

## 4. Desktop/mobile and accessibility

- Desktop: task draft and stage progress are primary; evidence/artifact inspector is beside them at ≥1050px.
- Mobile: task draft remains first, followed by stage progress and evidence anchors in one scroll; no flex child receives unbounded height.
- Keyboard order is draft → start (disabled unless verified) → stages → evidence → recovery note. Stage state is spoken text, never color alone.

## 1. User problem and product invariant

- Role and scope: no selected Subject or BrandFocus means GLOBAL_ALL. FOCUS is optional and only narrows the existing scope. Opening the product, reading globally, drafting, research and AI entry must not require choosing a Subject, BrandFocus or product account. Actual data reads and effects still use the canonical server authorization. The present missing AI execution integration is a service/contract gap, never a missing-selection error.
- User task: describe an analysis or draft task, inspect what real Evidence and recent AI executions are available, then start only when an authorized context and executable route are present.
- Completion signal: a real execution returns an execution ID; its response states whether Evidence was recorded. The current route does not return source-level Evidence IDs or a trace lookup route, so a recorded flag alone is not a completed source-level Trace.
- Owner and invariant: Shared AI / Agent Groups performs derived analysis within the caller's source-domain context. CTH owns commercial facts and Subject scope; BMP owns Brand/Market facts and focus. AI output remains a proposal and never replaces either domain's Canonical Data or Evidence.
- Out of scope: changing CTH/BMP ownership, generating fake AI output, inventing a context or trace API, or running write/export/publish operations from the intent composer.

## 2. Route, entry, exit and return

- Entry: AI-01 is mounted by the canonical App Shell or embedded by ACC-03 through the same widget, ViewModel and draft owner. Both receive the same shared Core client, whose default is GLOBAL_ALL. No second composer service, account wall or forced domain selection is introduced.
- Read route: `GET /api/experience/screen/AI-01`; implementation `experience_runtime.py::screen_viewmodel` delegates to `_build_ai01()`.
- Intent route: `POST /api/experience/ai/intent`; implementation `experience_runtime.py::ai_intent` delegates granted work to `lumenis.shared.agents.skills.execution.run_execution_chain`.
- Exit: navigate to the originating product workflow only when the shell supplies a verified route. Gateway/catalog links in the existing backend aggregate are descriptive until navigation and caller context are verified.
- Trace / Return: the POST response exposes `execution_id` and `evidence_recorded`. No current AI execution detail / Evidence lineage GET callable was found. Preserve the response locally and show whether Evidence recording was confirmed; do not render a fabricated Evidence item or pretend that a source trace can be opened. Return restoration requires the shell to own prior Subject/Brand and navigation state.

### 舒展工作空间与跨能力直接继续

五个架构分工是产品内部能力、数据和Owner边界，不是用户完成一件事必须依次打开的五层页面。首页以“我想做什么/继续哪件工作”为入口：选择研究、写作、制作、经营或品牌问题后直接进入该任务的具体工作面，并带当前合法材料、已保存版本和可用上下文；不要求先选架构、再选模块、再重新录同一问题。必要主体/市场/执行范围在使用该动作时就地说明和选择；当前范围明确且仍获授权则复用，歧义或跨域采用须明确核对，不能靠少点一步绕过Permission或复制跨域数据。

工作面默认舒展：一个清楚的主要编辑/阅读区域、少量必要即时操作、可按需展开的上下文/依据。留白用于区分任务层级与当前焦点，不用巨大装饰把正文挤到屏外；有创意的非对称构成、尺度对比和阶段揭示围绕真实对象展开，不把每个字段塞进紧密小卡。现各专属合同的左/中/右描述是信息关系和宽度足够时的可选并读，不代表默认三栏全部常开；桌面也先保主工作舒展，用户决定何时并读。密集表格/多窗仅在当前任务确需且用户选择时展开，可回舒适阅读；不删除字段、功能或完整比较能力来换留白。200%字体、三语长文本、窄窗和键盘出现时仍可到达主操作。

跨能力继续工作优先就地展开或直接带上下文跳转并保返回锚点：来源旁记要点、结论回原文、错误直达需修输入、当前稿查看影响、通知回待决定处。返回不经过首页重新找对象，不重复要求已合法保存的输入；多个真实任务可各自保稿和版本，系统不会因切面自动停止任务或重新发送外部动作。现有路由/Owner缺接线时明确缺项并保原工作，不能用假浮窗模拟后端已完成。便利操作适用于所有能够复用同一真实合同的能力，不限随手记；当前有用的小巧思纳入既有Owner/本地前端实施范围，而不是减少原能力或再造一套快捷操作服务。

官网以工作故事、真实成果与可控演示舒展叙事，不把架构图当必经导航；Web和Windows/macOS保直接任务入口、原位置返回和用户选择的并读；iOS以一个主工作面、可逆Sheet与清楚回链呈现，不层层堆弹窗。底部便笺、加载小动作和AI表达不能遮挡原稿、重要错误或确认。界面自身AIGC可以提出符合当前任务的原创空间/视觉构图和交互呈现，采用前可预览，用户锁定/撤销有效；不复制参考品牌皮肤、人物或叙事，不把规则重排或静态插画冒实时生成。

验收用完整任务路径对照：从首页合法输入到首次有用编辑/阅读、跨来源核对后回原选区、转用成果而不重复录入、切任务再继续、失败后原位恢复。分别记录导航层数、返回/复制/重复输入次数、首个有用结果耗时、错误和工作丢失；未知未测不填漂亮数字。减步骤不能跳掉必要确认/证据，视觉舒展不能牺牲信息可找性；现仍是设计与接口合同，实际四端布局和可用性由本地同版构建验证。

## 0. User problem and invariant

- User job: browse registered, versioned, evaluated and actually bound Product Skills that may be used by approved CTH/BMP workflows.
- Current slice is the read-only catalog; the in-loop Store adds install, enable, update, disable and uninstall per SOI §2-12.
- Shared Capability owns registration metadata; CTH/BMP retain business ownership and Permission/Evidence boundaries. AI remains derivative.
- The list/detail capability matrix is specific to skill verification and ownership, not a generic app-store card grid.

## 1. Route and verified allowlist

- Read route: `GET /api/experience/shared-skills` via `LumenisCoreClient.sharedSkillsCatalog()`.
- A row is shown only when: `ok=true`; safe `skill_id`, semver `version`, name/description/input/output; known permission/risk/execution/evaluation values; `binding.available=true`; `implementation_state` starts `BOUND_`; and evaluation is not `DEPRECATED`.
- Owner is normalized to `Shared Capability` or `Registered capability`. Consumers are limited to `CTH` and `BMP`.
- Raw implementation paths, module bindings, provider/model names, secrets, URLs and internal registry errors are never rendered.

## 2. State and recovery

| State | Meaning | Action |
| --- | --- | --- |
| Loading | registry read pending | Wait |
| Ready | verified entries returned | Search, inspect, optionally ask host to run an already verified READ_ONLY skill |
| Empty | no row passed verification | Explain that unverified rows remain hidden |
| Blocked / 401 / 403 | registry access not confirmed | Retry/return; no fallback catalog |
| Offline / malformed | registry cannot be trusted | Retry; no inferred availability |

Install/enable/update/disable stay hidden until the Store lifecycle passes. `onRun` only receives a verified `READ_ONLY` entry; no run here.

## 3. Desktop/mobile and accessibility

- Desktop at ≥1080px: searchable verified list and capability detail sit side by side within a bounded 650px region.
- Mobile: list has a bounded 360px viewport, followed by one selected capability detail; no unbounded flex list is placed in the scroll view.
- Search, row selection and optional read-only run affordance are keyboard/touch accessible; permission/risk/evaluation are text-labelled.

## 6. REAL USER WORK / capability evolution card

- `REAL USER JOB`: operator selects a real, trusted skill for a real CTH/BMP task and understands its input/output/risk before use.
- `REAL INPUT`: live shared-skills registry row and authorized workflow context.
- `END-TO-END PATH`: registry read → verified catalog → host-owned read-only invocation → result/Evidence → return.
- `USER-VISIBLE RESULT`: real capability metadata or honest hidden/unavailable state.
- `FAILURE/RECOVERY`: never downgrade unverified or stale registration to available; preserve the last verified read only when the source says it is current.
- `EVIDENCE`: registry version, binding/evaluation result, Permission decision, invocation result and trace.
- `ACCEPTANCE ASSERTION`: `BLOCKED_PENDING_LIVE_SHARED_SKILLS_AND_READONLY_E2E`.
- `RANDOM ENTITY DATA ACCEPTANCE`: sample count 0 here; future run must rotate registry entries and consumers.
- `GLOBAL UNIVERSE / DATA MATURITY IMPACT`: skills consume context but do not claim global coverage or maturity.
- `COMMERCIAL OVERLAY IMPACT`: `COMMERCIAL_READY=NO` until real catalog and optional read-only invocation are proven.

## 7. Continuous frontier research / review decision

- `RESEARCH COMPLETE / NO JUSTIFIED UPGRADE` on 2026-09-22. The canonical shared-skills registry already supplies version, Permission, risk, execution and evaluation metadata; adding a package marketplace or install manager would duplicate ownership.
- Decision: `ADAPT` the existing read route and registry gates. Remains `BLOCKED` until screen review, live registry and target-surface acceptance pass.

当前已绑定动作限定本轮可执行范围，不限定已批准的产品终态。任何尚未接通的既有能力必须列为现有 Owner 的 OPEN 依赖，补齐合同、真实正常结果与恢复验收；不得因接口暂缺把完整交互目标缩减成只读页，也不得用未绑定按钮假装已实现。

- **来源、范围与版本连续性：** 保留既有 skill ID/version、输入和原 Task；每个生命周期/运行操作单独经过既有 Permission，不因选择而授权

- **交互与视觉约束：** 按本屏任务组合文字、图形、可编辑对象和局部操作；只使用上文已绑定字段/动作。AI建议可检查、编辑或拒绝，服务端Owner/Permission决定是否执行。彩绘用于图标及适合的局部元素，有功能含义的线性控件继续保留；整体空间、层级、动效与交互依唯一Experience和真实任务设计，不固定为二维或三维风格；颜色可丰富但不过量，不单独表达真假/权限/状态。不得复制社交平台页面或套统一卡片模板；真实角色按用户Brief/脚本描述创作，不复制参考人物；原研究的采用范围、素材权利与任务完整性继续保留。

# XHS 账号安全事件：生产冻结与整改方案

> Incident ID: `XHS-SAFETY-2026-08-31-01`
> 状态：`ACTIVE / COLLECTION FROZEN`
> 触发：账号收到平台“疑似使用三方工具或脚本（如AI）自动浏览、查看或发布内容”的警告。
> 处置原则：保护账号优先，不尝试降低检测概率或恢复自动化。

## 1. 立即处置

小红书相关自动采集、自动浏览、自动登录、CDP/浏览器自动化、自动任务调度全部保持 OFF。

不得通过降低频率、随机等待、代理/IP 切换、设备切换、多账号等方式测试或规避平台检测。

## 2. 当前生产状态

- XHS Web 自动采集：`FROZEN`
- XHS App 自动化：`BLOCKED`
- XHS App Evidence：`OFF`，直到账号安全事件完成复盘；恢复时仍只允许用户主动提供证据
- XHS Topic Campaign：`DISABLED`
- XHS Scheduler：`DISABLED`
- XHS 自动恢复/自动登录：`DISABLED`
- XHS 代理/IP 规避逻辑：`DISABLED / PROHIBITED`

## 3. 证据保全

保留现有日志、错误状态、任务记录和版本信息，不删除以便复盘。

不得为了“清理痕迹”修改历史日志或生产数据。

## 4. 允许的研究路径

仅研究：

1. 小红书官方开放平台当前实际授权范围与官方 API/SDK。
2. 官方授权后可使用的 OAuth / API 能力。
3. 不依赖账号自动浏览的公开数据来源。
4. 用户主动提供的公开页面证据（恢复后再启用）。

## 5. 永久禁止

不得实现或测试：私有 API 逆向、签名还原、抓包重放、设备/Token 伪造、验证码绕过、IP/代理规避、设备指纹规避、多账号轮换、App 注入、App 私有数据库读取、自动批量浏览/点击/滑动、以 Shadow/Research/Debug 名义绕过门禁。

## 6. 恢复条件

本事件在没有新的人工批准前不得恢复 XHS 自动采集。

恢复前必须同时满足：

- 完成平台警告复盘
- 明确当前使用方式与平台规则的兼容性
- 确认没有继续产生自动化行为
- DCC 审计通过
- 三仓库状态一致
- 回归测试通过
- 人工批准

如果只能通过“规避检测”才能恢复，则永久不恢复该自动化路径。

# 序境整体产品工作方式升级：Apple / Tesla / Samsung 官方实践与适用标准

研究日期：2026-10-18 UTC。状态：研究建议；没有执行产品、数据库、运行环境、远端或凭证修改。本文不是新执行规则，也不是已完成验收证明。

## 0. 结论与证据边界

优先升级的是“任务真的做完、能看懂当前状态、能带着上下文接续、出错能恢复”，而不是复制三家公司界面。全部建议进入既有 SYSTEM / CTH / BMP / Shared / Agent、C1–C6/F/M Owner；不另造操作系统、通用 UI 平台、任务队列或真相数据库。

最值得先落实的五项：
1. 区分配置、授权验证、连通性、业务处理、持久保存、外部结果，杜绝假成功。
2. 输入带类型、单位、时区、期间和来源；把可继承的业务上下文自动带入，但不继承未经确认的权限。
3. 同一任务跨端继续，绑定原任务、版本和来源，保留焦点/选区/播放头。
4. 所有取消、撤销、恢复按真实效果分类；未知结果先核对，不盲目重复执行。
5. 同版本的真实任务、故障注入、可访问性和四端证据构成验收，不以测试数量、品牌口号或“接入成功”替代。

本文没有证据证明 Apple、Tesla 或 Samsung 的全部内部研发流程、管理机制、生产系统实现或组织文化。公开开发文档只能证明其公开接口/建议；营销页面的“高质量”“安全”等措辞不构成独立质量证据。NIST SSDF 是公开安全开发建议框架，WCAG 是 Web 可访问性推荐标准；二者都不是序境全产品质量的单一充分条件。

## 1. 研究方法与来源分级

S 类：正式公开规范/推荐标准，按具体版本和条款使用。
P 类：厂商官方开发或支持文档，证明公开产品实践，不等于跨行业标准。
C 类：官方公开源码，可检查特定版本行为，不代表全部生产部署。
M 类：营销、自述、文化主张；仅作背景，不进入效果或安全验收。
U 类：未公开或本次未证实；明确不推断。

全部外部来源本次实际检索或打开，详见 SOURCES.csv。Apple 动态页通过官方提供的 `.md` 内容读取；其 metadataVersion 0.1.0 只是文档元数据格式，绝不能写成 HIG 产品版本。未见发布日期的滚动文档标注“无正式版号；访问日2026-10-18”，不以页脚2026推导发布日期。没有阅读付费标准全文，也没有借标准标题推导合规认证。

## 2. 编号原则、产品适配与验收

### ATS-01 进度必须来自工作事实，而不是动画计时
- 问题：长任务显示加载、假百分比、完成后才报保存失败，促使用户重复提交。
- 来源：S01 Apple HIG Progress indicators，官方实践；可见变更记录最近为2023-09-12，滚动正文于本次核验。区分可确定/不可确定进度，并说明停滞与取消影响。
- 可证结论：状态反馈要让人判断是否等候、暂停、取消；无法计量时不应伪造精确完成率。它没有规定适用于所有系统的毫秒门槛，也未证明某种动画提高生产效率。
- 适配：C2/C6 的既有 Task/Agent 状态→F 当前 ViewModel 映射；C1采集、C4渲染、C5解析报告各自产出真实阶段。增加字段前先查原合同有无等价项：run/attempt、phase、done_units、total_units（未知=null）、unit、observed_at、can_cancel、blocking_reason。后端时间 UTC；界面按用户时区；耗时用秒、展现可本地化；未知 ETA=null。不能把子阶段100%当整个任务成功。
- 错误/恢复：断线呈现最后确认时间和当前未知；重连读回同一 run；旧 attempt 不覆盖新结果；取消收到确认前展示“正在停止”语义，而非立即假终态。
- 验收实验：解析10/100份资料、媒体10/60分钟两档；注入乱序、重复、丢事件和断线。所有显示成功都有成果读回；未知时无编造百分比；不同任务不串结果。建议目标为事件到呈现 p95≤1秒（受控网络），须先测基线，不能称 Apple 标准。记录用户主动刷新/重复提交数、等待判断错误率与p50/p95耗时。
- 不适用：纯瞬时动作无需强加进度条；装饰动效不能替代业务进度。下一步：只增补原映射和缺失回归，避免重写状态机。

### ATS-02 撤销、取消、版本恢复、外部补偿必须分开
- 问题：“撤销”按钮可能只是本地视觉回退，却掩盖服务器或外部效果已发生。
- 来源：S02 Apple HIG Undo and redo；S05 Tesla 更新支持与 S06 命令文档为反例边界。Tesla 安装阶段不可取消且不支持用户退回旧车载版本，这是车载领域限制。
- 适配：C4编辑器、C5 SavedWork/Artifact、C6任务取消、F操作呈现；沿现有版本记录保存 operation_label、base_version、result_version、affected_selection、reversibility。编辑撤销使用现有命令历史；已保存版本恢复形成有出处的新版本；外部动作按既有 Effect Fence 走补偿/对账。
- 默认/错误：不默认“所有行为可撤销”，也不以 Tesla 为由取消序境原有取消/恢复。批量编辑按一次业务动作分组；撤销明确对象和影响范围；冲突不得覆盖他人新版本；不可逆动作按现有确认门槛说明后果。
- 验收：删除段落/移动剪辑→撤销→重做→保存→关闭重开，字节/结构/播放头一致；断网取消后重连无“幽灵成果”；外部效果已提交且回执丢失时不得假称撤回。目标：可逆误操作从人工重做N步变1个恢复动作，实测N而非预估收益。
- 不适用：Tesla 的不可回退政策不用于文档、数据库或序境发布。下一步：为各既有 action 做 reversible/cancelable/compensatable 明确矩阵。

### ATS-03 跨端接续的是同一个任务，不是复制一份数据
- 问题：换设备后重新找文件、填写上下文，甚至继续旧版、串工作区。
- 来源：S04 Apple Handoff 支持文档2026-06-10。证明符合条件的设备可接续工作；需同账户、开启相关功能且满足设备条件。不证明其内部同步算法。
- 适配：C6 context/API、C5 SavedWork、C4 Timeline/Artifact、C3业务工作、F Flutter；保留 task/work、workspace、resource_version、source_versions、selection/playhead、locale、last_confirmed_at。只传必要引用与可恢复状态，接收端重新鉴权和读回；不把授权 token 放在链接里。
- 默认/单位：时间轴位置用既有毫秒或秒合同，禁止混用；业务日期显式时区；无当前可见范围时不猜 Subject/BrandFocus；普通 Shared 不额外强制领域上下文。
- 恢复：离线草稿与服务端版本分开；两端编辑冲突保留双方；撤权后接续入口只给安全提示，不泄露预览。
- 验收：Web编辑→桌面继续→iOS查看/批准→Web结果；含过期链接、用户切换、项目切换、两端同时编辑、网络恢复。原任务/版本/范围100%匹配；不得要求重新上传已可用材料。目标从“查找+下载/上传+重填+定位”缩减到打开任务接续；按端测点击数与时间，原生实机未测保持NOT_VERIFIED。
- 不适用：不引入 Apple 蓝牙/iCloud绑定、跨产品任意OS控制或复制 Apple Dock；官网不是完整编辑端。下一步：补现有 deeplink/context contract 的端间证据。

### ATS-04 权限在需要时请求，拒绝只影响相关动作
- 问题：启动就要一切权限、把普通资料上传强制转成权益问卷，或把连通性误当授权。
- 来源：S03 Apple HIG Privacy（可见变更记录2023-06-21；滚动正文）；S09 SmartThings OAuth scope 实践。
- 适配：C6 Permission + C1来源 + C4麦克风/素材 + C5导入 + F说明；沿既有授权字段绑定 actor/workspace/resource/action/purpose/expiry/version。默认未授权；目的和接收方以用户可理解业务词说明；撤权立即影响后续调用。
- 恢复：麦克风拒绝仍能导入现有音频；外部AI不可用仍能确定性解析/编辑/保存。普通材料上传保留现行无额外用途表单路径，unknown rights 不自动变发布/训练许可。
- 验收：首次使用、拒绝、仅选部分文件、撤权、跨成员、到期、旧批准复用；零跨域越权，零秘密进入日志/URL。观察首次完成率与多余权限提示数；不以提高同意率为成功指标。
- 不适用：Apple 专属系统弹窗前置页要求不是序境通用确认框模板；Keychain/硬件隔离只能在支持的平台使用，不能宣称Web获得相同硬件保护。下一步：逐个现有 action 补最小权限与拒绝退路。

### ATS-05 “可能已执行”是独立事实，不能自动重试
- 问题：调用超时后重试导致重复发布、重复产物或重复扣费；把网络异常包装成功。
- 来源：S07 Tesla 官方 vehicle-command v0.4.1 `pkg/protocol/error.go`，公开源码；MayHaveSucceeded 与 Temporary 分开，ShouldRetry 在可能成功时返回false。
- 适配：C2/C6 既有任务 UNKNOWN/outcome_unknown/Effect Fence，C3业务动作，C4导出，C5保存；沿现有 idempotency key、attempt、request_digest、effect_receipt、readback_ref。未知与失败分开，禁止更名来掩盖状态。
- 默认/错误：只对确认无效果且可重试的临时失败重试；预算/次数/退避用既有配置并保留单位秒。提交后超时先按作用域读取效果；未对账前冻结同一效果重发。用户改参数形成新意图，不能复用旧批准。
- 验收：服务端成功后丢响应、双击、重启、过期回调、不同输入重用key；每个意图最多一个可观察外部效果，持久结果有唯一出处，未知不会升级成成功。测试替身只证明机制；真实外部效果另需授权验收。
- 价值：减少重复产物清理和人工查账；统计重复率、对账时间、用户重做次数。下一步：把各 handler 异常分类映射到已有状态，不照搬车载协议/密钥。

### ATS-06 健康必须分层：配置 ≠ 鉴权 ≠ 连通 ≠ 业务完成
- 问题：有token、进程在线或200就显示“连接成功”，实际取不到业务数据。
- 来源：S10 SmartThings Device Health 明确健康检查有覆盖盲区，包括部分客户端状态更新与事件丢失；ONLINE 是预期响应而非业务完成。
- 当前落点：C1 `github_connector.py`、collector GitHub adapter，C6 `system_health_api.py` / `experience_runtime.py`，F SYS。当前新测试已明确 `/user` 实际验证，与这一原则一致。
- 字段/默认：configured、authorization_verification、dependency_health、last_check_at、last_successful_business_read_at、error_code、coverage；不要将last state change混成last successful probe。无探针=NOT_VERIFIED；配置状态读取不暗中发起网络探测；显式检查才用授权路径查询。
- 恢复：撤销凭证、401/403/429、超时、无效JSON、空login都不能CONNECTED；/user通过只证明该鉴权检查，具体仓库权限仍须范围内验证。错误脱敏，保留真实可行动原因。
- 验收：复用当前 test_github_status_verification，补UI读回/文案和过时状态；注入五类故障时0假绿色。测从错误出现到定位层级耗时，减少盲目重填凭证/重启步骤。
- 不适用：不能机械抄SmartThings的健康间隔或60秒断线口径；不能把“配置≠在线”当取消真实健康检查的理由。下一步：根修复同版审查后扩展到现有其他connector，不创建新监控服务。

### ATS-07 能力契约必须说明值、单位、允许动作与版本
- 问题：业务值含义模糊，百分比与比例、秒与毫秒、原生发布时间与入库时间混用；按钮暴露不存在的能力。
- 来源：S08 SmartThings Capabilities：属性与命令分开、类型/约束/可选单位；文档当前仅支持capability version 1，属性示例采用JSON Schema draft4。此版本不应复制为序境新schema标准。
- 适配：C1 Source/Evidence、C3 CTH/BMP指标、C4时间轴、C5研究与数学输入、C6 API、F真实控件；扩展既有typed contract，不建立新注册表。每个数值带单位/分母/时间窗口/币种（如适用）；unknown=null且原因明确；只在真正可调用且获准时暴露动作。
- 默认：先用同一任务已确认的范围/期间/单位并可编辑，缺币种不猜人民币，缺时区不默认为服务器当地时间；用户只填业务问题/范围/资源，不填算法内部权重。
- 错误/恢复：前后端同口径验证，错误定位字段并保留其他输入；变更单位时显式转换或要求确认，不静默改数值。旧客户端无法理解的新能力诚实禁用，不假装成功。
- 验收：0/空/null、极值、负值、除零、比例0.2/20%、秒/ms、DST、UTC跨日、韩文/中文/英文；输入输出同单位；跨端一致。目标每项有效信息只输入一次；减少字段返工率，实际测量。
- 不适用：只读事实没有必要虚构command；设备开关概念不能替代序境领域模型。下一步：以本轮播客时间修复为种子，审计同类单位边界而非泛化大重构。

### ATS-08 更新与恢复必须保留工作，并说明阶段后果
- 问题：更新切断未保存工作，界面先报完成、运行端仍是旧版本，或恢复点不可读。
- 来源：S05 Tesla 支持展示下载/安装、排期、版本、发行说明，且明确不可取消阶段。仅采用阶段透明原则，不采用其车载不可回退限制。
- 适配：C6现有 runtime/release、C5 SavedWork、C4项目、F设置与恢复。沿当前流程记录目标build、当前build、兼容性、迁移版本、checkpoint、rollback_artifact、验证时间；更新前检查未保存工作和活跃任务。
- 默认/错误：不自行开启自动部署/新服务。用户保存与正常任务不中断优先；提交/迁移若无法安全中断须事前明确，但原可取消/回滚能力不得减少。恢复验证要读回真实内容，不仅文件存在。
- 验收：更新前后同一可编辑项目、启动失败、迁移中断、空间不足、旧客户端；完整备份恢复演练，旧版兼容边界逐项标注。RPO/RTO由业务确定，先测实际恢复秒数，不引用Tesla的3小时排障建议为服务指标。
- 价值：减少人工重新打开、重导入和丢稿；记录更新后首次成功任务时间与恢复失败率。下一步：复用当前release gate和恢复脚本补真实用户成果证据。

### ATS-09 工作区减少重复输入，但上下文不能授权
- 问题：研究→提案/视频/播客时复制粘贴多次；工作区切换残留旧项目状态。
- 来源：S04 Handoff为任务接续实践；S12 WCAG 2.2 3.3.7 对同一流程中重复输入有规范要求及例外。不能扩成“所有数据跨项目自动共享”。
- 适配：C3现有 SourceBrief/业务工作→C5引用/SavedWork→C4制作→F上下文入口。可继承已选source_refs、业务问题、语言、可编辑约束；必须保持版本和用途限制。独立Shared从空白仍有效。
- 默认：同一流程已知信息自动填充或可选；用户新改优先；敏感、安全或过期数据按适用例外重新核验。复制Subject/BrandFocus配置不复制历史数据。
- 恢复/验收：切换工作区、清空Focus、回退导航、旧标签页、引用撤回和跨成员；输入不丢、范围不串、原始事实与AI派生保持分离。以“选3条材料→提案→导出”比较必填数、复制次数、任务时间；目标不重复输入已有合法字段，不宣称已节省分钟。
- 下一步：逐工作流检查已有字段传递，修确证断点；不增加必须依次走完的五轮用户向导。

### ATS-10 可访问性进入真实任务验收，不决定原创视觉
- 问题：动态任务状态读屏无反馈、焦点被重绘抢走、只能拖拽、表单错误丢输入。
- 来源：S12 WCAG 2.2 W3C Recommendation 2024-12-12，重点4.1.3状态消息、3.3.1/3.3.3错误、3.3.7重复输入、2.4.11焦点不遮挡、2.5.7拖拽替代。
- 适配：F现有组件/token/语义层，C6提供可表达真实状态，C4时间轴操作。保持原创新视觉和已批准动效；Follow System/减少动态下功能等价，自动更新不抢输入焦点。
- 验收：Web/Website键盘与真实读屏完整过程；桌面/iOS按平台适用测试独立记录，不能由Web WCAG推导原生全合规。拖拽能用非拖拽单指操作完成；状态无需抢焦点即可获取；中英韩放大后功能可用。计完成率、错误率、焦点丢失数。
- 限制：通过自动扫描不等WCAG完整符合；WCAG不覆盖全部体验、认知需求或产品业务正确性。下一步：逐screen完整任务人工验证，保留原四表面矩阵。

### ATS-11 质量门禁验证可用能力，不以“接入”或测试数结案
- 问题：自测通过但用户路径未接通；不同候选的绿灯拼成发布结论。
- 来源：S11 SmartThings公开认证/自测要求，S13 Apple Xcode Cloud公开 build/analyze/test/archive 工作流，S14 NIST SSDF 1.1 PO.4安全检查与RV.3根因修正。
- 适配：M/C6既有验收门禁 + C1–C5能力Owner + F端侧证据；每项绑定 exact source/build、依赖版本、输入、期望输出、真实读回、错误分支、恢复、适用surface。合成测试/真实数据/实机/生产/商业收益分开记。
- 默认：没有证据=NOT_VERIFIED，明确跳过不算通过；高风险失败阻断相应能力，不阻断无关正常功能。安全失败根因扫描同类调用方并留回归，不抹除旧失败。
- 验收：同SHA从干净启动到保存/导出/重开；断线/重试/取消/撤权；四表面独立证据；审阅者可从最终记录重放。度量逃逸缺陷、回滚率、首次正确完成率、重复返工工时，不能用测试总数替代。
- 限制：不申请WWST、不启用Xcode Cloud、不付费；不宣称三家内部都采用同一种门禁。下一步：扩充现有acceptance记录，避免再建“公司级标准平台”。

### ATS-12 协作方式采用可复现证据，而非神话式公司文化
- 问题：“像Apple一样打磨”“像Tesla一样快”“三星生态化”无法分配工程责任或验证收益。
- 来源：S11/S13仅证明对外工具和流程；S14公开框架支持安全检查证据和根因反馈。不对三家内部绩效、会议、责任文化、发布审批权作未证实断言。
- 适配：M负责整合证据，既有C1–C6/F按原责任提供契约变更、调用方、失败重现、同版测试、风险/恢复；在原计划与既有review记录中存，不另造管理层/规则。
- 输入/默认：工作项必须有用户任务、受影响字段/单位、scope、输入输出、版本、Owner、真实验收证据；研究建议默认未实现。没有实验基线的收益写“待测”。
- 验收：随机选三个跨Owner任务，另一审阅者能复现结果并定位失败；研究→实现→接线→运行→真实用户结果可追溯。衡量从报告到定位正确Owner耗时、重复实现次数、跨Owner退回次数。
- 不适用：文化口号不能放宽权限、安全、原范围或真实性。下一步：将本报告工作项去重映射入既有总账；实现要依具体授权及源码评审。

## 3. 实验设计与收益计算

上述数值是待验证工程目标，非三家公布指标，也不是当前序境已实现收益。

建议固定六个任务：普通材料独立研究；CTH同口径趋势到报告；BMP活动方案与效果读取；提案编辑保存恢复；60分钟播客剪辑/导出；跨端接续并处理一次授权失效。每项分别测无AI基础路径和获准AI增强，AI提升不得掩盖基础退化。

同输入、同版本、同网络条件配对对照旧路径/候选路径；熟悉度分组并平衡任务顺序；小样本先诊断，不以显著性包装结论。记录人工必要动作数、重复输入字段数、用户操作时间、系统等待时间、总任务时间、成功率、错误恢复时间、返工次数、重复外部效果、数据丢失/越权事件。报告p50/p95及样本量，失败也入分母。

成本以真实工时/资源计：节省工时 = 同一正确成果旧人工时间 − 新人工时间；若正确性/安全退化则不能记正收益。研究期间不新增遥测服务；后续可在授权隔离验收中记录匿名任务计数，避免录入真实用户个人信息。零越权/零丢稿是安全闸门，不用平均速度抵消。

# ZBP × CTH SYNCHRONIZED COMPLETION GATE

Status: ACTIVE / HARD DELIVERY CONSTRAINT

## 1. Core decision

ZBP is the parent system. CTH is the child system and the first development/validation system.

**CTH-first development does NOT mean CTH-first completion followed by a later ZBP project.** The delivery target is a synchronized finished ecosystem: CTH must be functionally complete and stable, while ZBP must be developed in parallel as the parent architecture that receives and governs proven capabilities.

## 2. Delivery model

```text
CTH capability development
        ↓
CTH verification / stabilization
        ↓
Capability contract
        ↓
ZBP parent integration
        ↓
ZBP verification
        ↓
Cross-system regression
        ↺

At the same time:
ZBP platform / shell / shared services / governance / cross-platform surfaces
continue development in parallel.
```

## 3. Completion definition

A release is not considered the final system completion if only CTH is complete. Final completion requires:

```text
CTH
= confirmed functions + stable runtime + verified data + UI + interaction

AND

ZBP
= parent architecture + shared capabilities + integrated domains + platform surfaces

AND

CTH ↔ ZBP
= verified ownership + contracts + data semantics + permissions + routing + regression

AND

Web + Desktop + Mobile + Mini Program
= supported presentation surfaces over the same contracts
```

## 4. Function preservation

CTH's confirmed existing functions remain frozen product assets during this migration. ZBP may absorb capabilities only through compatibility-preserving contracts. No transfer is allowed to silently remove, redefine or weaken CTH behavior.

## 5. Capability migration

```text
CTH existing function
 ↓
KEEP / ADAPT / REFACTOR classification
 ↓
Regression verification
 ↓
Capability contract
 ↓
ZBP shared capability
 ↓
CTH compatibility verification
 ↓
ZBP integration verification
```

## 6. Visual architecture

The final UI must represent:

```text
ZBP parent
 ├── CTH child system
 ├── KOS / KOC / UGC capability domain
 └── Podcast complete attached system

Shared Platform
 ├── Data Truth
 ├── Metrics / Functions / Formula
 ├── AI / Knowledge
 ├── Visualization
 ├── Workflow
 ├── Integration
 ├── Evidence / Files
 ├── Audit / Governance
 └── Internal Coding / Agent
```

The ChatGPT-like left-navigation + central-workspace + contextual-detail pattern may remain as a layout reference. Architecture and ownership must remain explicit and must not be flattened into one undifferentiated dashboard.

## 7. Data completion gate

No CTH or ZBP completion claim is valid unless numeric outputs follow:

```text
Source
→ Ingestion
→ Parse
→ Validate
→ Normalize
→ Function / Formula
→ Canonical Table
→ optional View Model
→ Visualization
→ Report / Export
```

A table-only output is valid. Visualization must never become a second calculation engine.

## 8. Cross-platform completion gate

The same domain objects, metric definitions, evidence IDs, permissions and business semantics must work across Web, Desktop App, Mobile App and Mini Program. Each surface may have a different presentation optimized for its use case.

## 9. Final gate

```text
CTH COMPLETE
      AND
ZBP COMPLETE
      AND
CTH ↔ ZBP INTEGRATION COMPLETE
      AND
ALL REQUIRED SURFACES VERIFIED
      AND
DATA / UI / ROUTING / AI / CODING REGRESSION PASS
      ↓
FINAL SYSTEM COMPLETE
```

This gate supersedes any interpretation that treats ZBP as a later optional phase after CTH completion.

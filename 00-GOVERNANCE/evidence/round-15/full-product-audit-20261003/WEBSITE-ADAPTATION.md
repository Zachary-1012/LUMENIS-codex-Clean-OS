# 序境官网调整提案｜供产品负责人审核

日期：2026-10-03。状态：DESIGN_EXPLORATION / 待审核；未修改网站运行代码、未部署。唯一设计权威仍是 Experience Constitution，批准后由 F 完成详细页面设计与实现，W6 发布。

## 1. 调整目标与当前差距

官网应让第一次接触的人理解：序境为谁完成什么工作、怎样从资料走到可用交付、为什么结果可信、现在怎样使用。产品内部仍是一套 CTH/BMP/Shared/SYSTEM，不在官网拆成几个互不相通的工具。

当前 `website/` 有 19 个已跟踪文件，Astro 7.3.3；`/`、`/en/`、`/ko/` 是同一介绍页的三语入口。已有业务问题选择、资料→判断→交付演示、四端说明及可用性诚实提示，既有浏览器/可访问性验收可复用。缺少独立能力、解决方案、成果案例、帮助、信任、更新和下载内容体系。环境变量支持配置工作空间/联系/帮助/试用 HTTPS 地址，不证明真实公开地址已经部署。

## 3. 建议的信息结构

主导航：**产品 / 解决方案 / 能力 / 成果与方法 / 帮助 / 下载**；右侧提供语言和真实「进入序境」。关于、更新、隐私、使用条款、联系方式在页脚。每页不重复堆满所有能力。

| 页面 | 应回答的问题 | 主要内容 / 真实入口 |
|---|---|---|
| `/` 产品首页 | 序境能替我完成什么 | 一件完整工作实例、三类用户、关键成果、连续性、来源可信、实际入口 |
| `/product` | 怎样从资料完成工作 | 一条完整研究→决策→创作→复盘；CTH/BMP 工作入口和共享资料贯通 |
| `/solutions/commerce` | 商业体如何运营判断 | 商场/门店/活动/租户/消费者；太古汇/罗湖作为内部验证案例，明确样本限制 |
| `/solutions/brand` | 品牌如何形成有效方案 | 市场/竞品/消费者/创作者→Brief→内容/活动→结果；Nike/Le Labo 的真实研究边界 |
| `/solutions/agency` | 如何把客户 Brief 变成交付 | 资料消化、判断、原创方案、修改、可编辑成果与成本约束 |
| `/capabilities/research` | 如何获得并分析资料 | 单平台选择、全网/文件来源、出处定位、时点/范围、趋势与推荐的依据 |
| `/capabilities/creation` | 如何把研究用于制作 | 方案、视频、播客分别展示编辑、审阅、输出和重开；不同能力分别标状态 |
| `/capabilities/ai` | 自有 AI 做什么、依据什么 | 已验证的理解/推理/任务恢复/学习边界；模型与部署状态，不能用训练接口冒充成熟模型 |
| `/workflows` 与详情 | 一件真实工作如何做完 | 真实输入、关键步骤、完整结果、人工介入、耗时/成本、限制、继续工作入口 |
| `/learn` 与指南 | 我如何开始和解决问题 | 导入/采集/选择范围/创作/导出/恢复/常见错误；按任务组织，不暴露内部工具管理给普通用户 |
| `/trust` | 来源、资料与操作是否可控 | 数据用途、来源/引用、范围继承、撤销、错误更正、备份恢复及真实局限 |
| `/download` | 我的设备能做什么 | Web/Windows/macOS/Linux/Android/iOS 的实际支持、版本、校验和/签名及角色；未发包不出现假下载 |
| `/updates` | 哪些内容实际更新了 | 发布日期、功能、修复、已知限制和支持端，不把未发布源码写已上线 |
| `/about`、联系、隐私/条款 | 谁提供产品、如何沟通 | 真实产品定位/联系人/政策；商业价格待后续决策 |

三语使用相同信息层级和能力事实，允许自然本地化。上述是一个网站内的内容结构，不是新增产品模块。页面数量随真实内容组织，可合并短内容；不得用空白详情页完成数量指标。

## 4. 首页内容草案

主标题建议：**把市场变化，变成下一步可执行的工作。**

说明：序境面向商业运营、品牌市场与创作团队，将有来源的资料、业务判断、创作交付和结果复盘接在同一条工作里。

首屏主入口「进入序境」，次入口「看一件工作如何完成」。如果尚无公开工作空间，显示实际可用的产品演示，不提供失效跳转，也不伪装试用成功。

页面顺序：用户问题 → 完整成果演示 → 三类真实业务场景 → 研究与制作如何接续 → 来源/版本与反馈 → 适用设备 → 实际入口与常见问题。CTH/BMP/Shared/SYSTEM 属于架构说明层，不用四个技术框做首页核心卖点。

演示选一份获准公开的材料及脱敏结果：能够打开来源、说明取舍、查看可编辑版本、一次修改并看到结果变化。内部验证明确标注。不得虚构客户、满意率、效率倍数、合作伙伴或付费用户。

## 5. 风格、交互与连续性

采用官方站的清晰导航、逐层解释、真实成果与操作入口等原则；具体排版、颜色、字体、留白、组件仍由序境 Experience Constitution 决定。用户指定的手绘平面/版画色彩是创作分镜风格约束，不自动替换整个产品 UI；人物按脚本/描述生成。

官网进入工作空间后保留明确的任务意图，不擅自扩大采集范围或授权。从研究切到方案/视频/播客时，沿用同一目标、Brief、预算、时间/市场范围、来源与 Artifact 版本；遇到权限变化只处理变化项。不得要求用户重选同一资料或重复解释目标。

四端职责按已批准 Multi-Surface Decision：官网负责理解和进入；Web 是日常工作；Desktop 承接适合本地媒体/文件的工作；Mobile 按批准角色查看、反馈和继续。没有经过实际验证的端上能力不作等价承诺。

## 6. 实施顺序和验收

用户审核后，F 用一个完整官网改造 Batch 完成：信息结构/文案/真实资源链接 → 详细页面设计与 M DESIGN_READY → 三语页面和内容组件 → 真实入口/返回/跨设备 → 必要页面验证 → W6 发布。保留已经通过的访问者交互，不重造页面框架。

验收：首访用户能说清适合谁、完成何事和如何开始；导航无空页/死链；主承诺均对应当前可用结果；鼠标/键盘/触屏、窄屏、三语、减少动效与辅助技术可用；下载与版本真实；公开演示无秘密/个人资料泄露；真实域名/HTTPS/工作空间链路通过。视觉与文案审核、源码/构建、公开部署分别记状态。

本提案等待产品负责人审核；它没有晋升任何产品能力，也不恢复暂停中的 F。

# v5.2 UI / 舆情事件设计

## 这版为什么改
首页从“数据大盘”改成“事件优先的舆情雷达”。

第一屏只回答四个问题：
1. 今天有没有新的/升温的事件？
2. 哪些事件需要我现在看？
3. 负面与高风险有没有上升？
4. 数据是否新鲜、系统是否正常？

笔记、全网发现、历史复核、报告都进入第二层工作台，不再把所有模块平铺在首页。

## 事件设计
事件卡优先展示：
- 事件标题与一句话摘要
- 待核实 / 多来源 / 持续升温 / 已核实状态
- 来源类型数、提及数
- 风险分

点击后从右侧抽屉展开完整事件上下文：事实状态、影响方向、风险依据、建议动作、时间范围与来源覆盖。

## 视觉原则
参考 Apple HIG 的“视觉层级、渐进披露、简洁、明确反馈”，避免把复杂信息一次性全部展示。Apple 的官方指南明确建议把最重要的信息放在较高/较前的位置，并使用 progressive disclosure 隐藏次级信息；帮助信息应简短、上下文相关。来源：Apple Human Interface Guidelines。

## 数据原则
- 风险分是监测优先级，不等于事实成立。
- “事件”是聚合后的研判单元，不等于已证实事件。
- 主体过滤优先于情感/风险判断。
- 历史复核保留审计轨迹，不直接删除原始笔记。

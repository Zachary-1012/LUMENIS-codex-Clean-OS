## 1. Product invariant and scope

The active Flutter SH-04 entry is an independently usable Shared workspace for user-authored reports. A user can write a Markdown report without selecting a CTH/BMP task, Subject, BrandFocus, or SourceBrief, save it as a versioned Shared SavedWork artifact, reopen a saved version, revise it into a new immutable version, and request an explicitly selected export. A user-authored report remains a deliverable, not Canonical external fact.

Every Shared operation uses the exact workspace scope and lets the server resolve the actor and evaluate the existing Permission boundary. The Shared screen never adds CTH/BMP domain headers to that call. If a revision has source citations, the server preserves and reauthorizes those original source uses; the UI does not replace or broaden them.

The previous CTH/BMP paths remain separate and are not replaced by the Shared queue:

- `GET /api/experience/screen/SH-04` still calls `list_domain_reports()` and returns the CTH and `zbmp` report-type catalog (six entries per domain in the current source). It is a read-only type catalog, not a list of persisted report versions; it has no row-level actor scope or export effect. It remains an existing, unscoped legacy read path, not a Shared SavedWork result.
- The SavedWork API also retains its legacy SourceBrief-derived CTH/BMP scope path when a caller omits the Shared scope header. The active SH-04 Flutter screen does not call that path. Keep domain reports in their existing domain context and never query or relabel them as Shared reports.

## 2. Binding and response contract

| UI region | Current source binding | Required behavior |
| --- | --- | --- |
| Entry | Workspace route `workflow.deliverables` → `SH-04`; shell constructs `Sh04Screen` | Load the Shared report list on entry; do not use the legacy report-type catalog as saved output |
| Shared scope | `X-Lumenis-Workspace-Scope: {"scope_kind":"shared_workspace","version":1}` on every request | Send this exact scope only; no client actor, domain, product, Subject, BrandFocus, or GLOBAL fields |
| Queue | `GET /api/experience/saved-work?kind=report&limit=100` with optional cursor | Parse only server-verified Shared report versions; hide internal Artifact/Work IDs and keep verification-incomplete state visible |
| Create | `POST /api/experience/saved-work` with `kind=report`, title, Markdown, empty user-authored payload/citations, and request ID | Require a nonempty title (≤300 characters) and body; retain idempotency identity for an unchanged retry |
| Reopen | `GET /api/experience/saved-work/{artifact_id}` | Reopen the exact saved Artifact, then require its returned Artifact ID, SHA-256, and version to match the selected row |
| Revise | `POST /api/experience/saved-work/{artifact_id}/revise` with expected digest, title/body edits, reason, and request ID | Require a nonempty reason (≤4,000 characters); preserve the parent version and original citations/source scopes; accept only the next version of the same Work with the selected parent |
| Export | `GET /api/experience/saved-work/{artifact_id}/export?format=...` | Offer `md`, `txt`, `docx`, `pdf`, and `xlsx`; the server performs DATA_EXPORT Permission and rechecks retained source scopes before returning bytes; require a nonempty body and the requested MIME type |

The server resolves the current local workspace principal or authenticated actor for Shared calls, then authorizes the exact Shared scope for read or write. Export also passes the server's DATA_EXPORT effect check. The client does not provide identity or permission claims. The parser requires the SavedWork schema/kind, exact Shared return scope, a server-derived actor/principal context, Artifact/Work/version references, content digest, and citation list before exposing an item.

Saved report content is Markdown. Export is a separate user action: Web hands the returned file to the browser; Windows/macOS use the selected file destination; iOS offers text formats and copies the returned text to the clipboard. The source also contains a Linux file-selector branch, but Linux is not an active native delivery target. The UI does not offer the backend's internal JSON export. No filename or HTTP status alone proves successful export.

The queue is paginated and contains individual returned versions. Reopening a row reads that exact version. Revision creates a new Artifact with the same Work ID, parent Artifact/digest and incremented version; earlier versions remain eligible for selection and reopening. The current inspector shows version and parent relationship, but does not yet show a content diff or a return-to-parent-Task action.

## 3. Responsive information architecture

### Desktop (available width ≥1120 logical px)

- Header and Shared-scope banner establish the workspace context.
- Output queue occupies a 390 px column; the selected-version inspector occupies the remaining column.
- The queue and inspector are the same Shared flow as narrower layouts.

### Intermediate width (760–1119 logical px)

- Below 1120 px the source stacks queue then inspector in one column; there is no separate 760 px breakpoint.
- Page content can scroll vertically. The source has not been runtime-verified at the listed widths.

### Mobile (available width <760 logical px)

- The narrow layout still offers create, select/reopen, revise, reread, pagination, and export after server checks.
- iOS source offers `md`/`txt` export through clipboard copy; the file-save path is not available there.
- This source description is not mobile acceptance; viewport, accessibility and real backend operation remain unverified.

## 4. State and recovery

| State | Meaning | Behavior |
| --- | --- | --- |
| Loading | Shared report listing is pending | Clear stale rows and show a loading state |
| Ready / empty | The response passed the Shared SavedWork parser | Show verified versions, or an explicit no-saved-reports message |
| Verification incomplete | Server reports candidates it could not verify | Hide those candidates, retain verified rows, and offer reread |
| Blocked | Shared scope is unavailable, denied, or malformed | Show a safe scope message and retry; do not render IDs |
| Failed | Authentication, permission, transport, or response failure | Keep failure kinds distinct and offer retry |
| Load-more failure | A later page could not be read | Keep already displayed versions and allow a retry |
| Operation failure | Save, revise, reopen, or export did not complete | Show a localized safe message; do not claim success |

## 5. Actions and effects

| Action | Effect | Availability |
| --- | --- | --- |
| Write report | `POST /api/experience/saved-work` through the Shared SavedWork client | Enabled from the report composer in Ready; title and Markdown are user-authored and saved under Shared Permission |
| Select/reopen version | Select a queue row, then `GET /api/experience/saved-work/{artifact_id}` | Enabled for a returned version; the reopened response must match that row's artifact ID, digest and version |
| Revise report | `POST /api/experience/saved-work/{artifact_id}/revise` | Enabled for a reopened version; saves a new child version and leaves the parent selectable |
| Export | Explicit format choice, then `GET /api/experience/saved-work/{artifact_id}/export?format=...` | Enabled for a verified reopened version; only report bytes returned after server Permission/source checks are handed to a file destination or copied as text |
| Reread / load more | Read the first page again or continue with the returned cursor | Reread is available in the mounted screen; load more is available when the server reports another page; later-page failure keeps prior rows |

When the selected artifact is `READY`, exact-scope, permitted, persisted and
reopenable, its nonempty preview text may expose a transient local Read Aloud
action. Bind it to the current scope and artifact identity; use only an exact
installed zh-CN, en-US or ko-KR device voice at 0.75×/1.0×/1.25×. Do not
request a new artifact, translate, save speech audio or use a remote voice.
Scope, artifact, text or screen change stops playback. Blocked/unavailable or
non-reopenable records never expose this action.

## 6. Accessibility and localization

- State, exact range, format and reopenability are announced as text and not by color alone.
- Preview content is rendered as inert text; no HTML or path is interpreted.
- Screen actions, empty/error states, editor prompts, export notices, the Shared-scope banner and saved/unavailable state labels use inline zh-CN/en/ko copy; the page title uses the existing `screen.SH-04` localization keys.
- A focused widget regression checks the Shared-scope banner and both saved-state labels in zh-CN, en and ko. This source/test coverage does not establish full screen accessibility or real cross-surface acceptance.
- Error copy hides raw IDs, paths, provider information and diagnostics. Markdown content and format extensions are data, not translated interface labels.

## 8. Review decision

Current source binds `workflow.deliverables` → `SH-04` → `Sh04Screen` → `CoreSh04Repository` → the Shared SavedWork Core client → the existing `/api/experience/saved-work` handlers and `saved_work` service. `_shared_work_actor_scope` resolves the actor and validates/authorizes the Shared scope for each operation; export reaches the existing DATA_EXPORT check and retained-source-scope reauthorization. This replaces the obsolete read-only-only description for the active Flutter path, while the separate legacy CTH/`zbmp` report-type catalog remains available as described in §1.

The SH-04 widget scenarios exercise create, reopen and revision through a fake in-memory repository and check the scope/saved-state labels in zh-CN, en and ko. They establish interaction and locale wiring only; they do not prove persistence, backend Permission, export execution, or real cross-session reopen/recovery. Those real user operations and per-surface acceptance remain unverified. The source also lacks content diff and return-to-parent-Task actions.

Keep this specification at `IMPLEMENTED_SCOPE_GUARDED_EFFECT_UNVERIFIED`, `design_decision: BLOCKED`, and `binding_ids: []`. This reconciliation records source behavior and open acceptance work; it is not a design review, binding promotion, `ACCEPTED` decision, or commercial-readiness claim.

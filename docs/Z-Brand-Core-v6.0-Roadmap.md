# Z-Brand Core v6.0 升级路线图

## 定位

Z-Brand Core 从舆情监测系统升级为品牌传播与市场情报智能平台。

核心链路：

品牌动作 → 传播主体 → 内容扩散 → 事件演化 → 消费者反馈 → 品牌影响 → 决策输出

## 架构方向

```
Z-Brand Core
├── CTH-POMS
│   └── 舆情监测生产能力
├── ZBMP
│   └── 品牌传播与市场情报分析能力
└── DCC
    └── 研发审计、版本管理、升级中枢
```

## v6.0 五层能力

### 1. 数据采集层

统一 Adapter 架构：

- 小红书 Web Adapter
- 小红书 App Topic Adapter
- 微博 Adapter
- B站 Adapter
- 官方来源 Adapter
- 手动导入

所有数据统一进入内容中心。

### 2. 内容理解层

新增双维度模型：

传播主体：
- KOS
- KOL
- KOC
- 普通用户
- 媒体
- 官方
- 机构

内容类型：
- UGC
- 商业内容
- 官方内容
- 测评
- 体验
- 投诉
- 活动内容

规则：subject_type 与 content_type 严格分离。

### 3. 事件智能层

事件中心升级为：

- 营销事件
- 传播事件
- 舆情事件

增加事件关系：

- 触发
- 衍生
- 继发
- 并行

形成营销→传播→舆情因果链。

### 4. 品牌分析层

新增：

- 传播主体分析
- 消费者需求洞察
- 品牌竞品对标
- 综合营销传播报告

### 5. AI辅助层

AI负责：

- 主体识别
- 内容分类
- 事件聚类
- 事件洞察
- 报告生成

原则：系统规则优先，AI辅助理解，人工修正沉淀规则。

## 小红书 App Topic Adapter

目标：补充话题发现能力，不替换现有 Web 采集。

架构：

```
XHS Web Adapter
XHS App Topic Adapter
        ↓
统一内容中心
        ↓
事件中心
        ↓
品牌分析
```

要求：

- Adapter 化接入
- 不绕过内容中心
- 不破坏主体过滤规则
- 支持来源区分 web/app

## Auth Recovery Center

统一处理：

- Cookie失效
- 登录过期
- 验证异常

流程：

异常检测 → 系统弹窗 → 二维码恢复 → 状态回写 → 任务恢复

## 开发阶段

### Phase 1

- 采集健康中心
- 登录恢复机制
- XHS App Topic Adapter
- 数据来源统一

### Phase 2

- 传播主体画像
- 三类事件统一
- 事件关系模型

### Phase 3

- 事件图谱
- 品牌对标
- AI洞察
- 高级报告体系

## 开发原则

- 不推翻现有系统
- 增量扩展
- 保持生产稳定
- 小步迭代
- 所有升级必须经过测试验证

## 一、数据精准性红线（全平台 100% 精准）

### 1.1 KOS 计算不得依赖固定公式
- KOS 互动率/影响力等指标计算**不得写死固定公式**。
- 必须根据各平台（小红书/抖音/微博/B站/知乎等）的**实际平台规则**实现，支持可延展配置。
- 平台规则变化时，计算逻辑应可配置/可扩展，不需要改核心代码。

### 1.2 全平台数据 100% 精准无误
- 覆盖平台：小红书、抖音、微博、B站、知乎等所有接入平台。
- **绝对禁止**：估算、近似、假数据、默认值填充。
- 所有数值必须来自真实采集的原始字段，经过可追溯的计算链路。

### 1.3 缺失值显式标记
- 数据缺失时必须显式标记为：`null` / `unknown` / `missing`。
- **绝对禁止**：用 `0` 或 `"未知"` 静默填充缺失值。
- 前端展示缺失值时必须有明确的视觉区分（如 "—" 或 "数据缺失"），不得与真实 0 值混淆。

### 1.4 时间口径分离
- 严格区分 `publish_datetime`（内容发布时间）与 `captured_at`（采集时间）。
- 相对时间（如"3小时前"、"昨天"）必须可靠归一化为绝对时间戳，不得保留相对字符串作为时间字段。
- 归一化失败时标记为 `missing`，不得猜测。

## 二、采集链路质量门禁

### 2.1 五步链路校验
采集链路必须经过以下五步，每步都要有校验和失败记录：
```
Source → Raw → Dedup → Subject Filter → Canonical
```
- 每一步输入/输出必须可校验。
- 任何一步失败必须记录失败状态、失败原因、原始数据引用，**不得静默丢弃**。

### 2.2 全链路可追溯
每条数据必须能追溯到：
- 原始 URL
- 采集时间（captured_at）
- 账号（account_id / account_name）
- 平台（platform）
- 原始字段（raw_fields 快照或引用）

### 2.3 去重精准
- 去重键必须使用 `content_hash + platform_id` 组合。
- **不得因标题相似就误删**内容。
- 去重决策必须记录（哪些被判定为重复、依据是什么）。

### 2.4 评论/详情失败不静默丢弃
- 评论采集、详情页抓取失败时，必须记录失败状态（failed / partial / timeout）。
- 不得因为评论/详情失败就丢弃整条主内容记录。
- 失败记录必须可查询、可重试。

---

## 三、AI 与原始数据分离

### 3.1 分离存储
- AI 分析结果与原始采集数据必须**分离存储**。
- 原始数据不得被 AI 输出覆盖。
- AI 结果必须关联到原始数据 ID（source_id / raw_id）。

### 3.2 人工修正可追溯
- 人工修正（human_correction）必须可追溯到：
  - 修正前的原始值
  - 修正后的新值
  - 修正人
  - 修正时间
  - 修正原因
- 不得直接覆盖原始字段，应使用修正表或修正字段。
